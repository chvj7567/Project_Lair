영웅 2D 전환 시안 · 카드 해골 기준 5스테이지

Project Lair · 기획서 docs/design/hero-2d-conversion.md. 스테이지 1 = 게임에 이미 들어간 카드 일러스트의 해골 픽셀 그대로(Fear/Bleed/MarkOfDeath/HeroAttackDown/HeroPoisonAura/Weaken/TimeStop 7장에서 로드). 스테이지 2~5 = 같은 해골 위에 카드 원화와 같은 4px 도트 격자로 수작업 픽셀 파츠(§3.2)를 얹은 합성. 절차 생성 캐릭터는 폐기했다.

베이스 = 실제 카드 PNG (7장 픽셀 중앙값으로 이펙트 제거)파츠 = 카드와 같은 4px 격자 수작업 도트공격 3종 · strike/end 실측 초S5 = 루트 스케일 ×1.4

모션은 한 장의 키아트를 움직이는 퍼펫 프리뷰(자세·타이밍·연출 확인용)다. 실제 프레임(대기·이동·공격 3종 등, 기획서 §5)은 이 키아트를 기준으로 수작업 제작한다(기획서 §8). 이미지는 로컬 서버의 /cardart/ 경로로 게임 원본을 읽기만 한다(복사본 없음) — node .mockups/server.js 로 열어야 보인다.

카드 일러스트 로딩 중…

1. 스테이지 카드 — 상태별 모션 + 실측 이벤트 타이밍

재생 속도
전체 상태

●STRIKE = OnAttackStrike(데미지 순간) · ◆END = OnAttackEnd/OnSpawnAnimEnd. 시각은 기획서 §5.3 실측(Slash 0.453/1.122s · Stab 0.494/1.617s · Spawn 1.320s). 피격 = 반전 0.1s, 공격 타격 = 백색 번쩍 + 펀치 1.15배.

2. 성장 사다리 — 같은 해골, 단계별 파츠

실루엣 검증 (기획서 §3.3 R2'·R3', 대기 키아트 기준)

S1 실루엣 = 카드 해골 마스크(색·위치 기반 자동 추출). 단위 환산: 카드 해골 높이 셀 → 게임 규격 몸 48px 로 비례 환산해 기준과 비교. 판정은 반올림 전 값, 미달은 빨강.

3. 전투 미니 프리뷰 — 영웅 단독 루프

등장(스폰 클립) → 대기 → 이동 → 도주 질주 → 공격 3종 순환. 노란 ●STRIKE / 청록 ◆END 가 실측 초에 뜬다.

4. 클립 타이밍 — 이벤트 위치 (기획서 §5.3·§11)

5. 원화 소스 — 카드 7장 → 이펙트 제거 베이스

7장 모두 같은 해골이 같은 위치에 있고 이펙트(파티클·장판·보호막)만 다르다. 픽셀마다 7장 중 "다른 장들과 가장 비슷한 원본 픽셀"을 골라(색을 섞지 않는 중앙값) 이펙트를 걷어낸 것이 베이스다. 눈(녹색)·검(은색) 위치는 자동 검출해 파츠 기준점으로 쓴다.

6. 핵심 결정 요약

  • 스테이지 1 은 카드 일러스트 해골 원본 픽셀 그대로 — 재디자인 없음.
  • 스테이지 2~5 는 같은 해골 위에 머리장식·무기·의복을 escalation: 캡 → 녹색 후드 → 반투구 → 뿔 달린 풀헬름 → 금 왕관 / 소검 → 장검 → 유령 장검 → 양손검 → 화염 대검 / 헝겊 → 튜닉 → 영묘 망토 → 정예 망토·견갑 → 판금+화염 망토.
  • 뼈·녹색 눈은 모든 스테이지 공통(같은 캐릭터로 읽히게), 스테이지색은 의복·망토에만 베이크(런타임 틴트 없음, 기획서 §6.2).
  • 이벤트 타이밍은 3D 클립 실측값 그대로 재현(기획서 §5.3), 게임플레이 수치 불변.
