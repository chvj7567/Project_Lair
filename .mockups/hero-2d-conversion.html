영웅 2D 전환 시안 · 카드 해골 기준 · 부위 리그 프레임 애니메이션

Project Lair · 기획서 docs/design/hero-2d-conversion.md. 스테이지 1 = 게임에 이미 들어간 카드 일러스트 해골의 원본 픽셀(7장에서 로드). 스테이지 2~5 = 같은 해골 + 카드와 같은 4px 도트 격자의 수작업 파츠(§3.2). 해골을 머리·몸통·골반·왼팔·오른팔+무기·왼다리·오른다리·망토(+후드 자락)로 분리해, 상태·프레임마다 부위별로 이동·회전(도트 단위 최근접 샘플)시켜 프레임을 한 장씩 굽는다 — 몬스터 시안(monster-2d-conversion.html)의 "상태별 프레임 파라미터표 → 프레임 베이크" 방식과 같다.

베이스 = 실제 카드 PNG (7장 픽셀 중앙값으로 이펙트 제거)부위 8개 리그 · 4px 격자 유지망토·후드 자락 1프레임 지연공격 3종 무기 궤적 · strike/end 실측 초사망 = 뼈 흩어짐 + 분해S5 = 루트 스케일 ×1.4

이미지는 로컬 서버의 /cardart/ 경로로 게임 원본을 읽기만 한다(복사본 없음) — node .mockups/server.js 로 열어야 보인다. 공격 번쩍(백색)·펀치(1.15배)·피격 반전은 게임의 AttackJuice/HitFlash 연출 그대로라 스프라이트 전체에 걸린다(캐릭터 동작은 전부 프레임).

카드 일러스트 로딩 중…

1. 스테이지 카드 — 상태별 프레임 애니메이션

재생 속도
전체 상태

●STRIKE = OnAttackStrike(데미지 순간) · ◆락 해제 / ◆스폰 게이트 = 다음 행동이 가능해지는 순간 — 기획서 §5.3 라이브 실측(strike 횡베기·내려찍기 0.500s · 찌르기 0.800s, 락 해제·스폰 게이트 1.800s). 공격·등장 클립이 끝난 뒤 1.8s 까지는 대기 모션이 재생된다(현재 게임과 동일). 하단 문구 = 현재 프레임 / 프레임 수 · fps.

2. 프레임 스트립 — 한 장씩 확인

노란 테두리 = strike 프레임, 청록 테두리 = end 프레임, 흰 테두리 = 지금 재생 중인 프레임. 프레임 수·fps 는 기획서 §5.2·§5.3 표와 같다.

3. 성장 사다리 — 같은 해골, 단계별 파츠 (대기 F0)

실루엣 검증 (기획서 §3.3 R2'·R3')

S1 실루엣 = 카드 해골 대기 F0. 단위 환산: 카드 해골 높이 셀 → 게임 규격 몸 48px 로 비례 환산해 기준과 비교. 판정은 반올림 전 값, 미달은 빨강.

4. 전투 미니 프리뷰 — 영웅 단독 루프

등장 → 대기 → 이동 → 도주 질주 → 공격 3종 순환. 노란 ●STRIKE / 청록 ◆락 해제가 라이브 실측 초(0.500·0.800 / 1.800s)에 뜨고, 다음 공격은 락 해제 뒤에 시작한다.

5. 클립 타이밍 — 이벤트 위치 (기획서 §5.3·§11)

6. 원화 소스 · 부위 분리

7장 모두 같은 해골이 같은 위치에 있고 이펙트만 다르다. 픽셀마다 7장 중 "다른 장들과 가장 비슷한 원본 픽셀"을 골라(색을 섞지 않는 중앙값) 이펙트를 걷어낸 것이 베이스다. 눈(녹색)·검(은색) 위치를 자동 검출해 부위 경계·회전축의 기준으로 쓴다.

7. 핵심 결정 요약

  • 스테이지 1 은 카드 일러스트 해골 원본 픽셀 그대로 — 재디자인 없음.
  • 애니메이션은 부위 리그: 몸통 호흡 1px, 머리 끄덕임(1프레임 늦게), 무기 팔 윈드업 → 휘두름 → 팔로스루 + 무기 궤적, 걷기·질주 시 다리 교차와 반대 팔 흔들기, 망토·후드 자락은 몸통보다 1프레임 늦게 따라옴, 피격 시 머리 젖힘 + 눈 찡그림, 사망 시 뼈가 흩어지며 분해, 등장은 흩어진 뼈가 모여 조립.
  • 스테이지 2~5 파츠는 붙은 부위와 같은 프레임에 같이 움직인다(투구·왕관 = 머리, 무기 = 오른팔, 튜닉·갑옷 = 몸통/골반, 견갑 = 팔, 망토 = 지연).
  • 이벤트 타이밍은 3D 클립 실측값 그대로(기획서 §5.3), 게임플레이 수치 불변.
