# Rule 01 — 자동 커밋 금지 / 커밋 메시지 포맷

## 룰
1. 작업 및 테스트가 완료되더라도 `git commit`을 직접 실행하지 않는다.
   대신 **커밋 메시지(안)만** 사용자에게 전달한다.
2. 커밋 메시지(안)를 전달할 때는 **관련 변경 파일을 `git add`(스테이징)까지 함께 수행**한다.
   사용자가 메시지만 복사해 바로 `git commit` 하면 되도록 준비한다.
3. 모든 커밋 메시지는 **한글**로 작성한다.
4. 커밋 메시지 제목은 다음 포맷을 따른다:

```
# [주제] - 커밋 메시지
```

## 포맷 규칙
- `#` 으로 시작 (1자)
- 공백 1칸 후 `[주제]` (대괄호 안에 분류 키워드)
- 공백 1칸 + `-` + 공백 1칸
- 이어서 한 줄 요약 (한글)

## 메시지 내용 규칙 (기획 관점 우선, 유동 판단)

**기획/게임 동작에 변화가 있는 작업**은 커밋 메시지를 **코드/구현 디테일이 아니라 "기획적으로 / 게임에서 무엇이 바뀌었는지"** 로 **간략하게** 적는다. 제목·본문 모두 플레이어 경험·게임 동작·콘텐츠 변화 중심.

- 제목: 그 변경으로 **게임이 어떻게 달라지는지** 한 줄.
- 본문(선택): 핵심 기획 변화만 2~5줄 bullet. 수치/페이싱/시너지/UX 변화는 적되, 구현 방식(버퍼·리플렉션·인터페이스 등)은 적지 않는다.
- 길게 나열하지 말 것. 한 기능이면 제목 + bullet 3~4개 이내.

**예외 — 기획적 의미가 없는 순수 코드 변경은 코드 관점 그대로 써도 된다.** 작성자가 유동적으로 판단한다. 예: Enum 값 추가/변경, 클래스·메서드·필드 리네임, 동작 불변 리팩터, 포맷·주석, 빌드/설정 변경. 이런 건 게임 변화로 옮길 게 없으므로 코드 사실을 그대로 적는 게 더 정확하다.

```
//# (X) 기획 변화가 있는데 코드 관점으로 나열
- EnemyStateContext 스냅샷 버퍼로 열거-중-수정 분리
- IEnemyStateContext.ApplyAreaDamage 추가, AreaGeometry.InRadius 판정

//# (O) 기획 변화가 있으면 — 게임이 어떻게 바뀌는지
- 적이 체력 70%/40% 구간에서 패턴을 바꿔, 같은 거리에서 계속 싸우면 불리해진다

//# (O) 순수 코드 변경이면 — 코드 사실 그대로 (예외)
# [refactor] - EEnemy enum 값명을 신규 네이밍 규칙으로 일괄 변경
# [refactor] - CHText 래퍼 필드명 _txt → _label 리네임
```

## 주제 키워드 (권장)
| 주제 | 사용 시점 |
|------|-----------|
| `[feat]` | 신규 기능 추가 |
| `[fix]` | 버그 수정 |
| `[refactor]` | 동작 변경 없는 구조 개선 |
| `[chore]` | 빌드/설정/메타 파일 등 |
| `[docs]` | 문서/주석/README |
| `[test]` | 테스트 코드 추가/수정 |
| `[style]` | 포매팅, 세미콜론 등 비기능 변경 |
| `[perf]` | 성능 개선 |
| `[asset]` | 에셋/프리팹/씬 변경 |
| `[infra]` | ChvjPackage 인프라 변경 |

## 적용 시점
- 코드 작성/수정/리팩터링 완료 후
- 테스트 작성 및 통과 확인 후
- 사용자가 명시적으로 "커밋해" 라고 요청하기 전

## 동작 방식
1. 변경 내용 요약
2. **Unity 에디터 포커스** — UnityMCP `editor_focus` 호출 (meta 파일 자동 생성 대기)
3. **관련 변경 파일을 `git add`(스테이징)**
4. 위 포맷의 제안 커밋 메시지를 코드블록으로 전달
5. 사용자가 직접 커밋하거나, 명시적 승인 시에만 커밋 실행

## add 범위 주의
- 관련 변경 파일만 스테이징 (`git add -A` / `git add .` 지양 — 무관 파일·민감 파일 혼입 방지)
- `.env`, 인증 토큰 등 민감 파일은 제외
- `.gitignore` 매칭 항목·외부 도구 산출물은 자연히 제외됨을 확인

## meta 파일 스테이징 규칙
Unity `.meta` 파일은 **신규 추가(A)·삭제(D) 파일의 것만** 함께 스테이징한다.
수정(M) 파일의 `.meta` 는 포함하지 않는다.

```
#  경로의 <code_root> 는 project.md 의 code_root 키 값으로 치환한다

# (O) 새 파일 추가 시
git add <code_root>Scripts/Foo.cs <code_root>Scripts/Foo.cs.meta

# (O) 파일 삭제 시
git add <code_root>Scripts/Bar.cs <code_root>Scripts/Bar.cs.meta

# (X) 수정 파일의 meta 포함 금지
git add <code_root>Scripts/Baz.cs <code_root>Scripts/Baz.cs.meta
```

## 예시 (기획 관점)
```
# [feat] - 적이 체력 구간마다 패턴을 바꾸는 단계형 전투

- 체력 70%/40% 구간에서 공격 패턴이 전환돼 한 자리에서 계속 싸울 수 없게 됨
- 플레이어가 거리·타이밍을 다시 잡아야 하는 새 긴장축
- 구간 수치는 인스펙터/SO 로 튜닝 가능
```

```
# [fix] - 인벤토리 슬롯 클릭 시 게임이 멈추던 문제 수정
```

```
# [asset] - 공격 범위 이펙트가 지형에 가려 안 보이던 문제 수정
```

## 금지 예시
```
feat: add pooling          //# (X) 영문 + 콜론 포맷
[feat] add pooling         //# (X) # 누락
# feat - add pooling       //# (X) 대괄호 누락
# [feat] 풀링 추가          //# (X) ` - ` 구분자 누락
# [fix] - EnemyStateContext NRE 수정   //# (X) 클래스명 등 코드 관점 — 기획 관점으로
```
