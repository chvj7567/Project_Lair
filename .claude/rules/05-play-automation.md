# Rule 05 — Play 모드 자동 조작·검증 (코드 호출 방식)

> 에디터에서 게임을 실행해 UI 흐름을 확인·검증할 때의 규약. 특정 게임·패키지에 종속되지 않는다.

---

## 1. 마우스 흉내 금지 — 코드로 `onClick` 을 호출한다

Play 중 버튼 조작은 OS 마우스 클릭(창 전면화·좌표 클릭 등)이 아니라 **`Button.onClick.Invoke()` 를 호출하는 에디터 도구**로 한다. 창 포커스·해상도·좌표·모달 대화상자에 영향받지 않고, 실제 클릭과 같은 리스너 경로를 탄다.

- 래퍼(`CHButton` 등)도 내부적으로 `Button.onClick` 에 리스너를 붙이므로 같은 방식으로 호출된다.
- 코드 호출은 **레이캐스트·가림·레이아웃 문제를 잡지 못한다.** 그런 시각 결함은 스크린샷으로 따로 확인한다.
- `interactable == false` 인 버튼은 누르지 않는다 (실제 입력과 같게).

## 2. 도구 구성 — 프로젝트에 하나, Editor 폴더, static 진입점

`<code_root>Editor/PlayDriver.cs` (partial 분할 허용) 한 곳에 둔다. 상시 도구이므로 Rule 04 §3 의 "생성 후 삭제" 대상이 아니다.

| 진입점 | 역할 |
|---|---|
| `GetState()` | 활성 씬·`timeScale`·열린 팝업·활성+interactable 버튼 목록(인덱스·경로·텍스트) |
| `Click` / `ClickIndex` | 경로 끝부분·텍스트·인덱스로 버튼 하나를 누른다. 0개/복수 매칭이면 누르지 않고 후보를 반환 |
| `StartSweep` / `SweepStatus` / `StopSweep` / `SweepReport` | 모든 화면의 버튼을 자동 순회하고 결과를 파일로 남기는 스위프 |

- Play 중이 아니면 `NOT PLAYING` 을 반환한다.
- **Editor 도구는 런타임 asmdef 와 패키지를 참조하되 게임 런타임 코드는 도구를 참조하지 않는다** (의존 방향 유지).

## 3. 인자 전달 — 파일로

UnityMCP `editor_invoke_method` 는 **인자를 받지 못한다** (클래스명·메서드명만). 인자가 필요한 진입점은 인자 있는 버전과 인자 없는 `*Arg` 버전 두 벌로 만들고, `*Arg` 는 `Temp/PlayDriverArg.txt` 에서 인자를 읽는다. 호출 전에 그 파일에 값을 쓴다.

- 이름이 같은 버튼(카드 3택 등)은 인덱스가 바뀐다 → **경로 끝부분**(`CardView_0/PickButton`)으로 지정한다.

## 4. 스위프 규약

스위프는 `EditorApplication.update` 기반 상태머신으로 **즉시 반환**하고 폴링한다 (씬 전환·여러 프레임에 걸치므로 동기 호출 불가). 결과는 `Temp/PlayDriverReport.txt` — 맨 위 요약(`state=` · 클릭 수 · PASS/FAIL/SKIP) + 클릭당 한 줄(`[PASS|FAIL|SKIP] 화면 > 버튼 -> 결과`).

- **FAIL 조건**: 클릭 중/직후 `Application.logMessageReceived` 의 Error·Exception, 예상 밖 씬 이탈, 팝업이 안 닫힘, 시간 상한 초과.
- **범위**: 부팅/로딩 → 시작 화면의 모든 버튼과 팝업(깊이 3 재귀) → 본 플레이 진입 → 플레이 중 선택 팝업 처리 → 결과 화면 → 시작 화면 복귀. 로딩처럼 완료 전 클릭을 무시하는 가드는 재시도로 처리한다.
- **시간 상한을 둔다** (전체·한 판 각각). 초과 시 FAIL 로 기록하고 중단.
- 스위프 중 배속은 `timeScale` 직접 설정. 팝업 일시정지 해제 시 1 로 돌아가는 구조면 **처리 후마다 재설정**한다.
- 완료·중단 시 스위프가 스스로 Play 를 끈다.

## 5. 안전 — 세이브 보호와 제외 목록 (필수)

스위프는 실제 세이브를 바꿀 수 있다. 아래 둘은 **스위프 작성 시 반드시** 갖춘다.

1. **세이브 백업/복원** — 시작 전 로컬 세이브 파일을 `Temp/` 로 백업하고, 정상·중단·크래시 모두 Edit 모드 진입 시 복원한다(`playModeStateChanged` + `[InitializeOnLoadMethod]` 로 잔여 백업 복구). 이전 백업이 남아 있으면 덮어쓰지 않는다. 메모리에 캐시된 프로필은 복원 후 무효화한다.
2. **제외 목록(deny-list)** — 코드 상단 상수로 `소속 팝업 타입:버튼 오브젝트명` 키를 둔다. 대상: 외부 서버에 쓰기(클라우드 복원·닉네임·리더보드 제출), 되돌릴 수 없는 확정(계정 삭제·전투 포기 확인), 기록을 오염시키는 진입(데일리/탑 도전 등), 스위프가 의도적으로 제어하는 진입(출격). 제외한 버튼은 `SKIP` 으로 기록하고 이유를 남긴다.

새 파괴적·네트워크 버튼이 UI 에 추가되면 **같은 작업에서 제외 목록을 갱신**한다.

## 6. 사용 절차 (메인 오케스트레이터)

1. 코드 변경 후 `editor_refresh_assets` → `editor_wait_ready` → 컴파일 에러 로그 확인.
2. `sim_play` → 부팅 대기(수 초) → 진입점 호출.
3. 완료 대기는 **foreground `sleep` 이 아니라 백그라운드 until 루프**로 한다 — 리포트 2번째 줄이 `state=RUNNING` 이 아니게 될 때까지. (`done|완료` 같은 느슨한 grep 은 클릭 로그에 걸려 일찍 끝난다.)
4. `SweepReport` 로 요약·FAIL 목록 확인 → 시각 확인이 필요한 화면은 열린 상태에서 `screenshot_editor`.
5. 도구 코드(`.cs`)는 gameplay-programmer 가 작성·수정하고 컴파일·실행은 메인이 한다 (서브에이전트는 UnityMCP 불가).

## 예외
- 순수 EditMode/PlayMode 자동 테스트(NUnit)로 충분한 로직 검증은 이 룰 대상이 아니다.
- 에디터 창 자체의 UI(인스펙터·툴 윈도우)는 대상이 아니다.
