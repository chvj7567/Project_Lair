## 1. 피의 반향 (Blood Echo) — 가칭

- **카테고리**: 패시브 강화 / Debuff 축
- **효과 모델**:
  - 영웅이 몬스터를 처치할 때마다 "반향 스택" +1.
  - 스택 5개마다 자동 발동: 영웅 받는 피해 배율 ×1.05 영구 누적 (캡: 최대 ×1.50).
  - 즉, 50마리 처치 후 받는 피해 +50% 영구 고정.
  - **밸런스 근거**: 영웅 공격력 50/타·공속 1s, 평균 몬스터 HP ~150 → 처치 주기 약 3s. 5분 = 약 100마리 처치 예상. 50마리 기점(런 중반 약 2~2.5분)에 캡 도달. 이후 나머지 카드 시너지가 막히지 않음. MarkOfDeath(×1.5, 5s 임시)와 구분: 이건 영구 누적.
  - **수치 조정 포인트**: 트리거 마릿수(5) / 배율(1.05) / 캡(1.50) 인스펙터 노출.
- **구현 패턴**:
  - `BloodEchoEffect.cs` — BloodThirstEffect 와 유사하게 OnMonsterDeath 이벤트 구독.
  - 내부 killCounter 필드 유지. `counter % 5 == 0` 시 `IBattleContext.Hero.ApplyDamageReceivedMultiplier(1.05f)` 호출.
  - 기존 HeroAttackDownEffect 의 영구 스탯 조작 패턴 응용 — `MonsterBuffService` 대신 HeroAura 레이어 사용.
- **시너지 후크**:
  - `MarkOfDeath` (영웅 받는 피해 ×1.5, 5s) + Blood Echo (영구 +50%) 조합: 피해 증폭 창이 두 배 효과.
  - `Bleed` (이동 시 HP -2%) + Blood Echo: 이미 지속 출혈 중인 영웅이 더 많이 맞아 사망 가속.
  - `Weaken` (공격력 ×0.5, 10s) + Blood Echo: 약해진 영웅이 더 오래 버텨야 하므로 스택 쌓일 시간 확보.
- **구현 비용 추정**: 3 — OnMonsterDeath 패턴은 BloodThirst에 이미 존재, Hero 스탯 조작은 HeroAttackDown 패턴 재사용.
- **중복 재검증**: 기존 BloodThirst는 "처치 시 몬스터 HP +30". 이건 "처치 시 영웅 피해 취약성 증가". 피해 대상(몬스터 vs 영웅)과 효과 방향 모두 반대. 과거 12회차 전부 OnDeath로 "뭔가 소환" 또는 "현재 상태 임계" 뿐, "처치 누적 → 영웅 취약 영구 증가"는 없음 ✅

## 2. 황폐의 행진 (Desolation March) — 가칭

- **카테고리**: 패시브 추가 / Swarm 축
- **효과 모델**:
  - 영웅이 몬스터를 처치할 때마다 "황폐 카운터" +1.
  - 카운터가 8의 배수가 될 때마다: 현재 활성화된 모든 Spawner 에서 즉시 몬스터 1마리씩 보너스 소환.
  - Spawner 6개 기준: 8처치마다 6마리 즉각 보충.
  - **밸런스 근거**: 5분간 약 100처치 → 12회 트리거 × 6마리 = 72마리 추가. 정상 스폰(6 Spawner × 주기 3s × 300s = 600 스폰) 대비 약 +12% 추가 공급. 글로벌 캡(18)에 의해 자동 조절됨 — 캡 도달 시 Spawner 자연 백오프로 효과 완충.
  - **수치 조정 포인트**: 트리거 처치 수(8) / 보너스 소환 수(1).
- **구현 패턴**:
  - `DesolationMarchEffect.cs` — OnMonsterDeath 이벤트 구독 + `killCounter % 8 == 0` 판단.
  - 트리거 시: `IBattleContext.GetAllSpawners()` 순회 → 각 Spawner 에 대해 `CHMPool.Pop(spawner.MonsterPrefab, spawner.transform)` (= SpawnWraithEffect 의 즉시 소환 패턴 응용).
  - 글로벌 캡 체크: `IBattleContext.IsAtGlobalCap()` 이 true 면 소환 스킵 (기존 Spawner 백오프 로직과 동일 정책).
- **시너지 후크**:
  - `SpawnerHaste` (모든 Spawner 주기 ×0.8) + Desolation March: 정상 스폰 가속 위에 보너스 소환까지 → 글로벌 캡 압박 극대화.
  - `SpawnPhantoms` / `SpawnWisps` (출력 +1) + Desolation March: 이미 출력이 높은 Spawner 에서 보너스 팝이 나와 소환 종 다양성 증가.
  - 영웅이 빠르게 처치하면 할수록 보너스 트리거 빈도 증가 → "잘 싸울수록 더 많이 나온다"는 역설.
- **구현 비용 추정**: 3 — GetAllSpawners() 패턴이 기존 SpawnHaste 에 유사하게 존재, 즉시 소환은 SpawnWraith 패턴 재사용. 글로벌 캡 체크는 BattleController 에 이미 있는 정책.
- **중복 재검증**: 06/02 death-echo는 "죽은 유닛의 위치에서 즉시 소환" + 영구 적용. Desolation March는 "처치 누적 카운터 임계에서 모든 Spawner 동시 보너스 팝" + 패시브 영구. 트리거 조건(스택 임계), 소환 출처(Spawner), 소환 종(Spawner 고유 종) 모두 다름 ✅

## 3. 용사의 족쇄 (Hero's Shackle) — 가칭

- **카테고리**: 액티브 저주 / Debuff 축
- **효과 모델**:
  - 활성화 시 8s 동안:
    - 영웅이 몬스터를 처치할 때마다 영웅 이동속도 ×0.95 누적 감소.
    - 8s 창 내 최대 ×0.65 (= 약 -35%) 까지. 8s 종료 후 이동속도 원복.
  - 8s 안에 약 5~7마리 처치 시 ×0.95^5~7 ≈ ×0.773~0.698 → 이동속도 -23~30%.
  - **밸런스 근거**: Slow(기존: ×0.5 고정, 10s)보다 mild하지만, 영웅이 얼마나 빠르게 처치하느냐에 따라 가변적 — 영웅이 잘 싸울수록 더 느려지는 역설. 영웅이 처치를 지연하면(몬스터 피하면) 효과가 약해지므로 영웅에게 딜레마 부여.
  - **수치 조정 포인트**: 지속시간(8s) / 처치당 배율(0.95) / 이동속도 캡(0.65) / 활성 cooldown(30s로 30초마다 1회 선택 가능하므로 자연 쿨다운됨).
- **구현 패턴**:
  - `HeroShackleEffect.cs` — IHeroAura.RegisterTimedModifier(8s) + OnMonsterDeath 구독 (활성 기간에만 반응).
  - 처치마다 `heroAura.MultipleMoveSpeed(0.95f)` — SlowEffect 의 IHeroAura.MultipleMoveSpeed 패턴 그대로.
  - 8s 후 `IHeroAura.RemoveTimedModifiers(this)` 로 원복 — FearEffect 의 지속시간 제한 패턴 참고.
  - 캡 체크: 현재 배율이 0.65 이하이면 추가 누적 스킵.
- **시너지 후크**:
  - `Frenzy` (공속 +50%, 10s) + Hero's Shackle: 더 빠르게 공격하는 몬스터를 피하려 이동 → 이동 중 처치 → 족쇄 발동 → 이동속도 감소 → 더 많이 맞는 악순환.
  - `TimeStop` (영웅 5s 정지) + Hero's Shackle: 정지 해제 후 8s 창에서 영웅이 다시 싸우기 시작하면 즉시 족쇄 가동.
  - `BloodEcho` (오늘 Card 1) + Hero's Shackle: 족쇄로 느려진 영웅이 더 오래 싸우며 Blood Echo 스택도 쌓임 → 두 효과가 협력.
- **구현 비용 추정**: 3 — SlowEffect + FearEffect 패턴 결합. OnMonsterDeath 구독 조건 분기만 추가.
- **중복 재검증**: 기존 Slow(×0.5 고정, 10s) / Fear(도주 3s) / escape-punishment(06/08 — 다칠수록 느려지고 선택할 때 묶이고 봉쇄)와 비교 — 이건 "처치 속도에 비례한 가변 감속 (8s 한정)". 트리거(MonsterDeath 카운트)와 가변성(누적 배율) 모두 기존과 다름 ✅

## 4. 공통 테마 고찰

**왜 오늘 이 테마인가?**

QA 리포트(2026-05-22)는 시뮬레이션이 BLOCKED 상태라 픽률 데이터가 없다. 대신 설계 관점에서 분석하면:

- 기존 28장은 "던전이 영웅을 일방적으로 약화/증가"하는 구조: 몬스터 강화, 영웅 디버프, 스폰 가속.
- 영웅의 **행동 자체**에 반응하는 카드가 BloodThirst(처치 → 몬스터 HP 회복) 1장뿐.
- 과거 12회차 중 OnDeath 트리거는 06/02(스폰)뿐 — "처치 카운터 임계" 기반 카드는 전무.
- 전략적 깊이 측면: 영웅이 "잘 싸우는 것"이 역효과를 낳는다면, 플레이어(던전 주인)는 딜 특화 빌드 + 이 카드를 조합하는 카운터플레이를 즐길 수 있음.
- v0.2에서 30~40장 패시브 풀이 필요할 때, "처치 반응형" 카드 카테고리가 없으면 전략 다양성이 제한됨.

**3장의 공통 메커니즘**: OnMonsterDeath 이벤트 구독 + 카운터/임계 로직. 구현 기반을 공유하므로 효율적 개발 묶음이기도 함.

## 6. 쉬운 설명 (비개발자 요약)

지금까지 던전 카드들은 "몬스터를 더 강하게 만들거나", "영웅을 약하게 만드는" 방식이었습니다. 그런데 오늘 제안하는 카드들은 조금 다릅니다. 영웅이 몬스터를 잘 처치하면 처치할수록, 오히려 던전이 더 강해지는 역설적인 효과를 냅니다. 예를 들어, 영웅이 10마리를 처치하면 받는 피해가 좀 늘어나고, 20마리를 처치하면 갑자기 사방 Spawner에서 추가로 몬스터가 쏟아져 나오는 식입니다. 마치 영웅이 강하게 싸울수록 더 위험해지는 덫을 설치하는 것과 같습니다. 그래서 오늘 제안하는 카드 3장은: 영웅이 처치를 많이 할수록 더 많이 얻어맞게 되는 "피의 반향", 처치할수록 추가 몬스터가 쏟아지는 "황폐의 행진", 빠르게 처치할수록 발이 묶이는 "용사의 족쇄"입니다.
