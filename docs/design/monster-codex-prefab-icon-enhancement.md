## § 헤더

- **목표**: 도감(몬스터 메뉴) 아이콘을 실제 몬스터 프리팹 렌더로 교체하고, 그 종족의 상점 강화 레벨(Lv0~5)과 레벨별 발광색·밝기·스케일을 도감 셀에 반영해 "내가 키운 몬스터"가 도감에서 확연히 다르게 보이게 한다.
- **검증 가설**: (a) 도감 아이콘 = 실제 원본 렌더 + 레벨 발광이 "내가 이 종족을 키웠다"는 투자 보상감을 강화하는가, (b) 도감 발광색·톤이 전투(`MonsterEnhancementVisual`)·상점(`ShopItemCell`)과 같은 SoT 를 읽어 "도감 = 전장 = 상점" 색 일치가 유지되는가. v0.3 재방문 가설의 메타 표현 보강.
- **현재 단계 범위 적합성**: **범위 내**. CLAUDE.md §8 "메타 진행 허용" + spec §2 가 "신규 몬스터 제작 아님 — 기존 6종 프리팹의 UI 표현 + 기존 발광 SoT 재사용"으로 확인. 신규 **몬스터/카드/영웅/레벨별** 리소스 제작 0(아이콘 6장은 기존 파일 **덮어쓰기**, 레벨별 스프라이트 제작 금지 §8). **예외 1건 — 발광 오버레이용 범용 라디얼 소프트글로우 UI 프리미티브 1장 신설**(§3.1): §8 금지 대상은 몬스터/카드/영웅/레벨 아트이며, 흰색 방사 알파 그라디언트 1장은 런타임에 종족색으로 틴트되는 **UI 프리미티브**(게임 콘텐츠 아트 아님, 재사용 가능)라 범위 내로 판단. 이 1건은 사용자 승인 게이트에서 명시 확인 대상.
- **핵심 메커니즘**: (Part 1) 6종 프리팹을 카메라+RenderTexture 로 렌더해 `MonsterIcons/{종}.png` 를 투명배경 원본 렌더로 덮어쓴다(영웅 아이콘 캡처 미러링, Lv0/발광 off 상태로 베이크 → 발광은 셀이 소유). (Part 2) 도감 셀이 `Enhance_<종족>` 레벨을 읽어 **아이콘 틴트(색 hue wash) + 뒤 발광 오버레이(밝기) + 아이콘 스케일(정점감) + 레벨 배지** 4채널로 레벨을 표현. 종족당 아이콘 1장, 레벨 표현은 전부 런타임 셀 계산.

## 1. 배경 — 왜 4채널로 나눠 표현하는가

강화 레벨은 셀에서 네 개의 시각 신호로 인코딩된다. 각 신호의 역할이 다르며, 하나만으로는 "발광하며 강해진다"가 약하게 읽힌다.

| 채널 | 무엇을 전달 | 물리적 한계 / 이유 |
|---|---|---|
| **발광 오버레이 알파** (`_glowOverlay`) | **밝기 — "빛난다"의 주 신호** | 아이콘 뒤 종족색 backdrop 을 알파로 밝힌다. 곱연산 틴트가 못 하는 "밝아짐"을 담당(§3). |
| **아이콘 틴트** (`_icon.color`) | **색 — "무슨 색으로 빛나나"** | `_icon.color` 곱연산은 **어둡게만** 가능(성분 ≤1). 그래서 밝기가 아니라 **hue wash** 로만 쓴다(§2). |
| **스케일** (`_iconRect.localScale`) | **정점감 — "만렙이 크다"** | 그리드 셀(106×128) 안에서 넘치지 않는 상한까지만(§4 검산). |
| **레벨 배지** (`_levelBadge` CHText) | **정량 — "정확히 Lv N"** | 시각 신호만으로 애매한 정확한 레벨을 명시. Lv0 은 숨김(순수 아이콘). |

**4채널이 과하지 않은 근거**: 84px 아이콘 + 4열 그리드에서 신호가 많으면 산만해질 수 있으므로, **각 채널의 Lv1 값을 낮게(floor) 잡아 저레벨은 미묘하게, 고레벨에서만 또렷하게** 오르게 설계한다(아래 곡선 표 전부 Lv1 floor + 상한 cap 구조). "키울수록 눈에 띈다"는 투자 보상 곡선을 유지하면서 저레벨 셀의 노이즈를 억제.

**곱연산 틴트가 어둡게만 되는데 괜찮은 이유**(design 근거): `_icon.color` 는 스프라이트 RGB 를 곱하므로 흰색보다 밝아질 수 없다. 그러나 (a) 밝기는 `_glowOverlay` 가 담당하고 틴트는 hue wash 전용이며, (b) `SpeciesGlowColor` 가 max 성분 0.90 으로 정규화(monster-species-enhancement §4.2)되어 있어 어두운 종(Phantom #82ABE6·Wraith #C0CCE6)도 과하게 어두워지지 않는다. 두 장치가 "곱연산 틴트의 어두워짐" 문제를 구조적으로 막는다.

## 2. 레벨 → 아이콘 틴트(색) 곡선 (열린 결정, ⟨기획서 확정⟩)

**적용**: `_icon.color = Lv0 ? Color.white : Color.Lerp(Color.white, SpeciesGlowColor(species), IconTintByLevel[lv])`.

`IconTintByLevel`(index = Lv, Lerp 계수 t):

| Lv | t (틴트 계수) | 델타 | 의미 |
|---|---|---|---|
| 0 | 0.00 | — | 미강화 = 순수 아이콘(흰색, 틴트 없음) |
| 1 | 0.16 | +0.16 | 첫 강화 = 색이 "켜진다"(가시 floor) |
| 2 | 0.28 | +0.12 | |
| 3 | 0.40 | +0.12 | |
| 4 | 0.52 | +0.12 | |
| 5 | 0.64 | +0.12 | 상한 cap — 원형(생물) 식별 유지 |

`IconTintByLevel = [0.00, 0.16, 0.28, 0.40, 0.52, 0.64]`.

**구조 = Lv1 floor(0.16) + 이후 선형 +0.12/Lv, Lv5 상한 0.64**. 두 하드 제약이 곡선을 결정한다:
- **Lv1 floor 0.16 (가시성)**: 전투 발광이 "Lv1 = 반드시 눈에 보여야 한다"는 원칙(monster-species-enhancement §4.1, Lv1 emission 1.5 = 검증된 가시 하한)을 따른다. t=0.16 미만이면 84px 아이콘에서 hue 변화가 안 읽혀 "첫 투자가 보인다" 훅이 무너진다.
- **Lv5 cap 0.64 (식별성)**: t=1.0 이면 `Color.Lerp(white, glow, 1)` = 순수 종족색 곱 → Reaper 아이콘이 통짜 빨강이 되어 **생물 형태가 지워진다**. 0.64 에서 종족색 wash 는 또렷하되 원본 실루엣·명암이 남는다. 검산: Wisp #28E66E, t=0.64 → Lerp = (1−0.64×0.845, 1−0.64×0.10, 1−0.64×0.57) = (0.459, 0.936, 0.635) → 흰 유령 스프라이트에 곱하면 **연녹색 유령**(형태 유지). Reaper #E64141, t=0.64 → (0.936, 0.526, 0.526) → 붉은 wash(형태 유지).

**대안 비교**:

| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **floor+선형+cap [0,.16,.28,.40,.52,.64] (채택)** | Lv1 확실히 보임, Lv5 형태 유지, 저레벨 노이즈 억제 | 완전한 곡선미는 없음(선형) | ✅ |
| 순수 선형 t = lv/5 (0.2~1.0) | 상점 프레임 밝기와 공식 동일 | Lv5 t=1.0 → 종족색 통짜 → 형태 소실 | ✗ (식별성 붕괴) |
| 전투 emission 정규화 t = 0.64×(emi/3.2) | 전투 곡선과 정확 미러 | Lv1 t=0.29 로 시작 → 저레벨끼리 차이 압축(투자감↓) | ✗ (dynamic range 부족) |

**전투 톤 정합**: 전투 `_emissionByLevel = [1.5,1.9,2.3,2.7,3.2]`(Lv1~5)은 "off → Lv1 floor → 완만 상승 → 만렙 근접 강조"의 형태다. 본 틴트 곡선도 같은 형태(0 → floor 0.16 → 등차 상승 → cap)를 공유 — 셀은 전투 곡선을 그대로 미러하지 않고(Character↔UI 역참조 회피, monster-species-enhancement §5.2 와 동일 원칙) **같은 형태의 셀 전용 곡선**을 쓴다. **색은 정확히 같은 SoT**(`SpeciesGlowColor`)이므로 "도감 색 = 전장 색"은 구조적으로 보장.

## 3. 레벨 → 발광 오버레이 곡선 (밝기 주 신호, ⟨기획서 확정⟩)

**적용**: 아이콘 **뒤**에 종족색 소프트글로우 요소(`_glowOverlay` Image)를 두고, `_glowOverlay.color = SpeciesGlowColor(species)` 에 알파만 레벨로 조절. Lv0 = 비활성(순수 아이콘).

### 3.1 오버레이 스프라이트 — 라디얼 소프트글로우 1장 신설 (⟨기획서 확정⟩)

`_glowOverlay` 의 스프라이트는 **범용 라디얼 소프트글로우 프리미티브 1장을 신설**한다: 흰색, 중심→가장자리 알파 방사 falloff(중심 α1 → 외곽 α0), ≈256×256. 런타임에 `_glowOverlay.color` 로 종족색·알파를 입혀 부드러운 아우라로 표현.

**대안 비교(글로우 요소)**:

| 안 | 표현 | 신규 에셋 | 판정 |
|---|---|---|---|
| **라디얼 소프트글로우 1장 신설 (채택)** | 부드러운 방사 아우라 = "빛에 잠긴 몬스터" | UI 프리미티브 1장 | ✅ |
| 내장 라운드 사각 스프라이트(제로 에셋) | 색 사각 매트 = "색 카드 위 몬스터"(발광 약함) | 0 | ✗ (헤일로 아닌 카드로 읽힘 — 헤드라인 효과 약화) |
| 내장 Knob(원형) 스프라이트(제로 에셋) | 하드엣지 색 원반(falloff 없음) | 0 | △ (사각보단 낫지만 여전히 딱딱) |

- **왜 제로 에셋을 포기하고 1장을 신설하나**: 발광은 본 기획의 **헤드라인 효과**("발광 = 투자 보상감")다. 내장 라운드 사각 스프라이트를 알파로 얹으면(특히 Lv5 α0.90) 소프트 글로우가 아니라 **평면 색 카드**로 읽혀 핵심 판타지가 약해진다. 구 아이콘의 방사 글로우(§3 아래)를 동적으로 되살리려면 falloff 가 있는 라디얼 스프라이트가 필요하다.
- **왜 §8 범위 내인가**: §8 신규 리소스 금지는 **몬스터/카드/영웅/레벨 아트** 대상이다. 흰색 라디얼 알파 그라디언트는 특정 콘텐츠가 아닌 **범용 UI 프리미티브**(런타임 틴트, 다른 UI 에도 재사용 가능 — 향후 상점 셀 글로우 프레임도 이 스프라이트로 통일 가능)라 게임 콘텐츠 아트가 아니다. **단 신규 에셋 1건이므로 사용자 승인 게이트(Task 4 목업)에서 명시 확인**한다.
- **생성**: 인스펙터 참조(Addressable 아님, 아이콘 switch resolver 와 동일 관례). 생성 방식(에디터 스크립트 절차 생성 또는 단순 그라디언트 PNG)은 구현자 재량이나, **산출물은 `Assets/_Lair/Art/Sprites/` 하위 단일 PNG + .meta**(Sprite Single, alphaIsTransparency on).

`GlowOverlayAlphaByLevel`(index = Lv):

| Lv | 오버레이 알파 | 델타 | 의미 |
|---|---|---|---|
| 0 | 0.00 (off) | — | 미강화 = 발광 없음 |
| 1 | 0.25 | +0.25 | 발광 "켜짐" floor |
| 2 | 0.42 | +0.17 | |
| 3 | 0.58 | +0.16 | |
| 4 | 0.74 | +0.16 | |
| 5 | 0.90 | +0.16 | 만렙 정점 — 가장 밝은 아우라 |

`GlowOverlayAlphaByLevel = [0.00, 0.25, 0.42, 0.58, 0.74, 0.90]`.

- **이것이 밝기의 주 신호**다(§1). 곱연산 틴트가 못 하는 "밝아짐"을 오버레이 알파가 담당. Lv0 off → Lv1 0.25 로 한 번에 켜져 "첫 강화 = 발광 시작"이 명확(전투 emission Lv0 off → Lv1 on 과 동일한 on/off 문법).
- **상점 셀 정합**: 상점 「몬스터 강화」 셀도 아이콘에 `SpeciesGlowColor` 글로우 프레임을 얹고 밝기를 레벨로 올린다(monster-species-enhancement §5.2). 도감은 같은 색 SoT + 같은 "레벨↑ = 밝기↑" 원리를 쓴다 → 도감·상점 표현 일관.
- **구 아이콘의 baked 글로우 대체**: 기존 `MonsterIcons/*.png` 는 방사형 글로우가 **그림에 박혀** 있었다(예: 구 Wisp 아이콘의 녹색 방사광). Part 1 에서 투명배경 원본 렌더로 덮어쓰면 그 baked 글로우가 사라지므로, `_glowOverlay` 가 그 글로우를 **레벨 구동 동적 요소로 되살린다**. 미강화(Lv0)면 글로우 off = 담백한 원본, 강화할수록 아우라가 밝아진다.

**오버레이 요소 스펙(디자인 의도 — 정확한 rect 는 프리팹 배선 Task 4)**: 아이콘보다 살짝 큰 종족색 아우라(≈96×96, 아이콘 중심 정렬, 아이콘 뒤 z-order). 스프라이트 = §3.1 라디얼 소프트글로우. 투명배경 아이콘의 생물 주변으로 부드러운 색이 방사돼 "종족 아우라에 잠긴 몬스터"로 읽힌다.

> **plan delta (명명)**: plan Task 3 Step 1 은 오버레이를 옵션(`_glowOverlay`)으로 뒀다. 본 기획서는 **`_glowOverlay` 를 필수 채택**한다(밝기 주 신호). plan 의 이름 `_glowOverlay` 를 그대로 쓴다(리네임 없음). `_icon.color` 곱연산 틴트(§2)와 **병행**: 틴트=hue, 오버레이=밝기.

## 4. 레벨 → 스케일 곡선 (정점감, ⟨기획서 확정⟩)

**적용**: `_iconRect.localScale = Vector3.one * ScaleByLevel[lv]`. (`_iconRect` = 아이콘 RectTransform, pivot 상단(0.5,1) 고정 → 스케일 시 아이콘이 **아래로** 자란다.)

`ScaleByLevel`(index = Lv):

| Lv | 스케일 | 델타 |
|---|---|---|
| 0 | 1.000 | — |
| 1 | 1.015 | +0.015 |
| 2 | 1.030 | +0.015 |
| 3 | 1.050 | +0.020 |
| 4 | 1.070 | +0.020 |
| 5 | 1.100 | +0.030 |

`ScaleByLevel = [1.00, 1.015, 1.03, 1.05, 1.07, 1.10]`.

- **상한 1.10 은 그리드 기하로 결정된 하드 캡**(넘치면 이름 텍스트 침범). **가속 곡선**(델타 0.015→0.03)으로 만렙에서 확대가 가장 크게 느껴지게 해 "정점감"을 준다.
- **검산(세로 — 이름 텍스트 비침범)**: CodexCell 106×128. 아이콘 84×84, pivot 상단, anchoredPosition (0,−8) → 아이콘 상단 = 셀 상단에서 8px. 이름 텍스트: 하단 앵커, pivot(0.5,0), pos (0,4), 높이 22 → **이름 상단 = 셀 하단에서 26px**.
  - Lv5(스케일 1.10): 아이콘 높이 84×1.10 = 92.4 → 아이콘 하단 = 셀 상단에서 8 + 92.4 = 100.4px → 셀 하단 기준 128 − 100.4 = **27.6px**. 이름 상단 26px 보다 **1.6px 위** → 비침범 ✓.
  - (1.12 로 올리면 아이콘 하단 = 8 + 94.08 = 102.08 → 셀 하단 기준 25.92 < 26 → 이름과 겹침. 그래서 상한 1.10 확정.)
- **검산(가로 — 셀/이웃 비침범)**: Lv5 아이콘 폭 84×1.10 = 92.4 < 셀 폭 106 → 좌우 여백 (106−92.4)/2 = 6.8px. 4열 그리드에서 이웃 침범 없음 ✓.
- **스케일 대상은 아이콘만**: `_glowOverlay`(아우라)는 고정 크기 유지 — 만렙에서 생물이 아우라 안에서 살짝 커지며 "빛을 뚫고 커진 느낌". 오버레이 96×96 ≥ Lv5 아이콘 92.4(=84×1.10) → 아이콘이 아우라를 벗어나지 않음.

## 5. 레벨 배지 (⟨기획서 확정⟩)

- **위치**: 셀 **우상단 코너**. 앵커/피벗 우상단, 오프셋 (−4,−4). 아이콘 우상단 모서리에 겹치는 "레벨 스탬프" 형태(초상화 위 등급 표식 관습). 크기 ≈ 36×18.
- **스타일**: 어두운 알약형 칩(bg #0F1520, 알파 0.85, 라운드) + `CHText`(Rule 03 §3) 흰색 "Lv N", 폰트 ≈13(Jua). 칩 배경으로 밝은 아이콘 위에서도 판독. 종족색 강조는 쓰지 않는다(4채널이 이미 종족색을 쓰므로 배지는 중립 = 정보 명확성 우선).
- **텍스트**: `"Lv N"`(N=1~5). 만렙 강조는 색이 아니라 스케일·발광이 담당하므로 배지는 "Lv 5"까지 동일 포맷(분모 "/5"는 생략 — 좁은 코너 칩 가독성 우선, 최대치 맥락은 상점 탭이 "Lv n/5"로 제공).
- **Lv0 표기**: **숨김**(`SetActive(false)`). 미강화 = 순수 아이콘(발광 off·틴트 white·스케일 1·배지 off) = "아직 안 키운 담백한 원본". "미강화" 라벨을 굳이 붙이지 않는 이유: 6종 중 다수가 초반엔 Lv0 이라 라벨이 도배되면 노이즈. 배지의 **존재 자체가 "강화됨" 신호**가 되어 강화한 종만 도감에서 스탬프로 도드라진다.

**대안 비교(배지)**:

| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **우상단 칩 "Lv N", Lv0 숨김 (채택)** | 강화한 종만 스탬프로 도드라짐, 정확한 레벨, 노이즈↓ | 최대치(/5) 맥락은 상점에서만 | ✅ |

## 6. 미해금 실루엣 ↔ 강화 표시 상호작용 (⟨기획서 확정⟩)

**규칙: 미해금(실루엣) 우선 — 미해금·잠금 더미 셀은 강화 표현(배지·발광·틴트·스케일) 전부 off.**

강화 4채널은 **`data.Species.HasValue && data.Unlocked` 일 때만** 적용한다. 아니면 모두 리셋(배지 off·`_glowOverlay` off·`_icon.color` = 기존 규칙[실루엣 SilhouetteColor]·`_iconRect` 스케일 1).

| 셀 상태 | 아이콘 | 발광 오버레이 | 배지 | 스케일 |
|---|---|---|---|---|
| 해금 + 강화(Lv1~5) | 원본 + 종족색 틴트(§2) | 알파 by Lv(§3) | "Lv N"(§5) | by Lv(§4) |
| 해금 + 미강화(Lv0) | 원본(흰색, 틴트 없음) | off | 숨김 | 1.0 |
| 미해금(SeenMonsters 미포함) | **검정 실루엣**(기존 규칙) | **off** | **숨김** | **1.0** |
| 잠금 더미(IsLockedDummy) | 아이콘 자체 숨김(기존) | off | 숨김 | 1.0 |

**근거**:
- **도감의 1차 계약 = 발견(discovery) 상태 표시**다. 본 적 없는 몬스터는 정체를 숨기는 실루엣이 최우선 — 그 위에 강화 발광을 얹으면 실루엣 익명성이 깨지고 종족색이 새어 정체가 유추된다.
- **엣지 케이스**: 플레이어가 상점에서 미발견 종족을 먼저 강화하면 `Enhance_<종족>` 레벨 > 0 이지만 SeenMonsters 미포함일 수 있다. 이때도 **실루엣 우선(강화 표시 안 함)** 이 옳다 — "강화 투자 표시"는 **아는(발견한) 몬스터에 대한 보상**이고, 미발견은 여전히 실루엣으로 남아 발견 동기를 유지한다. 실제 플레이에서도 전투에서 종을 먼저 마주친 뒤 강화하는 순서가 자연스러워 이 케이스는 드물다.
- **구현 정합**: plan Task 3 Step 2 의 `if (data.Species.HasValue && data.Unlocked)` 가드 = 본 규칙. `else` 분기에서 4채널 전부 리셋(풀 재사용 잔상 방지, §9 리셋 참조).

- 히스토리에 없으면 §7.1 정성 기준 + 영웅 `HeroIcons/Knight.png` 육안 대조로 재구성.
- **육안 수용 기준(메인 검증)**: 6 PNG 가 (1) 실제 몬스터 원본으로 보이고, (2) 영웅 아이콘과 **조명·각도·배경 톤**이 일치하며(프레이밍은 §7.1 대로 **의도적 차이** — 영웅은 흉상 크롭, 몬스터는 전신 크롭이므로 "톤 일치"는 조명/각도/투명배경에 한함, 프레이밍은 6종 자체 일관만 확인), (3) 투명배경·전신 중앙·발광 off 이고, (4) **6종이 서로 동일 프레이밍**(같은 각도·여백·전신 비율)인가 — 6종 프리팹 pivot/높이가 제각각이라 이 항목이 가장 어긋나기 쉬움, 종별 개별 확인. 하나라도 실패면 §7.1 기준으로 재베이크.

## 8. 그리드 가독성 (4열) 종합 점검

- **셀 106×128, 4열**. 4채널이 저레벨에서 미묘(각 채널 Lv1 floor 낮음)하고 고레벨에서 또렷 → 그리드 전체가 "강화한 종만 도드라지고 나머지는 담백"한 대비를 만든다.
- **배지**는 우상단 코너 칩으로 아이콘 본체를 가리지 않음. **발광 오버레이**는 아이콘 뒤라 생물 실루엣을 가리지 않음. **스케일**은 1.10 상한으로 이름·이웃 비침범(§4 검산). → 4채널이 서로의 정보를 덮지 않고 겹쳐 읽힌다.
- **색 대비**: 6종 `SpeciesGlowColor` 는 max 0.90 정규화로 어두운 배경(#1F2937)에서 균일 가시(monster-species-enhancement §4.2). 4열에서 서로 다른 종족색 아우라가 나란히 놓여도 각 색이 구별됨(Wisp 녹 / Reaper 적 / Hex 금 / Plague 자 / Phantom 청 / Wraith 냉백).

## 9. 구현 요청사항 (gameplay-programmer 용)

> 시그니처·파일 구조는 plan 이 SoT. 아래는 도메인 값·시각 스펙의 확정.

### Enum (Rule 02 §8)
- **신규 Enum 없음**. 기존 `EMonster`(Wisp~Phantom) 재사용.

### Interface / static
- **신규 인터페이스 없음**. 발광색은 기존 `Lair.Data.SpeciesVisual.SpeciesGlowColor(EMonster) → Color`(단일 SoT) 를 **읽기만** 한다(신규 색 정의 없음).
- 레벨→틴트/발광/스케일 매핑은 `CodexCell` 내부 **static 룩업 테이블 상수**(전투 `_emissionByLevel` 처럼 배열). 런타임 `Mathf.Pow` 불필요.

### SO 스키마 / 데이터 필드
- `CodexCellData`(CodexPopup.cs)에 필드 추가: `public int EnhanceLevel;`(0~5), `public EMonster? Species;`(몬스터 셀만, 카드/더미는 null).
- `BuildMonsterCellData` 루프에서 `Species = type`, `EnhanceLevel = profile.GetShopLevel("Enhance_" + type)`. **시그니처 `BuildMonsterCellData(profile, cfg, iconResolver)` 3-arg 유지**(테스트·호출부 무회귀). 카드/더미 빌더는 두 필드 미설정(기본값 `EnhanceLevel=0`·`Species=null`).

### CodexCell 위젯 필드 (`[SerializeField] private`, Rule 02 §6.1)
- `_levelBadge` (CHText) — 우상단 레벨 배지 텍스트(§5).
- `_glowOverlay` (Image) — 아이콘 뒤 종족색 발광 아우라(§3). 스프라이트 = §3.1 라디얼 소프트글로우 프리미티브(신규 1장, 런타임 종족색 틴트). 인스펙터 참조.
- `_iconRect` (RectTransform) — 스케일 대상(= 기존 `_icon` 의 RectTransform, §4).

### 레벨 매핑 상수 (CodexCell 내 static)
```
IconTintByLevel        = [0.00, 0.16, 0.28, 0.40, 0.52, 0.64]   //# Color.Lerp(white, SpeciesGlowColor, t)
GlowOverlayAlphaByLevel= [0.00, 0.25, 0.42, 0.58, 0.74, 0.90]   //# _glowOverlay.color 알파, Lv0 off
ScaleByLevel           = [1.00, 1.015, 1.03, 1.05, 1.07, 1.10]  //# _iconRect.localScale
```
- 인덱스 = 레벨(0~5). 안전 접근(`Mathf.Clamp(lv, 0, 5)`).

### Bind 로직 (§6 상호작용)
- `data.Species.HasValue && data.Unlocked` 일 때만 4채널 적용. 아니면 전부 리셋:
  - 배지 `SetActive(false)`, `_glowOverlay` `SetActive(false)`(또는 알파 0), `_iconRect.localScale = Vector3.one`, `_icon.color` = 기존 규칙(해금 white / 미해금 SilhouetteColor).
- **풀 재사용 리셋 필수**: `CodexCell` 은 몬스터/카드/더미 셀에 공용 재사용된다. `Bind` 이 매 재사용마다 4채널을 **전부 재설정**해야 카드/더미/미해금 셀에 이전 몬스터의 배지·발광·스케일 잔상이 남지 않는다. Lv0 = 발광 off·틴트 white·스케일 1·배지 off 로 명시 리셋.

### 프리팹 배선 (Task 4 — ⛔ 목업 승인 게이트 선행)
