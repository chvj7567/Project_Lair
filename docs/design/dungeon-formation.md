## § 헤더

- **목표**: 출격 직전 플레이어가 던전의 둥지(스포너) 6곳에 **기존 몬스터 6종** 중 무엇을 넣을지 코스트 안에서 고르는 **던전 편성** 화면을 만든다. 스테이지(규칙·영웅·배경·수치)는 그대로 두고, 플레이어 쪽 선택으로 판마다 다른 출발점을 만든다.
- **검증 가설**: (1) 챕터별 영웅 약점 축(Ch2 Tank 약 / Ch3 Dps 약 / Ch4 Swarm 약 / Ch5 Debuff 약)과 스테이지 규칙(봉인 종·안개·보스 페이즈)이 화면에 보이면, 플레이어가 **스테이지마다 다른 편성**을 고르는가. (2) 편성이 카드 3택1의 후보 풀을 바꿔(편성에 없는 종의 카드 제외) **빌드 방향을 출격 전에 미리 정하는 결정**이 되는가. (3) 기본 편성(현행 배치)을 그대로 두면 판 전체가 오늘의 게임과 비트 단위로 같아 기존 밸런스가 깨지지 않는가(2026-11-01 현행: 판 중 출력 종을 바꾸는 카드가 없어 기본 편성에서는 6종이 끝까지 출력되고 카드 후보 제외가 0 이다 - §5.2·R7).
- **현재 단계 범위 적합성**: **범위 밖 항목의 명시 승격 요청 - 사용자 승인 필요.** CLAUDE.md §8 은 "던전 편성·신규 몬스터 6종" 을 개별 승격 전까지 금지한다. 이 기획은 **던전 편성만** 승격을 제안하며(§12 승격 문구 초안), **신규 몬스터는 포함하지 않는다**(후속 제안으로만 §11). ★ 목표·무한 탑·데일리는 계속 금지(연동 가정만 §10). 서버는 Firebase 클라이언트 코드 범위 유지(신규 서버 코드 0, 편성은 `MetaProfile` 일부로 기존 클라우드 백업에 실린다). 별도 메인 메뉴/세팅 화면 금지 유지(편성은 마을 HUD 안 팝업). **승인 전에는 구현에 착수하지 않는다.**
- **핵심 메커니즘**: (a) 슬롯 = 씬의 스포너 6개(개수·위치 불변). 각 슬롯에 6종 중 1종을 넣고, 종마다 코스트(1~3)가 있어 합계가 상한 13 을 넘을 수 없다. 기본 편성(현행 1종씩) = 코스트 13 = 상한. (b) 같은 종은 최대 2곳(1장 보스 처치 후 3곳). **(2026-11-01 개편 - §0 이 우선)** 코스트·상한·종당 최대·해금 단계 2 는 폐지됐고, 둥지 6곳은 종족(이그니스·레무르·눅스·헥시아·미아르·판타스)의 자리로 고정되어 플레이어는 종족마다 소속 몬스터 하나를 고른다(가정). 지금은 종족당 몬스터가 1개라 선택지가 없고 편성 화면은 확인용이다. (c) 고르지 않은(출력되지 않는) 몬스터를 대상으로 하는 카드는 3택1 후보에서 빠진다(현재는 휴면).

> **읽는 법**: 이 문서의 §1~§15 는 코스트·상한·종당 2~3·순서 배치를 전제로 쓴 설계다. **§0(2026-11-01 종족·등급 개편)과 충돌하는 서술은 §0 이 우선**하며, 본문에 달린 "(2026-11-01 …)" 주석과 §0A 는 개편 이전 단계의 이력이다. 폐지된 항목: §2.2 코스트 도출식·§2.3 상한·§2.4 해금 단계 2·§2.5 조건 3~4·§3 의 `FormationMonster`/`FormationConfig` 구 필드·§5.3 추가 소환 안 비교·§7.4 코스트 게이지/팔레트 구조·게이트 F2~F5·D-3~D-6·D-11·R2·R3·R9. (d) 편성 저장은 `MetaProfile.Formation`(0행 = 기본 편성, 또는 정확히 6행).

**해석 확인**: "스테이지 고정 + 플레이어 쪽 선택으로 반복감 해소 + 기존 몬스터만 + 마을 HUD 안 팝업" 모두 반영. 이견 1건을 §1.4 에 정직하게 적었다 - 편성은 **스테이지 사이**의 반복감은 강하게 깨지만, **같은 스테이지를 연속 재도전**할 때는 플레이어가 한 편성으로 수렴할 가능성이 높다(위험 R1, 결정 D-12).

### 0.2 종족 · 등급 · 몬스터 (표)

| 종족 (`ERace`) | 표시 이름 | 의미 | 소속 몬스터 (등급 → `EMonster`) | 편성 슬롯 |
|---|---|---|---|---|
| `Ignis` | 이그니스 | 불 | 1 `Wisp` (풋내기 도깨비불) | 1 |
| `Nox` | 눅스 | 밤 | 1 `Reaper` (풋내기 사신) | 2 |
| `Hexia` | 헥시아 | 저주 | 1 `Hex` (풋내기 저주술사) | 3 |
| `Lemur` | 레무르 | 떠도는 영혼 | 1 `Wraith` (풋내기 망령) | 4 |
| `Miar` | 미아르 | 독기 | 1 `Plague` (풋내기 역병귀) | 5 |
| `Phantas` | 판타스 | 환영 | 1 `Phantom` (풋내기 환령) | 6 |

- 슬롯 → 종족 매핑은 §2.1 의 현행 기본 슬롯 순서(도깨비불 / 사신 / 저주술사 / 망령 / 역병귀 / 환령)를 그대로 종족으로 바꾼 것이다. 기본 편성 = 각 슬롯 종족의 **최저 등급 몬스터** = 현행 씬 배치와 같다.
- 한 몬스터는 정확히 한 종족·한 등급에만 속한다(`monster` 는 전체에서 유일). 2~5등급 칸은 **자리만** 있고 몬스터 행이 없다 - 화면에는 존재하는 몬스터만 보인다("준비 중" 자리표시 없음, 신규 몬스터 노출 방지).
- 등급 접두어 문구는 5개(풋내기/견습/숙련/정예/군주). 표시 이름은 `접두어 + 공백 + 기존 이름`.
- **접두어 적용 범위(가정, U-E)**: 개별 몬스터를 가리키는 화면 이름(상점 몬스터 행 머리, 편성 칸, 도감, 스포너 상태 UI)에는 접두어를 붙이고, 카드·시너지·유물 문구의 집합 표기("모든 도깨비불 HP +50%")는 접두어 없는 기존 이름을 유지한다. 목록은 §0.9.

### 0.3 편성 방식 (가정) · 지금 편성 화면이 하는 일

| 항목 | 현행 규칙 (가정) |
|---|---|
| 슬롯 | 6 고정, 슬롯마다 종족 1개 고정(`FormationSlot.race`) |
| 선택 | 슬롯마다 **그 종족 소속 몬스터 중 1개**(`Race_Monster`). 다른 종족의 몬스터는 못 넣고, 슬롯끼리 자리를 맞바꾸는 조작은 없다 |
| 빈 둥지 | 없음 (종족마다 몬스터 1개 이상 필수) |
| 유효 편성 | 모든 슬롯 i 에서 `F[i]` 가 슬롯 i 종족의 소속 몬스터. 중복 몬스터는 소속이 유일해서 구조적으로 불가 |
| 기본 편성 | 슬롯마다 종족의 최저 등급 몬스터. `Formation` 0행 = 기본 편성(그대로) |
| 코스트·상한·종당 최대·해금 단계 2 | **없음** (폐지) |

**솔직한 현황**: 종족마다 몬스터가 **1개뿐**이라 **선택지가 하나도 없다.** 유효한 편성은 기본 편성 하나뿐이고, 편성 팝업은 "6개 둥지에 어떤 몬스터가 들어가는지 확인하고 출격" 하는 **확인용 화면**이다. "1-1 클리어 후 해금(`unlockClearedStage` 1)" 은 그래서 **"선택 기능이 열린다" 가 아니라 "확인 팝업이 열린다" 는 뜻**일 뿐이고, 출격 클릭이 1회 늘어나는 마찰(R5)만 생긴다. 바뀌는 것은 ① 이름(풋내기 접두어) ② 종족 이름이 팝업에 보이는 것뿐이다. **신규 몬스터가 승격되기 전까지 편성 기능은 사실상 비어 있다** - 어떻게 둘지는 §0.8 U-D.

몬스터가 추가되면(승격 후): 같은 종족에 2등급 몬스터가 생기고 그 슬롯에서 1등급과 2등급 중 하나를 고르게 된다. 이때 비로소 ① 고르지 않은 몬스터를 대상으로 하는 카드가 3택1 후보에서 빠지는 규칙(§0.7, 휴면 해제) ② 편성이 실력 요소가 되므로 랭킹 영향 점검(F6) ③ 몬스터 등급별 능력치·코스트 개념의 재도입 여부(별도 결정)가 의미를 갖는다.

### 0.4 슬롯 고정 구조가 폐지시키는 것

- 종당 최대(`maxPerSpecies`): 한 종족은 한 슬롯뿐이고 몬스터는 한 종족 소속이라 한 몬스터를 두 곳에 둘 방법이 없다 → 의미 없음, 폐기.
- 코스트: 합이 늘 같고(고르는 것이 없음) 몬스터 간 비교 요소도 없다 → 폐기. 몬스터 추가 후에 "더 높은 등급 = 더 비싼 선택" 장치가 필요해지면 그때 별도 결정(코스트 재도입이 아니라 등급 효과로 풀 가능성 있음).
- 순서 배치/맞교환(구 §0A 단계의 UI): 슬롯→종족이 고정이라 자리 맞바꿈이 불가 → 폐기.

**§11-1 판정 메모**
- Race: 핵심 엔티티 = "종족 하나". 이름·성격은 모든 종족이 가지는 **필수 1:1** 이라 직접 필드(관계 데이터 불필요).
- Race_Monster: 종족과 몬스터의 관계는 **선택적**(2~5등급은 몬스터가 있는 종족·등급에만 행) → 별도 관계 데이터. `-1`/null 같은 빈 칸 sentinel 없음(없는 등급 = 행 없음). 한 종족 안에 등급별 여러 몬스터가 생기므로 **복합키 `race + grade`**(§11-1-4). 이름 규칙 `<부모>_<관계명>`(§11-1-5) = `Race_Monster`.
- Grade: 모든 등급이 접두어를 항상 하나씩 가지므로 필수 1:1 직접 필드. 종족과 독립인 별도 엔티티(등급은 종족 간 공유).
- FormationSlot.race: 모든 슬롯이 정확히 한 종족을 가지는 필수 1:1 → 직접 필드(`defaultMonster` 의 후속). 기본 몬스터는 저장하지 않고 `Race_Monster` 에서 도출한다(최저 등급) - 몬스터가 추가되어도 기본 편성이 어긋나지 않는다.
- `FormationMonster`(monster, cost): cost 폐지로 `monster` 만 남아 `Race_Monster` 와 중복 → **삭제**.

**로드 검증** (위반 시 로드 오류, 기존 오류 수집 패턴)
1. `Race`: `ERace` 6값을 정확히 한 번씩, `nameKey`·`descKey` 가 Strings_Ko 에 존재.
2. `Grade`: `grade` 1~5 연속, `prefixKey` 존재.
3. `Race_Monster`: `(race, grade)` 중복 없음, `race` ∈ Race, `grade` ∈ Grade, `monster` 가 `EMonster` 값명이고 **전체에서 한 번만**, **종족마다 몬스터 1개 이상**(기본 편성 보장).
4. `FormationSlot`: `slot` 1~6 정확히 한 번씩, `race` ∈ Race, **6슬롯이 6종족을 정확히 한 번씩**(슬롯 수 = 종족 수 불변식).
5. `FormationConfig`: `unlockClearedStage >= 0`.
6. `Card_Species`: `(cardId, monster)` 중복 없음, `cardId` 가 `ECardId` 값명, `monster` ∈ `Race_Monster.monster`.
7. `Chapter_FormationHint`: 모든 챕터에 문구 존재(기존).
8. **로드 실패 시**: 기존과 같다 - 오류 로그 후 "편성 기능 비활성"(팝업 없이 바로 출격, 씬 인스펙터 `_outputType`, 카드 제외 없음, 저장 편성 보존). `Card_Species` 만 실패하면 카드 제외만 끈다.

### 0.6 저장 · 마이그레이션 · Version

- `MetaProfile.Formation` 의 **모양(`List<FormationSlotEntry>{Slot, Monster}`)은 불변**이다. 의미만 "각 슬롯의 몬스터 선택" 으로 바뀐다(이전에도 슬롯마다 몬스터 1개).
- **`Version` 은 올리지 않는다.** 근거: ① 필드 추가/삭제/타입 변경이 없다 ② 새 유효성(종족 소속)은 `Race_Monster` JSON 에 의존하므로 JSON 로드 전에도 도는 마이그레이션에서 검사할 수 없다(기존 코스트 검사와 같은 이유, `difficulty-select.md` §3.1 선례) ③ 구버전 클라이언트도 같은 모양을 읽는다. 편성 도입 버전 9 표기와 현행 `CurrentVersion` 12 는 그대로다.
- **마이그레이션 규칙 4(구조 정리: null 행·행 수 0/6 아님·슬롯 1~6 미중복·`Monster` 가 `EMonster` 값명 아님 → 0행)는 유지**한다. §0A 단계에서 추가했던 **규칙 5(순열 검사)는 철회**한다 - 몬스터가 추가되면 순열이 아닌 유효 편성이 생기므로 영구 규칙으로 부적합하다.
- **읽는 순간 판정**(`FormationRules`): 슬롯마다 종족 소속 검사. 무효면 전투는 `EffectiveFormation` 이 **기본 편성**으로 방어(+경고 로그, 기존 §6.3). 팝업은 무효 슬롯만 그 종족의 기본 몬스터로 치환해 보여 주고 "출격" 때 저장한다. 따라서 이전 규칙(종당 2~3 / 순서 배치)으로 저장된 **슬롯-종족이 어긋난 편성은 자동으로 기본 편성이 된다**(출격이 막히지 않는다). 안내 토스트는 U-C.
- 클라우드: `CopyFrom`·충돌 UX 변경 없음. 복원된 편성이 무효이면 같은 읽기 판정.

### 0.7 연관 규칙

| 규칙 | 현행 (개편 후) |
|---|---|
| **카드 후보 제외 (`Card_Species`, §5.2)** | 슬롯 종족마다 몬스터가 1개뿐이라 6종이 항상 출력 -> 제외 0. 18행·제외 조건은 **휴면 유지**. 몬스터가 추가되어 플레이어가 그 종족의 다른 등급을 고르면 "고르지 않은 몬스터를 대상으로 하는 카드(예: 풋내기 도깨비불 HP 카드)" 가 후보에서 빠지는 용도로 되살아난다. any-of 매핑(수호자의 분노·공포의 군세·처형 명령)도 그대로 |

| **랭킹 · 최단 기록 (§5.6, D-9)** | 지금은 유효 편성이 기본 하나뿐이라 영향 0. Easy 한정 규칙 그대로. 몬스터가 추가되어 편성이 실력 요소가 되는 시점에 F6 로 재점검 |
| **상점 육성 (`monster-growth-currencies.md`)** | 육성은 몬스터 단위(체급 `Enhance_<EMonster>` 등 키 불변). 편성에서 고르지 않은 몬스터의 육성은 그 판에 쓰이지 않는다(몬스터 추가 후 적용될 수 있는 규칙) |

### 0A.2 봉인된 둥지 · 카드 후보 제외

- **봉인(§5.1)**: 봉인 종은 편성에 늘 정확히 1곳이다. 따라서 "봉인 종 0곳이면 코스트 최고 둥지 봉인"·"2곳 이상이면 슬롯 번호 최소"·"동률은 슬롯 번호 최소" 분기는 **발생하지 않는다**. 현행 `StageRuleContext.LockSpawners(species)`(그 종을 출력하는 모든 스포너 봉인)의 결과가 곧 "정확히 1곳" 이므로 §5.1 안 A("현행 유지")와 같은 동작이 되고, 안 C 의 대체 규칙 코드는 불필요하다(구현에 이미 들어간 대체·동률 코드는 정리 대상, §0A.5). 봉인 종이 "회피 불가·피해 최소 둥지 선택" 이라는 결정(P2)도 사라져, 편성 팝업의 봉인 예고 줄은 **어느 둥지 번호가 막히는지 알려 주는 정보**가 된다. 해제 조건·해제 버스트·전투 HUD 해제 % 표시는 변경 없음.
- **카드 후보 제외(§5.2)**: 6종이 판 내내 출력 중이므로 어떤 카드도 제외되지 않는다. 판 중 종 교체 카드도 없어(2026-11-01 이전 정정) 제외 조건이 참이 되는 경로가 없다. `Card_Species` 18행·`CardDeck.Draw` 제외 조건은 그대로 두되 항상 거짓이다(휴면). F4 후보 부족 검산(§5.2 최소 4장)은 전제 편성이 불가능해져 무효 - 후보는 항상 28장 전체에서 3픽 캡 제외분만 빠진다.
- **추가 소환(§5.3)**: 그 종 둥지가 1곳이라 "전부 +1" = "1곳 +1" = 현행 게임 그대로. 결과 변화 0.
- **풀 워밍(§6.4)**: 종별 현행 수 × 편성 곳 수(최소 1) = 현행 수 × 1 → 변경 없음.

- 영웅 성향 문구는 기획 가설(`chapter-4.md` §1·`chapter-5.md` 빌드 압박 표)이다. 문구가 시뮬 결과와 어긋나면 문구만 고친다(`Strings_Ko` 한 줄).

### 1.4 한계 - 같은 스테이지 연속 재도전

같은 스테이지를 다시 도전하면(유물 파밍, 난이도 상승, 랭킹 갱신) 영웅·규칙·편성 조건이 전부 같으므로 플레이어는 결국 "그 스테이지의 최선 편성" 하나로 수렴할 가능성이 높다. 이 경우 반복감을 깨는 것은 기존과 같이 카드 3택1의 무작위성과 난이도 선택이다. 편성은 이 문제를 **줄이지만 없애지 못한다.**

- 완화(이번 범위): 코스트를 "서로 다른 편성이 비슷한 강함" 이 되게 튜닝(F2 의 "최선 편성 5% 이내 편성 수" 지표). 카드 후보 제외(P3)로 편성마다 카드 흐름이 달라져 같은 스테이지라도 편성을 바꿔 볼 이유가 생긴다.
- 완화(후속 제안만, §11): 편성 프리셋, 스테이지별 추천 편성 표시. 이번에는 하지 않는다(D-12).

### 2.2 코스트 - 도출식

코스트는 `BalanceConfig.asset` 의 종별 기본 스탯에서 도출한다(감으로 정하지 않음).

```
공격 처리량 D(종) = (Power / Cooldown) / SpawnPeriod        (스포너 하나가 초당 보드에 더하는 DPS 기여)
체력 처리량 H(종) = Hp / SpawnPeriod                        (스포너 하나가 초당 보드에 더하는 HP)
상대 가치 V(종)  = (1.0 × D/평균D + 0.4 × H/평균H) / 1.4    (가중치 Power 1.0 / HP 0.4 = village-meta-hub §3.3 상점 검산 모델)
코스트(종)       = round(2 × V), 최소 1
```

| 종 | Hp | Power | Cooldown | Period | D | H | D/평균D | H/평균H | V | 2V | **코스트** |
|---|---|---|---|---|---|---|---|---|---|---|---|
| Wisp 도깨비불 | 200 | 5 | 1.0 | 9 | 0.556 | 22.22 | 1.019 | 1.917 | 1.276 | 2.55 | **3** |
| Wraith 망령 | 500 | 10 | 1.0 | 20 | 0.500 | 25.00 | 0.917 | 2.157 | 1.271 | 2.54 | **3** |
| Reaper 사신 | 100 | 6 | 0.5 | 12 | 1.000 | 8.33 | 1.833 | 0.719 | 1.515 | 3.03 | **3** |
| Hex 저주술사 | 60 | 9 | 1.0 | 15 | 0.600 | 4.00 | 1.100 | 0.345 | 0.884 | 1.77 | **2** |
| Plague 역병귀 | 50 | 2 | 1.0 | 10 | 0.200 | 5.00 | 0.367 | 0.431 | 0.385 | 0.77 | **1** |
| Phantom 환령 | 30 | 2 | 0.8 | 6 | 0.417 | 5.00 | 0.764 | 0.431 | 0.669 | 1.34 | **1** |

검산: 평균D = (0.556+0.500+1.000+0.600+0.200+0.417)/6 = 3.273/6 = 0.5455. 평균H = (22.22+25.00+8.33+4.00+5.00+5.00)/6 = 69.55/6 = 11.59. Wisp V = (1.019 + 0.4×1.917)/1.4 = (1.019+0.767)/1.4 = 1.276. Reaper V = (1.833 + 0.4×0.719)/1.4 = (1.833+0.288)/1.4 = 1.515. V 합 = 1.276+1.271+1.515+0.884+0.385+0.669 = 6.000(정규화 확인).

- **모델이 빠뜨린 것**: 역병귀 둔화(공격 시 영웅 둔화 20%), 저주술사 사거리 5(후방 생존), 환령 이동속도 2.4(빠른 접촉)는 V 에 들어 있지 않다. 그래서 역병귀·저주술사·환령의 실제 가치는 V 보다 높을 수 있다. **최종 코스트는 qa-simulator 검증 후 결정**하며 결정 메트릭은 게이트 F2·F5(§9).
- 반올림 결과 사신(V 1.515)과 도깨비불(1.276)이 같은 코스트 3 이다. 즉 이 초기값에서는 사신이 "코스트 대비 가장 좋은 3코스트" 다. 의도적으로 그대로 둔다 - 사신은 HP 100 으로 약해 암살자(Ch3)·광전사(Ch4)에게 약하므로 챕터마다 평가가 바뀌는지가 F2 의 관찰 대상이다.

| `costCap` | **13** (고정, 성장 없음) | 기본 편성 합 = 3+3+2+3+1+1 = 13. 기본 편성이 정확히 상한이라 **어떤 변경도 무언가를 내주는 교환**이다. **(2026-11-01 개편 - 폐지)** 코스트·`costCap` 은 사용자 결정으로 폐기됐다(§0.1-1). 이 절은 이력 |
| 상한 성장 | **없음** (D-3) | 상한을 키우면 편성이 "교환" 이 아니라 "순수 강화" 가 되어 스테이지 튜닝(`chapter-system.md` §0A.4 의 상점 보조 계수 M)을 다시 해야 한다. 이번 목적은 다양성이지 강화가 아니다 |

**상한 13 에서 가치 지수 상한** (V 합, 기본 편성 = 6.000) - **(2026-11-01) 작성 당시 기록, 종당 1 이후 모든 편성의 V 합은 6.000 으로 아래 표는 무효**:

| 종당 최대 | 최고 가치 편성(모델 기준) | 코스트 | V 합 | 기본 대비 |
|---|---|---|---|---|
| 2 | 사신 2 · 환령 2 · 저주술사 1 · 도깨비불 1 | 6+2+2+3 = 13 | 3.030+1.338+0.884+1.276 = 6.528 | +8.8% |
| 3 | 사신 3 · 환령 2 · 저주술사 1 | 9+2+2 = 13 | 4.545+1.338+0.884 = 6.767 | +12.8% |

- 비교: 상점 만렙 환산 +30.8%(`village-meta-hub.md` §3.3), 유물 능력치 풀셋 +28.3%(`relics.md` §1.3). 편성 최적화의 상한은 모델 기준 +8.8~12.8% 로 그보다 작다. 이 값은 "편성 공부의 보상" 이며 단, V 가 둔화·사거리를 빠뜨렸으므로 실제 최적 편성은 다를 수 있다(F2).
- 대안: 영주 Lv4/6/8 잠금 더미 보상을 "코스트 +1" 로 바꾸는 상한 성장안. 상한 16 이면 사신 3 · 도깨비불 1 · 망령 1 · 환령 1 = 9+3+3+1 = 16, V = 4.545+1.276+1.271+0.669 = 7.761(+29.4%)로 상점 만렙급 강화가 추가된다 → 기각(D-3).

### 2.4 해금 규칙

| 단계 | 조건 | 열리는 것 |
|---|---|---|
| 0 | `ClearedStage = 0` (1-1 미클리어) | 편성 잠김. "방어하기" 는 지금처럼 바로 출격, 기본 편성 사용 |
| 1 | `ClearedStage >= 1` (1-1 클리어) | 편성 팝업 해금. 종당 최대 **1** 곳 (2026-11-01 개정, 이전 2) |
| ~~2~~ | ~~`ClearedStage >= 5`~~ | **폐지 (2026-11-01)** - 종당 3 해금은 없다. 종당 최대는 해금과 무관하게 1 |

- 몬스터 종 해금은 없다 - 6종 모두 기본 편성에 이미 있다.
- 해금 단계 0 의 이유: 첫 판 신규 유저에게 선택 화면을 먼저 보여 주면 "뭘 골라야 하는지" 모르는 상태에서 결정을 강요한다. 1-1 을 한 번 깨서 6종이 어떻게 싸우는지 본 뒤 연다.
- 해금 단계 2 (폐지, 2026-11-01): 작성 당시 이유는 "종당 3 으로 가치 상한 +8.8% → +12.8%, 한 종 집중 빌드 개방". 종당 1 결정으로 삭제.
- 결과창 변경 없음. `ClearedStage` 0→1(1-1 첫 Easy 클리어)은 항상 난이도 "Normal 해금!" 배너가 뜨는 승리라(`difficulty-select.md` §4.4) 편성 배너를 따로 둘 자리가 없다. 발견은 다음 "방어하기" 에서 팝업이 처음 열리는 것으로 충분하다.

### 2.5 편성 유효성 (단일 판정 함수)

편성 F(슬롯 1~6 의 종) 가 유효한 조건 - 모두 만족:

1. 슬롯 1~6 이 정확히 한 번씩 채워져 있다.
2. 모든 몬스터가 `Race_Monster` 에 있는 `EMonster` 값이다. **(2026-11-01 개편: 구 `FormationMonster`)**
3. ~~`Σ cost(F[i]) <= costCap`~~ **폐지** (코스트 폐기, §0.1-1).
4. ~~종당 등장 수 `<= maxPerSpecies`~~ **폐지** -> 대체 조건: **모든 슬롯 i 에서 `F[i]` 는 슬롯 i 의 종족(`FormationSlot.race`)에 속한 몬스터**(§0.3). 중복 몬스터는 소속이 유일해 구조적으로 불가.

이 판정은 순수 함수 하나(`FormationRules`, §13.5)가 소유하며 마을 팝업·전투 시작·마이그레이션 이후 읽기 지점이 모두 이것을 쓴다. 상한과 종당 최대는 **인자로 받는다**(무한 탑·데일리가 다른 상한·고정 편성을 넘길 수 있게, §10).

## 3. 데이터 구조표 (구 구조 - 2026-11-01 개편으로 **§0.5 가 대체**)

> **이 §3 은 코스트 시절 구조(`FormationMonster`(cost)·`FormationConfig`(costCap·종당 최대·해금 단계 2)·`FormationSlot.defaultMonster`)의 이력이다.** 현행 구조표·필드 개명/삭제·로드 검증은 **§0.5**, 저장·마이그레이션은 §0.6. 아래 표의 `Card_Species`·`Chapter_FormationHint`·`MetaProfile.Formation` 서술은 모양이 같아 그대로 유효하다(FK 대상만 `Race_Monster.monster`).

> Rule 02 §11-1 적용. 콘텐츠·밸런스 수치 = JSON(`Assets/_Lair/Data/Json/`, 파일명 = `EData` 값명). 세이브 = `MetaProfile` 엔트리 리스트(`DifficultyClearEntry`/`RelicEntry` 선례). sentinel(-1/0/null) 미사용. 관계 데이터 이름 `<부모>_<관계명>`.

### 3.1 엔티티 / 관계 트리

```
FormationConfig (단일 설정 행)  전역 편성 규칙 수치                         <- 1행
FormationMonster (엔티티)  "편성에 넣을 수 있는 몬스터 종 하나"              <- 6행 (EMonster 6종 전부)
FormationSlot    (엔티티)  "던전 둥지(스포너) 하나"                          <- 6행 (슬롯 1~6)
 |-- defaultMonster ─────────────────► FormationMonster.monster   (필수 1:1, 직접 필드)

Card (기존, ScriptableObject - ECardId)
 +-- Card_Species (선택적 관계, 복합키 cardId+monster)  "이 카드가 효과를 내려면 이 종이 출력 중이어야 한다"
        monster ─────────────────────► FormationMonster.monster          <- 18행 (종 의존 카드만 행 존재)

Chapter (기존, JSON)
 +-- Chapter_FormationHint (관계, chapterId)  "편성 팝업에 보여 줄 영웅 성향 문구"   <- 5행

MetaProfile (세이브 루트)
 +-- Formation : List<FormationSlotEntry>  { Slot, Monster }   <- 0행(기본 편성) 또는 정확히 6행
        Slot ─────────────────────────► FormationSlot.slot
        Monster ──────────────────────► FormationMonster.monster
```

- 관계 판정:
  - `FormationSlot.defaultMonster` 는 모든 슬롯이 정확히 하나를 갖는 **필수 1:1** 이라 직접 필드(§11-1-3).
  - `Card_Species` 는 28장 중 종에 의존하는 카드만 행이 있는 **선택적 관계**다. 의존 없는 카드에 "None" 행을 두지 않는다. 한 카드가 여러 종 중 하나에만 의존할 수 있어(수호자의 분노·공포의 군세 = 도깨비불·망령 둘 중 하나라도 출력 중이면, 처형 명령 = 사신·저주술사 둘 중 하나라도 출력 중이면) 복합키 `cardId + monster`(§11-1-4). **의미는 "행 중 하나라도 출력 중이면 후보"(any-of)**.
  - `Chapter_FormationHint` 는 모든 챕터에 하나씩 있는 필수 1:1 이지만 기존 `Chapter.json` 스키마·테스트를 건드리지 않고 편성 기능을 독립 제거할 수 있도록 별도 관계 데이터로 분리했다(`Stage_Relic` 선례).
  - `FormationMonster` 는 BalanceConfig(SO)의 종별 스탯과 별개 엔티티다. 코스트는 "자주 튜닝되는 밸런스 수치" 라 JSON(Rule 02 §11)이고, 종 스탯은 이번에 옮기지 않는다.
- 세이브 판정: `Formation` 은 **0행 = 사용자가 편성을 바꾼 적 없음(기본 편성 사용)**, **6행 = 사용자 편성**. 부분 행(1~5행·7행 이상)은 무효 상태이며 마이그레이션이 0행으로 정리한다(§4.1). "기본으로 되돌리기" 는 0행으로 저장한다 - 기본 편성 JSON 이 바뀌면 바꾸지 않은 유저가 자동으로 새 기본을 따르게 하기 위함이다.

### 3.3 로드 검증 (위반 시 로드 오류, `ChapterDatabase` 오류 수집 패턴 재사용)

1. `FormationMonster`: 6행, `monster` 가 `EMonster` 6값을 정확히 한 번씩, `cost >= 1`.
2. `FormationSlot`: 6행, `slot` 이 1~6 연속, `defaultMonster` 가 `FormationMonster` 에 존재.
3. `FormationConfig`: `costCap >= 6`(최저 코스트 1 x 6 슬롯), `1 <= maxPerSpecies <= 6`, `unlockClearedStage >= 0`. (2026-11-01: 해금 단계 2 필드 삭제로 순서 검사 제거)
4. **기본 편성이 유효**: 기본 편성의 코스트 합 `<= costCap`, 종당 등장 수 `<= maxPerSpecies`. (이 검사가 없으면 코스트 튜닝 실수로 아무것도 안 바꾼 유저가 출격 불가가 된다.)
5. **채울 수 있음**: `maxPerSpecies x 종 수 >= 6` (2026-11-01: 1 x 6 = 6 ≥ 6 - 경계값이라 `maxPerSpecies` 를 1 미만으로 두면 로드 오류).
6. `Card_Species`: `(cardId, monster)` 중복 없음, `cardId` 가 `ECardId` 값명, `monster` 가 `FormationMonster` 에 존재.
7. `Chapter_FormationHint`: `Chapter.json` 의 모든 `chapterId` 를 정확히 한 번 덮고, `hintKey` 가 Strings_Ko 에 존재.
8. **로드 실패 시**: 오류 로그 후 "편성 기능 비활성" 으로 동작 - "방어하기" 는 팝업 없이 바로 출격, 전투는 씬 인스펙터 `_outputType`(= 현행) 사용, 카드 후보 제외 없음. 저장된 `Formation` 은 지우지 않는다(데이터 복구 시 복원). `Card_Species` 만 실패하면 카드 제외만 끄고 편성은 정상 동작.

## 5. 편성이 다른 시스템과 맞물리는 방식

### 5.1 스테이지 규칙 - 봉인된 둥지 (`SealedNest`)

> **(2026-11-01 개편 - §0.7)** 봉인은 **봉인 대상 몬스터가 속한 종족의 둥지 1곳**을 막는다. 종족 자리가 고정이라 항상 정확히 1곳이며, 아래 안 C 의 "봉인 종 0곳 → 코스트 최고 둥지"·"2곳 → 슬롯 번호 최소"·동률 분기는 불필요하다(코스트도 폐지). 현재는 현행 `LockSpawners(species)` 결과와 같다. 안 비교 표와 D-5 는 작성 당시 기록이다.

현행 `StageRuleContext.LockSpawners(species)` 는 그 종을 출력하는 **모든** 스포너를 봉인한다. 편성이 생기면 두 문제가 생긴다 - 봉인 종을 0곳 넣으면 규칙이 아무것도 안 하고(규칙 회피 = 스테이지 고정 결정 위반), 3곳 넣으면 3곳이 한꺼번에 봉인된다.

| 안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| A. 현행 유지(그 종 전부) | 코드 변경 0 | 0곳이면 규칙 무효, 3곳이면 과벌. 봉인 종을 빼는 것이 항상 정답이라 "결정" 이 아니라 "회피" | 기각 |
| B. 봉인 종 편성 강제 | 봉인 스테이지는 그 종 최소 1곳 필수 | 회피는 막지만 편성 자유가 줄고 무효 편성 사유가 하나 늘어 UX 가 복잡 | 기각 |
| **C. 정확히 1곳 봉인 + 대체 규칙 (권장)** | 봉인 종을 출력하는 둥지 중 **슬롯 번호가 가장 작은 1곳**만 봉인. 그 종이 편성에 없으면 **코스트가 가장 높은 둥지 1곳**(동률이면 슬롯 번호가 가장 작은 곳)을 봉인. 해제 조건(`unlockHpFraction`)·해제 버스트는 현행 그대로 | 기본 편성(1종씩)에서는 결과가 현행과 동일. 회피 불가(항상 1곳 봉인) + 과벌 없음. 봉인 종을 넣을지 = "그 종 1곳을 잠깐 잃을지, 내 가장 비싼 둥지를 잠깐 잃을지" 라는 진짜 결정 | **채택(D-5)** |

- 편성 팝업은 SealedNest 스테이지에서 **봉인 예고 줄**을 실시간으로 보여 준다: "봉인 예정: 둥지 {n} ({종}) · 영웅 HP {p}% 에서 해제"(§7.3). 편성을 바꾸면 즉시 갱신.
- 전투 HUD 의 봉인 표시(`SealedNestInfo.UnlockHpPercent`, `BattleController` ~532 의 종별 해제 % 표시)는 **실제로 봉인된 둥지의 종** 기준으로 표시해야 한다(대체 규칙으로 봉인된 종이 `lockedSpecies` 와 다를 수 있음). 봉인 사슬 FX 는 1곳(현행 워밍 2개로 충분).
- 밸런스 영향: `chapter-system.md` §4.1 의 `ruleFactor`(예: 1-4 망령 봉인 1.065)는 "기본 편성에서 망령 비중 15.3%" 를 가정한다. 대체 규칙으로 사신(코스트 3)이 봉인되면 압력 감소 폭이 달라진다 → 게이트 F3(§9).

### 5.2 카드 - 후보 제외 (`Card_Species`)

> **(2026-11-01 개편 - §0.7)** 종족마다 몬스터가 1개뿐이라 6종이 항상 출력되어 이 절의 제외 규칙은 **항상 거짓(휴면 유지 확정)** 이다. 몬스터가 추가되어 고르지 않은 몬스터가 생기면 다시 작동한다. 아래 검산(최소 4장)은 종 일부를 뺄 수 있던 시절의 설계다.

| 안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| A. 제외 없음 | 편성에 없는 종의 카드도 나옴 | 3택1 중 1~2장이 "아무 효과 없는 카드" 가 되어 선택이 망가진다(예: 망령 0곳인데 망령 추가 소환) | 기각 |
| B. 판 시작 시 편성 기준 제외 | 편성 종만 보고 1회 결정 | (작성 당시 기각 사유: 판 중 교체 카드로 새 종이 생겨도 그 종 카드가 안 나옴. **2026-11-01 정정**: 판 중 출력 종을 바꾸는 카드가 없어 이 사유는 성립하지 않으며, 현행 데이터에서 B 와 C 의 결과는 같다) | 기각 (C 가 판 중 출력 종 변화가 생겨도 그대로 맞으므로 C 유지) |
| **C. 드로우 시점의 현재 출력 종 기준 제외 (권장)** | 카드를 뽑을 때마다 `Card_Species` 행이 있는 카드는 "행의 종 중 하나라도 지금 출력 중인 스포너가 있으면" 후보, 아니면 제외. 행이 없는 카드는 항상 후보 | 기본 편성은 6종이 판 끝까지 출력 중이라 제외 0 → 현행과 동일. 편성에서 뺀 종을 대상으로 하는 카드만 빠진다. 두 종을 함께 강화하는 카드(수호자의 분노·공포의 군세·처형 명령)는 두 종 중 하나라도 출력 중이면 후보 | **채택(D-7)** |

- 구현 위치: 기존 `CardDeck.Draw(n, isExcluded)` 의 제외 조건(현재 `_pickCounter.IsCapped`)에 "종 부재" 조건을 OR 로 더한다. 실제 드로우(~1765)와 시뮬 드로우(~1748) 두 곳 모두.
- 봉인된 둥지도 출력 종은 그대로라 그 종 카드는 후보에 남는다.
- **이미 고른 카드의 효과는 바꾸지 않는다.** `spawner-status-ui.md` §2.3.6 의 retroactive 정책(강화 카드는 종 전역 배율 `_typeModifiers` 라 나중에 그 종 스포너가 생기면 적용, 추가 카드 픽 기록은 출력 0대여도 누적)은 그대로다. 이번 규칙은 "무엇을 제시하느냐" 만 바꾼다. 결과적으로 "도깨비불은 있고 망령은 없는" 편성에서는 망령 전용 강화 카드(망령의 압박·더 많은 망령)가 판 내내 나오지 않는다 - 수용(편성의 의도된 대가).
- **후보 부족 검산 (2026-11-01 18행 기준 재계산)**: 종 의존 패시브 수(두 종 카드는 양쪽에 셈) = 도깨비불 3(WispHpBoost·SpawnWisps·공포의 군세) · 망령 3(WraithDamageBoost·SpawnWraith·공포의 군세) · 사신 3(ReaperAtkSpeed·SpawnReapers·처형 명령) · 저주술사 2(HexRangeBoost·처형 명령) · 역병귀 2(SpawnPlagues·PlagueSlowBoost) · 환령 2(PhantomMoveSpeedBoost·SpawnPhantoms). 무의존 패시브 3(LingeringCurse·HeroAttackDown·SpawnerHaste). 최악은 의존 패시브가 겹치지 않고 가장 적은 두 종만 남기는 편성(해금 단계 2, 종 2개 x 3곳) - {저주술사·역병귀·환령} 중 두 종(예: 저주술사 3 + 역병귀 3, 코스트 6+3 = 9 ≤ 13). 남는 패시브 = 의존 2 + 2 + 무의존 3 = **7장**(제외 9장). 패시브 픽 최대 9회, 카드당 3픽 캡이라 캡에 걸리는 카드는 최대 floor(9/3) = 3장 → 남은 후보 최소 7 - 3 = **4장**. 3택1 이 항상 성립한다. 액티브는 빠른 번식(환령)·수호자의 분노(도깨비불·망령) 최대 2장만 빠져 10장 이상. (이전 16행 기준 값은 남는 패시브 6장 · 최소 3장이었다.)
- **시너지 Tier**: 축 카운트·Tier 발화 규칙은 그대로다. Tier 효과가 편성에 없는 종을 대상으로 하면(예: Tank T1 "도깨비불·망령 HP x1.3" 인데 둘 다 0곳) 효과는 종 전역 배율로 기록되어 나중에 그 종이 생기면 적용된다(현행 retroactive). 해당 축 카드 상당수가 제외되므로 그 축 Tier 에 닿는 빈도 자체가 줄어든다 - 이것이 P3(빌드 축 사전 결정)의 의도다.

### 5.3 카드 - 추가 소환 대상 (`Spawn*` 5장)

> **(2026-11-01 폐지 - §0A.1)** 모든 종이 정확히 1곳이라 "그 종 둥지 전부 +1" 은 "그 둥지 +1" 이고 현행 게임과 동일하다. 아래 안 비교·×3 검산·예비안 B·F5 는 **폐지**(D-6, R9 폐지). 카드 설명 변경 없음.

현행 `IncrementSpawnerOutput(type)` 은 그 종을 출력하는 **모든** 스포너 출력을 +1 한다. 사신 3곳 편성에서 `SpawnReapers` 를 3번 고르면 스포너 3곳 x 출력 4 = 주기당 사신 12마리(기본 편성은 4마리)로 3배가 된다.

| 안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| **A. 현행 유지 (권장)** | 그 종 둥지 전부 +1 | 카드 의미·설명·기본 편성 결과가 전부 그대로다. (작성 당시 근거 "오늘의 게임도 교체 카드로 같은 종 2곳이 생겨 x2 가 이미 허용된다" 는 **2026-11-01 정정** - 종 교체 카드가 없어 같은 종 2곳의 x2 는 편성으로 처음 생긴다.) 종당 2곳의 x2 · 종당 3곳(해금 단계 2)의 x3 모두 게이트 F5 로 판정한다 | **채택(D-6)** |
| B. 1곳에만 +1 | 출력 수가 가장 적은 1곳(동률이면 슬롯 번호 최소)에 +1 | 몰빵 폭주는 막지만 카드 설명 5장을 고쳐야 하고, 집중 편성의 보상이 줄어든다 | 예비안 - F5 에서 종당 2·3 + 추가 소환이 과강하면 그때 B 로 전환(전환 대신 종당 최대를 2 로 고정하는 안과의 선택은 F5 결과 보고 시 사용자 선택 필요) |

- 강화 카드(종 전역 배율)는 바꾸지 않는다 - 종을 많이 넣을수록 강화 카드가 더 가치 있는 것은 집중 편성의 정당한 보상이다(선형).
- x3 상한 검산(해금 단계 2, 사신 3곳 + `SpawnReapers` 3회 픽): 둥지당 출력 1+3 = 4, 3곳 x 4 = 주기당 12마리. 기본 편성 + 같은 3픽 = 1곳 x 4 = 4마리. 사신 3곳은 코스트 9 라 나머지 3곳은 합 4 이하(저주술사 2 + 역병귀 1 + 환령 1)로만 채울 수 있어 탱커가 0 이 된다 - 이 대가가 x3 을 상쇄하는지가 F5 의 판정 대상.
- 「공포의 군세」(`ReplaceWispsToWraith`, 도깨비불·망령 데미지 +30%)·「처형 명령」(`ReplaceReapersToHex`, 사신·저주술사 데미지 +30%)은 종 전역 배율 강화 카드라 둥지 수와 무관하다(강화 카드와 같은 선형 보상). 2026-11-01 정정: 작성 당시 "그 종 전부를 바꾸는 교체 카드" 로 서술했으나 2026-06-01 부터 종을 바꾸지 않는다.
- `Multiply`(빠른 번식, 환령 스포너 주기 x0.6)는 환령 전부에 적용(현행 유지). 환령은 코스트 1·가치 최저라 환령 3곳 + 빠른 번식의 압력은 게이트 F5 에서 확인.
- Swarm T3(모든 스포너 출력 +1)·SpawnerHaste(모든 주기)는 편성과 무관(변경 없음).

### 5.4 상점 (`Enhance_<종>` 체급 - 2026-10-29 표시명 "각성" → "체급")

- 상점 수치·가격 변경 없음. 체급 레벨은 종 전역 배율이라 편성에 그 종이 많을수록 효과가 커진다.
- (2026-11-01) 6종이 모두 쓰이므로 체급·각성·둥지·특성 투자는 항상 회수된다 - R4 소멸.
- 편성 팝업 종 팔레트에 "체급 Lv n"(문구 1400, 2026-10-29 `각성 Lv {0}` → `체급 Lv {0}`)을 보여 준다(P4). 상점 레벨을 읽기만 한다. 이하 본문의 "각성 Lv" 표기(§7.3 팔레트 행, F+7)는 현행 "체급 Lv" 로 읽는다. 새 "각성"(각성석 축)은 `monster-growth-currencies.md` §3.2.
- 위험: 편성에 거의 안 쓰는 종에 투자한 소울은 회수가 줄어든다(R4). 환급은 하지 않는다(소울 경제 개입 금지 - `relics.md` D-3 와 같은 원칙).

### 5.5 유물 · 난이도

- **유물**: 전부 종 전역(모든 몬스터 배율·모든 스포너 주기·영웅 오라)이라 편성과 독립. `AmbushHorn`(전투 시작 도깨비불 소환)·`SpawnPrelude`(모든 스포너 첫 스폰 단축)는 편성과 무관하게 동작(변경 없음). 유물 드랍 확률·테이블에 편성 조건 없음.
- **난이도**: 독립. 난이도는 영웅 배율만, 편성은 몬스터 출발 상태만 바꾼다. 같은 편성 상한이 모든 난이도에 적용(Hard 에 코스트 보너스 없음 - YAGNI).
- **기록·도감·도전과제**: 변경 없음.

### 5.6 랭킹 · 최단 기록

| 안 | 내용 | 판정 |
|---|---|---|
| **A. 편성 무관하게 기존 규칙 유지 (권장)** | Easy 판만 최단 기록·랭킹 대상(`difficulty-select.md` §1.6), 편성은 묻지 않는다 | **채택(D-9)**. 편성 최적화는 카드 픽과 같은 실력 요소이며 v0.3 가설의 "경쟁 동기" 를 강화한다. Firestore 문서 스키마·보안 규칙 변경 0 |
| B. 기본 편성 판만 랭킹 | 공정성은 높으나 편성을 쓰는 순간 랭킹을 포기하게 되어 기능을 벌한다 | 기각 |
| C. 랭킹 항목에 편성 저장·표시 | Firestore 문서 필드 추가 + 랭킹 UI 확장 → 이번 범위 밖(후속 제안 §11) | 기각 |

- 위험: 편성 도입 직후 최단 기록이 일제히 갱신되어 도입 전 기록이 밀린다(R6). 랭킹 초기화는 하지 않는다.

### 6.3 `EffectiveFormation` (전투 시작, 읽기 전용)

전투 시작 시 `EffectiveFormation` 을 계산해 그 판 전체에 쓴다(판 도중 다시 읽지 않음). 프로필을 수정하지 않는다(`EffectiveDifficulty` 선례).

```
편성 데이터 로드 실패            → 씬 인스펙터 _outputType (현행)
편성 잠김 (ClearedStage < 1)     → 기본 편성
Formation 0행                    → 기본 편성
Formation 6행 + FormationRules 유효 (모든 슬롯의 몬스터가 그 슬롯 종족 소속, §0.3) → 저장 편성
Formation 6행 + 무효             → 기본 편성 + 경고 로그 (팝업이 1차 가드라 정상 경로로는 도달하지 않음)
```

### 6.4 전투 적용 순서 (`BattleController` 시작 시퀀스)

`Spawner.OnEnable` 이 `_currentType` 을 인스펙터 값으로 초기화하고, 이후 `BindSpawners`(주기 대입)·`SetupStageRules`(봉인)·`ApplyFirstSpawnDelays`(종별 이동·사거리)·제단 틴트가 모두 `CurrentType` 을 읽는다. 따라서 편성 적용은 **이들보다 먼저**여야 한다.

```
SpawnHero
→ [신규] 편성 적용: 슬롯 i 의 스포너 출력 종 = EffectiveFormation[i]   (기존 Spawner.ReplaceOutput 재사용 - OnOutputTypeChanged 로 제단 틴트 갱신, 신규 Spawner API 불필요)
→ BindSpawners (종별 base 주기 대입, VM AttachSpawners)
→ SetupStageRules (봉인 1곳 규칙 §5.1)
→ ApplyMetaBonuses → ApplyRelicBonuses → ApplyFirstSpawnDelays → ApplyRelicSpawnPrelude   (현행 순서 그대로)
```

- 풀 워밍(`PrewarmPools` ~1962): 종별 워밍 수를 "현행 수 x 그 종 편성 곳 수(최소 1)" 로 맞춘다(2026-11-01: 모든 종 1곳이라 현행 수 그대로 - 사실상 변경 없음. 작성 당시 예: 사신 3곳이면 사신 풀 3배). 편성에 없는 종도 현행 수는 유지(작성 당시 근거 "교체 카드로 생길 수 있음" 은 2026-11-01 정정 - 종 교체 카드가 없어 판 중 새 종은 생기지 않는다. 워밍 수 유지는 풀 비용이 작아 그대로 둔다).
- 스포너 상태 UI(빌드 패널·모달)는 `CurrentType` 을 읽으므로 자동 반영.

### 10.1 무한 탑 (`infinite-tower.md`, 별도 진행 중)

- **가정**: 탑 층 출격 전에도 같은 `EUI.FormationPopup` 을 재사용한다. 요약 패널의 내용(층 정보·규칙)만 탑이 채운다. 편성 저장은 공용 `MetaProfile.Formation` 1개를 쓴다고 가정하며, 탑 전용 별도 편성이 필요하면 탑 기획서가 별도 세이브 필드를 정의한다.
- **훅**: `FormationRules` 가 상한·종당 최대를 인자로 받으므로 탑이 층마다 다른 상한(예: 층이 오를수록 상한 증가)을 넘길 수 있다. 이번 구현은 그 기능을 만들지 않는다.

### 10.2 데일리 (`daily-challenge.md`, 별도 진행 중)

- **가정**: 데일리 랭킹 공정성을 위해 데일리가 편성을 **지정**(고정 편성)하거나 상한을 지정할 수 있다. `FormationRules`·`EffectiveFormation` 은 "외부가 넘긴 고정 편성" 을 받으면 저장 편성 대신 그것을 쓰는 입력 자리를 둔다(이번에는 호출자 없음). 팝업의 "읽기 전용 표시" 모드는 데일리 기획에서 필요할 때 추가한다.
