## § 헤더

- **목표**: 로딩·마을·배틀 세 씬의 3D 바닥·벽(Ground/Wall_*, Floor/MapBackground)과 3D 조명을 **시안 코드로 그린 PPU 48 도트 배경 + URP 2D Renderer 의 2D Light(계단식 디더 양자화)** 로 교체하고, 배틀 HUD 를 시안 3번 섹션 배치(보스 바 · 좌 타이머 · 우 액티브 카드 카운트다운 · 하단 스포너 행 · 오른쪽 시너지/빌드 열)로 재배치한다. **게임플레이·밸런스 수치 변경 0.**
- **검증 가설**: (a) 영웅·몬스터가 도트가 된 뒤 배경까지 같은 도트 밀도·같은 조명 문법으로 통일되면 "던전 주인의 둥지"라는 무대감이 살아나 재방문 첫인상(로딩·마을)이 강화되는가. (b) 현행의 넓은 배틀 시야를 유지한 채 HUD 가 가장자리로 물러나 가운데가 비면 "전장이 좁다"는 인상이 해소되고, 스포너 칸 게이지 색 = 종족 발광색으로 몬스터 강화 발광과 색이 이어져 "어느 종족이 싸우는지"가 읽히는가(컨셉 §5.2 시너지 가시성). (c) 액티브 카드까지 남은 시간과 패시브 눈금(HP 10% 구간)이 보스 바 옆에 보이면 컨셉 §4 트리거 페이싱이 예측 가능해지는가.
- **현재 단계 범위 적합성**: **범위 내**. CLAUDE.md §8 "아트/에셋 작업 허용 — 실제 스프라이트·모델 등 에셋으로 교체 가능". 마을 허브는 v0.2 승격분(§8 "메타 진행 허용"). 신규 메인 메뉴·세팅 화면 없음(마을 허브가 계속 시작 화면), 신규 사운드 없음, 서버 연동 무관. 게임플레이 수치(스포너 위치·영웅 구역·스폰 규칙·스탯) 변경 없음 → qa-simulator 불필요.
- **핵심 메커니즘**: 세 씬 모두 **"도트 무대(DotStage)" 규약** 하나로 통일한다 — 직교 카메라 + 카메라 정면을 향한 배경 평면(배경 1도트 = 월드 1/48u, PPU 48) + 지면(XZ) 위 캐릭터는 기존 빌보드 그대로. 배틀 카메라는 현행 값(직교 size 7, 피치 50°) 그대로 쓰고 배경을 그 화면 범위에 맞춰 그린다. 조명은 2D Global Light(시안 `ambient`) + 타원 감쇠 쿠키를 쓰는 Sprite Light 2D(시안 `lights()` 의 `(1−d)²·i` 그대로) 를 라이트 텍스처에 누적하고, 모든 lit 스프라이트 셰이더가 **도트 중심에서 1회 샘플한 빛을 6단계 + 4×4 Bayer 디더로 양자화**해 곱한다(시안 `applyLight` 의 `Q=6`·`BAYER` 재현). 발광 레이어(불꽃·링·결정)는 조명 뒤에 가산으로 얹는다(시안 `emissive` 단계 재현). HUD 는 1280×720 캔버스에 시안 960×540 좌표를 ×4/3 으로 옮기고, 신규 위젯 2개(액티브 카운트다운, 보스 바 패시브 눈금)는 ViewModel 이벤트 2개로 구동한다.

### 0.4 결정 반영 중 드러난 사실 (사용자 보고 필수)

| # | 사실 | 결과 |
|---|---|---|
| **F1** | 배틀 카메라는 **이미 직교**(size 7, 피치 50°)다. 원근은 마을·로딩 카메라뿐이다. | 배틀 카메라 값은 그대로 둔다. 실제 변경 = 배경을 누운 쿼드에서 **카메라 정면 평면**으로 옮기기. 피치 50° 직교에서 누운 도트 바닥은 세로가 sin50° = 0.766 배로 눌려 도트가 가로로 긴 직사각형이 된다 — 정면 평면이면 정사각 도트. |
| **F2** | 시안 배틀 캔버스 640×360 도트 @ PPU 48 = 화면 세로 7.5u 인데 현행 화면 세로는 2×7 = 14u 다. | 현행 시야 유지 결정(Q1) → 배경 캔버스를 현행 화면 크기로 **다시 그린다**: 세로 14×48 = 672, 가로 14×(16/9)×48 = 1194.67 도트 + 흔들림 여백 → **1228×704**(§1.2·§2.4). 캐릭터 화면 크기는 현행 그대로. |
| **F3** | 스포너 반지름 20u 는 화면 가로 반폭 7×16/9 = 12.44u 밖이다(현행과 같음). | 스포너 위치를 바꾸지 않으므로 **전장 제단 소품은 두지 않는다**(§3.2 — 결정과 사유). |

## 1. 공통 규약 — 도트 무대(DotStage)

### 1.1 방식 — 직교 카메라 + 카메라 정면 배경 평면 + 지면 위 빌보드

| 안 | 내용 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **A. 피치 직교 + 카메라 정면 배경 평면(DotStage) + 지면(XZ) 빌보드** | 게임플레이는 지금처럼 XZ 평면. 카메라는 피치 θ 직교. 배경·조명·발광 장식은 카메라와 같은 회전을 가진 평면(`@DotStage`) 위에 놓아 배경 1도트 = 화면 1도트. 캐릭터는 기존 빌보드 그대로 | 이동·판정·AI·스폰·BattleZone 코드 변경 0. 배경 도트가 정사각. 지면 데칼(그림자·강화 문장·지면 FX)은 sinθ 로 눌려 그림 속 원근과 같은 비율이 된다. 캐릭터 깊이 정렬 = 월드 Z | 배경 평면과 지면 좌표를 잇는 매핑 식이 필요(§1.2, 순수 함수로 테스트) | ✅ 채택 |
| B. 피치 90°(수직 탑다운) + 누운 배경 | 지면 1:1 | 시안의 3/4 원근 그림(투기장 타원·절벽)과 게임 지면이 어긋남. 빌보드 캐릭터가 위에서 눌려 보임 | ✗ |
| C. 피치 0°(정면) + 게임플레이 XY 평면 이관 | 순수 2D 씬 | 이동·판정·BattleZone·스포너·영웅 AI 전부 XZ→XY 재작성 — 이번 작업이 게임플레이 코드를 흔든다 | ✗ (배틀). 로딩은 게임플레이가 없어 C 사용(§6) |

- **배틀 θ = 50°(현행 유지)**. 피치를 바꾸면 월드 Y 로 띄운 HP 바·팝업·FX 높이를 전부 다시 환산해야 하고(F5), 화면에 보이는 지면 깊이(14÷sin θ)도 바뀐다. 그림 쪽이 50° 에 맞추면 된다 — 투기장은 월드에서 원이 아니라 **가로 13u × 세로 7u 타원형**(게임플레이와 무관한 그림)으로 두어, 화면상 세로/가로 비 = (7×36.770)÷(13×48) = 257.4÷624 = 0.41 이 되어 시안 투기장 비율 148÷336 = 0.44 와 같은 3/4 인상을 유지한다(§3.1). 지면 데칼(그림자·강화 문장·지면 FX)의 눌림 0.766 은 현행 그대로.
- 마을은 투영진 링 10÷38 = 0.263, 그림자 타원 1÷3.5 = 0.286 사이 → **마을 θ = 16°**(sin16° = 0.2756). 마을은 게임플레이가 없어 피치 선택이 자유롭다.
- 배경 평면은 카메라 정면을 향하므로 직교 투영에서 깊이와 무관하게 1:1 로 찍힌다. 깊이는 "모든 배우보다 뒤"이기만 하면 된다(정렬은 §1.3 레이어로 보장).

### 1.5 조명 — 시안 `applyLight` 재현 방식

시안 식(도트마다): `LM = ambient + Σ c·i·(1−d)²` (d = 타원 정규 거리, 가로 반경 r · 세로 반경 r·sq), `q = floor(LM·6 + BAYER[(y&3)·4+(x&3)]) / 6`, 최종 = base × q, 그 뒤 발광을 가산.

| 단계 | 유니티 구현 결정 |
|---|---|
| ambient | 씬마다 **Global Light 2D** 1개, 색 = 시안 `ambient`, intensity 1, 대상 레이어 Backdrop·Default |
| 점 조명 | **Sprite Light 2D** + 쿠키 스프라이트 `Light2D_Falloff`(128×128, RGB = (1−d)², A = 1, d = 중심 거리/64, Bilinear, sRGB off, 무압축). 색 = 시안 `c`, intensity = 시안 `i`(깜빡임은 `DotLightFlicker`, §7.3), **Transform 스케일 = (2r/48, 2r·sq/48, 1)** — 쿠키가 1u 원에 맞도록 쿠키 스프라이트 PPU = 128. 모든 조명은 `@DotStage`(배틀·마을·로딩) 자식이거나 영웅 빌보드 자식이라 카메라 정면을 향한다 → 화면에서 시안과 같은 타원 |
| 누적 | 라이트 텍스처가 ambient + Σ 를 가산 누적(HDR Emulation Scale 2 까지) — 시안 `LM` 과 같은 값 |
| 양자화 | 공용 셰이더 서브그래프 `DotLightQuantize`: 라이트 텍스처를 **해당 프래그먼트가 속한 도트의 중심**에서 1회 샘플 → 채널별 `floor(L·6 + b)/6`, b = Bayer 4×4 `[0,8,2,10,12,4,14,6,3,11,1,9,15,7,13,5]` 의 (index+0.5)/16, 인덱스 = (dotY mod 4)·4 + (dotX mod 4). **도트 좌표 = 뷰 공간 위치 × 48** 에 씬별 원점 오프셋(= 화면 중앙의 배경 도트: 배틀 (614,352), 마을·로딩 (240,135))을 더해 floor(뷰 y 는 부호 반전 — 화면 아래가 +). 뷰 공간 기준이라 레터박스 뷰포트·해상도와 무관하게 격자가 배경 도트와 겹친다 |
| 전역 파라미터 | 씬 컴포넌트 `DotLightingSettings`(§7.6)가 `Shader.SetGlobalVector("_DotGridOrigin", …)` 로 원점 오프셋을 1회 설정. 단계 수 6·PPU 48 은 서브그래프 상수 |
| 도트 안 균일성 | 필수 요건: 한 도트 안에서 빛이 갈라지지 않는다(도트 중심 1회 샘플). 구현 방법(스냅된 뷰 위치 → 화면 UV 변환 후 샘플)은 gameplay-programmer 판단. 검증 = §11 G3 |

### 1.8 배틀 카메라 유지에 따른 화면 높이 — 보정 없음

배틀 피치(50°)·size(7)를 바꾸지 않으므로 월드 Y 로 띄운 요소의 화면 높이(h·cos50° = 0.643h)와 지면 데칼 눌림(sin50° = 0.766)이 **현행과 같다**. 이번 작업에서 높이 보정은 하지 않는다.

| 대상 | 이번 작업 |
|---|---|
| 몬스터 HP 바 `SetHeightAboveRoot`(월드 Y) | 변경 없음. 기획서 수치(화면 높이 의도)와 월드 Y 구현의 차이로 HP 바가 스프라이트 위쪽에 겹치는 **기존 문제**는 별도 후속(§12) |
| `DamagePopup` 부상(월드 Y 1.2) | 변경 없음 |
| `FearSkull`(0,2.1,0) · `TimeStopShield`(+0.5) | 변경 없음 |
| 지면 FX·강화 문장·`AuraShadow`·`Aura` | 변경 없음(눌림 0.766). 배경 투기장은 이 비율을 전제로 그리지 않고 타원형 그림으로 3/4 인상을 낸다(§1.1) |
| `HeroTargetProvider`·`MonsterVisual2D`·`SpriteSheetFx` 빌보드 | 변경 없음 |

### 2.2 추출 절차

1. 시안 원본(`scene-2d-atmosphere.src.html`)에 **추출 패널**(버튼 1개 "Backdrop2D 추출")을 추가한다. 각 대상은 새 캔버스(대상 크기, 1× 도트)에 시안과 **같은 함수·같은 시드**(`seed` 11/23/41)로 그린 뒤 `toBlob('image/png')` → `POST /export/<파일명>`.
   - 배경(마을·로딩): 각 씬 `build(b, mulberry32(seed))` 결과 `base` 캔버스를 그대로 내보낸다(이미 조명 전 레이어).
   - 배경(배틀): 시안의 `BScene.build` 를 **광각 파라미터 표(§3.1.1)** 로 호출하는 `buildBattleWide` 로 1228×704 캔버스에 그린다 — 크기·투기장 중심/반경·동심원 수·장식 개수·벽 기둥 x·화로 위치만 바꾸고 팔레트·그리기 함수·시드(41)는 시안 그대로. **제단 블록은 그리지 않는다**(§3.2). 같은 함수로 시안 페이지에 "3′. 배틀 광각판" 섹션(1228×704 를 화면 폭에 맞춰 축소 표시 + 새 HUD 오버레이)을 추가해 사용자 재확인(G1)에 쓴다.
   - 애니 시트: 해당 함수(`flame`, 거품, 스캔라인)를 t = i/12(i = 0…N−1)로 호출해 가로 스트립으로 이어 붙인다.
   - 흰색 틴트용 스프라이트(축 고리)는 해당 도형을 `#ffffff` 로 그린다.
2. `server.js` 에 세 번째 화이트리스트 `BACKDROP_NAMES`(§2.4 파일명 전부 + `Backdrop2D_SheetSpec.json`)와 저장 폴더 `Assets/_Lair/Art/Sprites/Backdrop2D/` 를 추가한다. UI 스프라이트 4장(§2.4 마지막 표)은 `Assets/_Lair/Art/Sprites/UiDot/` 로 저장하는 네 번째 화이트리스트 `UIDOT_NAMES`.
3. 추출 도구는 `Backdrop2D_SheetSpec.json` 에 파일별 {크기, 셀, 프레임 수, 피벗, 좌상단 도트} 를 기록한다 — 임포트 설정의 단일 진실(영웅 `Knight_SheetSpec.json` 선례). 아래 §2.4 의 크기·피벗은 시안 코드에서 계산한 기대값이며 추출값과 1도트라도 다르면 추출값이 맞는지 시안 코드로 재검산한다.
4. 메인이 `node .mockups/server.js` 로 서버를 띄우고 사용자가 버튼을 눌러 저장 → `[asset]` 커밋.

### 3.4 HUD 가 비워 두는 전장 (도트)

HUD 좌표(§4.2, 1280×720 캔버스)를 배경 도트로 환산: 도트 = 여백 + 캔버스값 × (672÷720 = 0.93333), 여백 = 가로 16.67 · 세로 16.

#### 4.3.1 피해 잔상(Lag)

- `SetHp` 가 불릴 때마다 잔상 시작값 = 현재 잔상, 목표 = 새 비율, 경과 0. 매 프레임 잔상 = 시작 + (목표 − 시작) × min(1, 경과 ÷ **0.7s**)(시안 CSS `transition: width .7s linear`).
- 목표가 현재 잔상보다 크면(회복) 잔상을 즉시 목표로 맞춘다(채움 뒤에 가려져 의미 없음).
- 경과는 `Time.unscaledDeltaTime` — 카드 선택 일시정지 중에도 잔상이 마저 줄어 다음 화면에서 남은 잔상이 없게 한다.

| 자식 | 배치(1280, 부모 좌상단) | 내용 |
|---|---|---|
| 배경 | 전체 | `Px_PanelDark` |

| `Value` | (0,−27) 115×30 가운데 | CHText 24 #F7C64A — `m:ss`(남은 초 올림), 다음 임계 없으면 `—` |
| `MiniBar` | 좌우 여백 12, 아래 11, 높이 5 | 트랙 #0C1017, 채움 #F7C64A, Filled Horizontal |

**계산(순수 함수 `ComputeActiveCountdown(thresholds, elapsed)`)**: next = elapsed 보다 **큰** 첫 임계, prev = elapsed 이하의 마지막 임계(없으면 0). 남은 초 = next − elapsed, 진행 = (elapsed − prev) ÷ (next − prev). next 없음 → `HasNext = false`, 표시 `—`, 진행 0.

| elapsed | next | prev | 남은 초 | 표시 | 진행 |
|---|---|---|---|---|---|
| 0 | 30 | 0 | 30 | 0:30 | 0.000 |
| 29.5 | 30 | 0 | 0.5 | 0:01 | 0.983 |
| 30.0 | 90 | 30 | 60 | **1:00** | 0.000 |
| 60 | 90 | 30 | 30 | 0:30 | 0.500 |
| 269.9 | 270 | 210 | 0.1 | 0:01 | 0.998 |
| 270 | 없음 | 270 | — | — | 0 |

- 시안 코드는 `0:${ceil(r)}` 라 60초 구간에서 "0:60" 이 나온다 — **m:ss 로 정정**(타이머와 같은 올림 규칙: `HandleTimer` 의 `CeilToInt`).
- 임계 30s 를 넘는 순간 카드 선택 팝업이 뜨고 시계가 멈추므로 1:00 은 팝업 뒤에서 대기한다.

## 7. 신규 런타임 컴포넌트 행동 명세

코드 구조·클래스 배치는 gameplay-programmer 판단. 아래는 동작과 테스트 가능한 순수 함수 계약만 정한다.

### 7.1 `DotStageMapping` (정적 순수)
- §1.2 표의 세 씬 식을 제공: `BattleGroundToDot(Vector3 world)`, `BattleDotToGround(Vector2 dot)`, `VillageGroundToDot`, `VillageDotToGround`, `StageLocalFromDot(Vector2 dot, Vector2 screenCenterDot)`(= ((dx−cx)/48, (cy−dy)/48)).
- 상수: PPU 48, 배틀 θ 50°·기준 = 주시점 (0,0,−1.60904) ↔ 배경 도트 (614,352)·화면 중앙 (614,352), 마을 θ 16°·기준 (240,221)·화면 중앙 (240,135).

### 7.2 `DotOrbitRing`
- 정적 자식 N개(프리팹·씬에 고정 배치, 동적 생성 금지)를 매 프레임 배치. i 번째 도트 오프셋 = (floor(cos a·rx + 0.5), floor(sin a·ry + 0.5)) 도트, a = 위상 + ω·t + i·2π/N, 화면 아래 = +y → 로컬 y 부호 반전 후 ÷48.
- 직렬화: 개수 N(= 자식 수), rx, ry(도트), ω(rad/s), 위상(rad), 색.
- 순수 함수: `DotOffset(int i, int count, float t, float omega, float phase, float rx, float ry)` → Vector2Int.

### 7.3 `DotWave` · `DotAlphaPulse` · `DotLightFlicker`
- `DotWave.Evaluate(float baseValue, float[] amps, float[] omegas, float[] phases, float t)` = base + Σ amp_k·sin(ω_k·t + φ_k).
- `DotAlphaPulse`: SpriteRenderer 알파 = clamp01(Evaluate). `DotLightFlicker`: Light2D intensity = max(0, Evaluate). 시간 = `Time.time`(일시정지 시 멈춤 — 카드 선택 중 조명도 정지).
