## § 헤더

- **목표**: 로딩·마을·배틀 세 씬의 3D 바닥·벽(Ground/Wall_*, Floor/MapBackground)과 3D 조명을 **시안에서 추출한 PPU 48 도트 배경 + URP 2D Renderer 의 2D Light(계단식 디더 양자화)** 로 교체하고, 배틀 HUD 를 시안 3번 섹션 배치(보스 바 · 좌 타이머 · 우 액티브 카드 카운트다운 · 하단 스포너 행 · 오른쪽 시너지/빌드 열)로 재배치한다.
- **검증 가설**: (a) 영웅·몬스터가 도트가 된 뒤 배경까지 같은 도트 밀도·같은 조명 문법으로 통일되면 "던전 주인의 둥지"라는 무대감이 살아나 재방문 첫인상(로딩·마을)이 강화되는가. (b) 배틀에서 스포너 제단이 화면 안에 보이고(종족 발광색 = HUD 스포너 칸 게이지 색) HUD 가 가장자리로 물러나면, 플레이어가 "어느 제단에서 무엇이 나와 싸우는지"를 전장에서 직접 읽는가(컨셉 §5.2 시너지 가시성). (c) 액티브 카드까지 남은 시간과 패시브 눈금(HP 10% 구간)이 보스 바 옆에 보이면 컨셉 §4 트리거 페이싱이 예측 가능해지는가.
- **현재 단계 범위 적합성**: **범위 내**. CLAUDE.md §8 "아트/에셋 작업 허용 — 실제 스프라이트·모델 등 에셋으로 교체 가능". 마을 허브는 v0.2 승격분(§8 "메타 진행 허용"). 신규 메인 메뉴·세팅 화면 없음(마을 허브가 계속 시작 화면), 신규 사운드 없음, 서버 연동 무관. 단 §4.5 의 **스포너 반지름·영웅 구역 축소는 게임플레이 수치 변경**이라 qa-simulator 게이트(§12.2)를 통과해야만 병합한다 — 사용자 선택 필요 항목 **Q1**(§14).
- **핵심 메커니즘**: 세 씬 모두 **"도트 무대(DotStage)" 규약** 하나로 통일한다 — 직교 카메라 + 카메라 정면을 향한 배경 평면(배경 1도트 = 화면 1도트, PPU 48) + 지면(XZ) 위 캐릭터는 기존 빌보드 그대로. 조명은 2D Global Light(시안 `ambient`) + 타원 감쇠 쿠키를 쓰는 Sprite Light 2D(시안 `lights()` 의 `(1−d)²·i` 그대로) 를 라이트 텍스처에 누적하고, 모든 lit 스프라이트 셰이더가 **도트 중심에서 1회 샘플한 빛을 6단계 + 4×4 Bayer 디더로 양자화**해 곱한다(시안 `applyLight` 의 `Q=6`·`BAYER` 재현). 발광 레이어(불꽃·링·결정)는 조명 뒤에 가산으로 얹는다(시안 `emissive` 단계 재현). HUD 는 1280×720 캔버스에 시안 960×540 좌표를 ×4/3 으로 옮기고, 신규 위젯 2개(액티브 카운트다운, 보스 바 패시브 눈금)는 ViewModel 이벤트 2개로 구동한다.

### 0.4 결정 반영 중 드러난 사실 (사용자 보고 필수)

| # | 사실 | 결과 |
|---|---|---|
| **F1** | 배틀 카메라는 **이미 직교**(size 7, 피치 50°)다. 원근은 마을·로딩 카메라뿐이다. | D1 의 배틀 쪽 실제 변경 = 피치 50°→28°(§1.2) + size 7→3.75 + 배경을 누운 쿼드에서 **카메라 정면 평면**으로 옮기기. 피치 50° 직교에서 누운 도트 바닥은 세로가 sin50° = 0.766 배로 눌려 도트가 가로로 긴 직사각형이 된다 — 정면 평면이면 정사각 도트. |
| **F2** | 시안 640×360 도트 @ PPU 48 = 화면 세로 360÷48 = **7.5u**. 현행 게임 화면 세로는 2×7 = **14u**. | D4 를 그대로 반영하면 캐릭터가 화면에서 14÷7.5 = **1.867배 크게** 보인다(시안 문구의 "1.33배 줌아웃"은 **이전 시안 480×270 대비**이고, 현행 게임 대비로는 확대다). 결정대로 반영하되 사용자가 인지해야 한다. |
| **F3** | 스포너 반지름 20u 는 새 화면 가로 반폭 640÷2÷48 = 6.667u 밖이다. 시안 제단은 반지름 204도트 = 4.25u 에 있다(`ALTAR`: 320+204·cos). 현행도 스포너는 "맵 밖"(size 7 화면 가로 반폭 12.4u < 20u). | 시안 구도(제단이 영웅 둘레에 보임)를 만들려면 **스포너 반지름 20→4.25u = 게임플레이 변경**. 이동 시간이 줄어 전투가 빨라지므로 이동 시간 보존 보정(§3.5.2)과 qa 게이트를 둔다 → **Q1**. |
| **F4** | 요청에 적힌 각도(Wisp 240° Reaper 180° Hex 120° Wraith 60° Plague 0° Phantom 300°)는 **시안 `ALTAR` 표 값**이고, 씬 실측은 Wisp 0° Reaper 60° Hex 120° Wraith 180° Plague 240° Phantom 300° 다. | 제단은 스포너 자식이라 어느 배치든 자동으로 따라간다. **씬 배치 유지**(HUD 칸 순서 = `_spawners` 순서도 유지)로 결정 — **Q3** 에서 시안 배치로 바꿀지 사용자 확인. |
| **F5** | 몬스터 HP 바·데미지 팝업·일부 FX 는 **월드 Y** 로 띄운다. 빌보드 스프라이트 높이는 화면 높이 그대로인데 월드 Y 높이 h 는 화면에 h·cos(피치)로 보인다(피치 50°: 0.643h). | 피치 28° 에서 cos28° = 0.883 → 같은 월드 Y 가 화면에서 0.883÷0.643 = 1.373배 높아진다. HP 바는 카메라 up 축으로 올리도록 바꾸고(기획서 수치 = 화면 높이라는 원래 의도 회복), FX 월드 Y 오프셋은 환산한다(§1.8). |
| **F6** | 몬스터 몸과 강화 오버레이는 같은 정렬 레이어의 order 0/+1 이라, **다른 몬스터의 오버레이가 앞 몬스터의 몸 위에** 그려질 수 있다(order 가 거리보다 먼저 비교됨). 현행에도 잠재. | 캐릭터 프리팹 루트에 `SortingGroup` 부착(§1.3). |
| **F7** | `BattleCamera` 휠 줌은 카메라를 forward 로 옮기는데, 직교에서는 화면 크기가 변하지 않아 **현행에도 무동작**이다. | 새 구도에서 줌은 쓰지 않는다 — `_minZoomDistance` = `_maxZoomDistance` = 20 으로 고정(§3.6). |

## 1. 공통 규약 — 도트 무대(DotStage)

### 1.1 방식 — 직교 카메라 + 카메라 정면 배경 평면 + 지면 위 빌보드

| 안 | 내용 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **A. 피치 직교 + 카메라 정면 배경 평면(DotStage) + 지면(XZ) 빌보드** | 게임플레이는 지금처럼 XZ 평면. 카메라는 피치 θ 직교. 배경·조명·발광 장식은 카메라와 같은 회전을 가진 평면(`@DotStage`) 위에 놓아 배경 1도트 = 화면 1도트. 캐릭터는 기존 빌보드 그대로 | 이동·판정·AI·스폰·BattleZone 코드 변경 0. 배경 도트가 정사각. 지면 데칼(그림자·강화 문장·지면 FX)은 sinθ 로 눌려 그림 속 원근과 같은 비율이 된다. 캐릭터 깊이 정렬 = 월드 Z | 배경 평면과 지면 좌표를 잇는 매핑 식이 필요(§1.2, 순수 함수로 테스트) | ✅ 채택 |
| B. 피치 90°(수직 탑다운) + 누운 배경 | 지면 1:1 | 시안의 3/4 원근 그림(투기장 타원·절벽)과 게임 지면이 어긋남. 빌보드 캐릭터가 위에서 눌려 보임 | ✗ |
| C. 피치 0°(정면) + 게임플레이 XY 평면 이관 | 순수 2D 씬 | 이동·판정·BattleZone·스포너·영웅 AI 전부 XZ→XY 재작성 — 이번 작업이 게임플레이 코드를 흔든다 | ✗ (배틀). 로딩은 게임플레이가 없어 C 사용(§6) |

- 피치 θ 는 **그림 속 지면 타원 비율**에 맞춘다: 시안 제단 링 `ALTAR` 세로/가로 = 96÷204 = 0.4706 → **배틀 θ = 28°**(sin28° = 0.4695, 제단 세로 반경 204×0.4695 = 95.8도트 ≈ 시안 96). 마을은 투영진 링 10÷38 = 0.263, 그림자 타원 1÷3.5 = 0.286 사이 → **마을 θ = 16°**(sin16° = 0.2756).
- 배경 평면은 카메라 정면을 향하므로 직교 투영에서 깊이와 무관하게 1:1 로 찍힌다. 깊이는 "모든 배우보다 뒤"이기만 하면 된다(정렬은 §1.3 레이어로 보장).

### 1.5 조명 — 시안 `applyLight` 재현 방식

시안 식(도트마다): `LM = ambient + Σ c·i·(1−d)²` (d = 타원 정규 거리, 가로 반경 r · 세로 반경 r·sq), `q = floor(LM·6 + BAYER[(y&3)·4+(x&3)]) / 6`, 최종 = base × q, 그 뒤 발광을 가산.

| 단계 | 유니티 구현 결정 |
|---|---|
| ambient | 씬마다 **Global Light 2D** 1개, 색 = 시안 `ambient`, intensity 1, 대상 레이어 Backdrop·Default |
| 점 조명 | **Sprite Light 2D** + 쿠키 스프라이트 `Light2D_Falloff`(128×128, RGB = (1−d)², A = 1, d = 중심 거리/64, Bilinear, sRGB off, 무압축). 색 = 시안 `c`, intensity = 시안 `i`(깜빡임은 `DotLightFlicker`, §7.3), **Transform 스케일 = (2r/48, 2r·sq/48, 1)** — 쿠키가 1u 원에 맞도록 쿠키 스프라이트 PPU = 128. 모든 조명은 `@DotStage`(배틀·마을·로딩) 또는 빌보드 부모(제단·영웅) 자식이라 카메라 정면을 향한다 → 화면에서 시안과 같은 타원 |
| 누적 | 라이트 텍스처가 ambient + Σ 를 가산 누적(HDR Emulation Scale 2 까지) — 시안 `LM` 과 같은 값 |
| 양자화 | 공용 셰이더 서브그래프 `DotLightQuantize`: 라이트 텍스처를 **해당 프래그먼트가 속한 도트의 중심**에서 1회 샘플 → 채널별 `floor(L·6 + b)/6`, b = Bayer 4×4 `[0,8,2,10,12,4,14,6,3,11,1,9,15,7,13,5]` 의 (index+0.5)/16, 인덱스 = (dotY mod 4)·4 + (dotX mod 4). **도트 좌표 = 뷰 공간 위치 × 48** 에 씬별 원점 오프셋(배틀 (320,180), 마을·로딩 (240,135))을 더해 floor(뷰 y 는 부호 반전 — 화면 아래가 +). 뷰 공간 기준이라 레터박스 뷰포트·해상도와 무관하게 격자가 배경 도트와 겹친다 |
| 전역 파라미터 | 씬 컴포넌트 `DotLightingSettings`(§7.6)가 `Shader.SetGlobalVector("_DotGridOrigin", …)` 로 원점 오프셋을 1회 설정. 단계 수 6·PPU 48 은 서브그래프 상수 |
| 도트 안 균일성 | 필수 요건: 한 도트 안에서 빛이 갈라지지 않는다(도트 중심 1회 샘플). 구현 방법(스냅된 뷰 위치 → 화면 UV 변환 후 샘플)은 gameplay-programmer 판단. 검증 = §11 G3 |

### 1.8 피치 변경에 따른 월드 높이 보정

| 대상 | 현행 | 문제 | 결정 |
|---|---|---|---|
| 몬스터 HP 바 `SetHeightAboveRoot(h)` | 월드 Y 로 h | `monster-2d-conversion.md` §6.3.7 의 h 는 빌보드 스프라이트 위 **화면 높이**로 산정됐는데 월드 Y 는 화면에 h·cosθ 로 보임(현행 50°: 0.643h — 이미 스프라이트에 겹침) | **카메라 up 축**으로 h 만큼 올린다(위치 = 루트 + 카메라 up × h). 표 값 그대로 화면 높이가 된다 |
| `DamagePopup` 부상 | 월드 Y 1.2 → 화면 1.2·cosθ | 피치마다 부상 거리가 달라짐 | 부상 축을 **카메라 up** 으로. 화면 부상 = 1.2u(기획 의도값). 시작점(호출부 콜라이더 상단 월드 좌표)은 유지 → 화면 시작 높이 = 1.8×루트스케일×0.883. Phantom T3 만 HP 바 하단(0.747) 아래(0.4×1.8×0.883 = 0.636)에서 시작하지만 첫 스텝(1/12s)에 RiseRatio(1) = 1−(6/7)³ = 0.370 → +0.44u 로 바 위로 벗어난다(현행 예외와 같은 성격) |
| `FearSkull` 부착 오프셋 (0, 2.1, 0) | 화면 2.1·cos50° = 1.350 | 28° 에서 1.854 로 머리 위 0.5u 이상 뜸 | 화면 높이 보존: 2.1 × cos50°/cos28° = 2.1 × 0.72801 = **1.53** |
| `TimeStopShield` 위치 hero.y + 0.5 | 화면 0.321 | 28° 에서 0.441 | 0.5 × 0.72801 = **0.36** |
| 지면 FX·강화 문장·`AuraShadow`·`Aura` | 세로가 sin50° = 0.766 로 눌림 | 28° 에서 sin28° = 0.469 로 더 눌림(0.469÷0.766 = 0.613배) | **변경 없음** — 그림 속 지면 타원 비율(0.44~0.47)과 일치하는 것이 이번 전환의 목적 |
| `HeroTargetProvider` 화면 사분면 선호 | 카메라 right/up 을 XZ 에 투영 | up 투영 = (0,0,sinθ) 정규화 → (0,0,1), 피치와 무관 | 변경 없음 |
| `MonsterVisual2D`·`SpriteSheetFx` 빌보드 | 카메라 회전 복사 | 피치와 무관 | 변경 없음 |

## 2. 에셋 제작 방법 — 시안 base 레이어 추출 (1안)

### 2.1 대안 비교

| 안 | 내용 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **1. 시안 캔버스 추출** | 시안 각 씬 `build()` 가 그리는 base(조명 전) 캔버스와 발광 요소를 같은 코드로 1× 도트 해상도 PNG 로 내보냄. `.mockups/server.js` 의 `POST /export/<Name>` 화이트리스트 패턴(영웅 `Heroes2D`·FX `FX2D` 추출 선례) 재사용 | 승인된 시안과 **픽셀 단위 동일**. 추가 아트 비용 0. 수치(좌표·팔레트)의 단일 출처가 코드로 유지 | 절차 생성 그림의 한계(손그림보다 단조) — 향후 같은 파일명으로 손그림 덮어쓰기 가능 | ✅ 채택 |
| 2. Tilemap 으로 재구성 | 타일 팔레트 제작 후 배치 | 편집 쉬움 | 투기장 동심원 석판·원근 행 간격이 타일 격자와 맞지 않음, 시안 재현 불가 | ✗ |
| 3. 외부 에셋 구매 | — | — | 톤 불일치, 승인 시안과 다름 | ✗ |

### 2.2 추출 절차

1. 시안 원본(`scene-2d-atmosphere.src.html`)에 **추출 패널**(버튼 1개 "Backdrop2D 추출")을 추가한다. 각 대상은 새 캔버스(대상 크기, 1× 도트)에 시안과 **같은 함수·같은 시드**(`seed` 11/23/41)로 그린 뒤 `toBlob('image/png')` → `POST /export/<파일명>`.
   - 배경: 각 씬 `build(b, mulberry32(seed))` 결과 `base` 캔버스를 그대로 내보낸다(이미 조명 전 레이어). 단 배틀은 **제단 블록을 건너뛴** `build` 변형으로 그린다(제단은 스포너 자식 스프라이트, §3.2). 시안 화면용 `build` 는 바꾸지 않는다.
   - 애니 시트: 해당 함수(`flame`, 거품, 스캔라인)를 t = i/12(i = 0…N−1)로 호출해 가로 스트립으로 이어 붙인다.
   - 흰색 틴트용 스프라이트(제단 링·결정·축 고리)는 해당 도형을 `#ffffff` 로 그린다.
2. `server.js` 에 세 번째 화이트리스트 `BACKDROP_NAMES`(§2.4 파일명 전부 + `Backdrop2D_SheetSpec.json`)와 저장 폴더 `Assets/_Lair/Art/Sprites/Backdrop2D/` 를 추가한다. UI 스프라이트 4장(§2.4 마지막 표)은 `Assets/_Lair/Art/Sprites/UiDot/` 로 저장하는 네 번째 화이트리스트 `UIDOT_NAMES`.
3. 추출 도구는 `Backdrop2D_SheetSpec.json` 에 파일별 {크기, 셀, 프레임 수, 피벗, 좌상단 도트} 를 기록한다 — 임포트 설정의 단일 진실(영웅 `Knight_SheetSpec.json` 선례). 아래 §2.4 의 크기·피벗은 시안 코드에서 계산한 기대값이며 추출값과 1도트라도 다르면 추출값이 맞는지 시안 코드로 재검산한다.
4. 메인이 `node .mockups/server.js` 로 서버를 띄우고 사용자가 버튼을 눌러 저장 → `[asset]` 커밋.

#### 4.3.1 피해 잔상(Lag)

- `SetHp` 가 불릴 때마다 잔상 시작값 = 현재 잔상, 목표 = 새 비율, 경과 0. 매 프레임 잔상 = 시작 + (목표 − 시작) × min(1, 경과 ÷ **0.7s**)(시안 CSS `transition: width .7s linear`).
- 목표가 현재 잔상보다 크면(회복) 잔상을 즉시 목표로 맞춘다(채움 뒤에 가려져 의미 없음).
- 경과는 `Time.unscaledDeltaTime` — 카드 선택 일시정지 중에도 잔상이 마저 줄어 다음 화면에서 남은 잔상이 없게 한다.

| 자식 | 배치(1280, 부모 좌상단) | 내용 |
|---|---|---|

**계산(순수 함수 `ComputeActiveCountdown(thresholds, elapsed)`)**: next = elapsed 보다 **큰** 첫 임계, prev = elapsed 이하의 마지막 임계(없으면 0). 남은 초 = next − elapsed, 진행 = (elapsed − prev) ÷ (next − prev). next 없음 → `HasNext = false`, 표시 `—`, 진행 0.

| elapsed | next | prev | 남은 초 | 표시 | 진행 |
|---|---|---|---|---|---|
| 0 | 30 | 0 | 30 | 0:30 | 0.000 |
| 29.5 | 30 | 0 | 0.5 | 0:01 | 0.983 |
| 30.0 | 90 | 30 | 60 | **1:00** | 0.000 |
| 60 | 90 | 30 | 30 | 0:30 | 0.500 |
| 269.9 | 270 | 210 | 0.1 | 0:01 | 0.998 |
| 270 | 없음 | 270 | — | — | 0 |

- 시안 코드는 `0:${ceil(r)}` 라 60초 구간에서 "0:60" 이 나온다 — **m:ss 로 정정**(타이머와 같은 올림 규칙: `HandleTimer` 의 `CeilToInt`).
- 임계 30s 를 넘는 순간 카드 선택 팝업이 뜨고 시계가 멈추므로 1:00 은 팝업 뒤에서 대기한다.

## 7. 신규 런타임 컴포넌트 행동 명세

코드 구조·클래스 배치는 gameplay-programmer 판단. 아래는 동작과 테스트 가능한 순수 함수 계약만 정한다.

### 7.1 `DotStageMapping` (정적 순수)
- §1.2 표의 세 씬 식을 제공: `BattleGroundToDot(Vector3 world)`, `BattleDotToGround(Vector2 dot)`, `VillageGroundToDot`, `VillageDotToGround`, `StageLocalFromDot(Vector2 dot, Vector2 screenCenterDot)`(= ((dx−cx)/48, (cy−dy)/48)).
- 상수: PPU 48, 배틀 θ 28°·기준 (320,198)·Z 기준 −2·화면 중앙 (320,180), 마을 θ 16°·기준 (240,221)·화면 중앙 (240,135).

### 7.2 `DotOrbitRing`
- 정적 자식 N개(프리팹·씬에 고정 배치, 동적 생성 금지)를 매 프레임 배치. i 번째 도트 오프셋 = (floor(cos a·rx + 0.5), floor(sin a·ry + 0.5)) 도트, a = 위상 + ω·t + i·2π/N, 화면 아래 = +y → 로컬 y 부호 반전 후 ÷48.
- 직렬화: 개수 N(= 자식 수), rx, ry(도트), ω(rad/s), 위상(rad), 색.
- 순수 함수: `DotOffset(int i, int count, float t, float omega, float phase, float rx, float ry)` → Vector2Int.

### 7.3 `DotWave` · `DotAlphaPulse` · `DotLightFlicker`
- `DotWave.Evaluate(float baseValue, float[] amps, float[] omegas, float[] phases, float t)` = base + Σ amp_k·sin(ω_k·t + φ_k).
- `DotAlphaPulse`: SpriteRenderer 알파 = clamp01(Evaluate). `DotLightFlicker`: Light2D intensity = max(0, Evaluate). 시간 = `Time.time`(일시정지 시 멈춤 — 카드 선택 중 조명도 정지).

### 7.4 `SpawnerAltar2D`
- 상위 `ISpawnerOutputProvider` 구독(기존 `SpawnerBody` 방식) → `SpeciesGlowColor` 로 RingDim·Ring·Crystal·Sparkle·Light 색 설정. 결정 흔들림(§3.2). Start 에서 카메라 회전 1회 복사.
- 순수 함수: `CrystalBobDots(float t, float phase)` = floor(sin(2.4t + phase)·1.5 + 0.5).

### 7.5 `SpriteSheetFx` 확장
- 직렬화 `_startTimeOffset`(초, 기본 0): `OnEnable` 에서 경과 = `_startTimeOffset`. 풀 FX 는 기본값 0 이라 동작 불변.
- 프레임 배열에 `null` 항목 허용(빈 프레임 — 반짝 깜빡임용). 현 `ShowFrame` 이 null 스프라이트를 그대로 대입하므로 동작상 이미 허용 — 테스트로 고정.

### 7.6 `DotLightingSettings`
- 씬마다 1개. `Awake` 에서 전역 셰이더 벡터 `_DotGridOrigin` = 화면 중앙 도트(배틀 (320,180), 마을·로딩 (240,135)).

### 7.7 `VillageWanderer`
- §5.6 규칙. 순수 함수: `StepToward(Vector2 pos, Vector2 target, float speed, float dt)` → (새 위치, 도착 여부), `NextWaypointIndex(int current, int count, int randomOffset)`.

### 7.8 `SpawnTravelCompensation` (정적 순수) + `Spawner.SetFirstSpawnDelay(float seconds)`
- `FirstSpawnDelay(float legacyRadius, float radius, float range, float moveSpeed)` = §3.5.2 식, moveSpeed ≤ 0 이면 0.
- `Spawner`: 첫 스폰을 지연만큼 늦춤. 지연 중 `Progress` = timer ÷ delay, `RemainingSeconds` = delay − timer. 기존 `_initialDelay`(no-op 필드)는 재사용하지 않는다(의미 혼동 방지).
- `BattleController` 가 스포너 바인드 시점에 종별 실효 Range·MoveSpeed 로 계산해 주입. 상수 R_legacy = 20, R_new = 스포너 링 반지름(씬 값 읽기).

### 7.9 월드 높이 보정
- `MonsterHpBar`: 위치 = 루트 위치 + 카메라 up × h. 순수 함수 `BillboardOffset(Vector3 cameraUp, float height)`.
- `DamagePopup`: 부상 방향 = 카메라 up(`_rise` 1.2 유지).
- `FearSkull` 부착 오프셋 y 2.1 → 1.53, `TimeStopShield` y +0.5 → +0.36.

### 7.10 `BattleCamera` 흔들림
- 오프셋 = right·rx + up·ry, rx·ry = 현행 난수 × 진폭을 `Round(v × 48) / 48` 으로 양자화. 순수 함수 `QuantizeToDot(float value)`.

### 7.11 영웅 2D 비주얼 홀로그램 모드
- 영웅 비주얼 루트에 홀로그램 on/off API(머티리얼·색·조명·그림자, §5.5). `OnEnable` 에서 기본값 복구.
