# 기사 S1 — 최종 시트 한 번에 제작 (코덱스 → 바로 적용 가능한 결과물)

02(대기 8프레임 시안)는 폐기한다. 이 프롬프트 하나로 최종 규격 시트까지 받는다.
첨부 3장: ① `keypose_approved.webp`(승인된 4포즈) ② `ref_knight_s1_idle_sprite.png`(실제 게임 스프라이트) ③ 스타일 레퍼런스 스크린샷
(②의 형태·캡·눈·천·검·갈비뼈를 지키고 ①의 치비 비율·외곽선을 따른다.)

## 프롬프트 (복붙)

```
[목표]
첨부한 승인 키포즈(1번)의 해골 기사를 그대로 유지한 채, 게임에 바로 넣을 수 있는 최종 스프라이트 시트 1장과 확인용 파일을 만든다. 그림 생성 + 코드 후처리를 모두 직접 수행하고, 결과 파일만 내게 넘긴다.

[캐릭터 — 모든 프레임에서 불변]
따뜻한 상아색 뼈 해골 치비(머리 40~45%), 초록 형광 눈 점 2개(#4ADE80), 보이는 갈비뼈, 어두운 2px 외곽선(#0A0D14), 왼쪽 어깨 낡은 천 조각, 어두운 반바지, 오른손(이미지 기준 오른쪽)에 은색 한손 소검.
색 교정: 캡은 어두운 남회색 + 초록 띠, 어깨 천은 어두운 회색 남색(승인본의 보라갈색·초록 대신). 형태는 승인본과 동일.
몸은 정면에 가까운 시점(승인본과 같음), 공격은 이미지 오른쪽 방향으로 한다.
스타일: 치비 고밀도 도트, 3톤 셀 셰이딩+하이라이트(빛은 왼쪽 위), 안티앨리어싱·디더링·블러·그라데이션·글로우 금지, 글자·그림자 금지.

[시트 규격 — 최종 파일]
- Knight_Sheet.png : 2048x1152 RGBA, 128x128 셀 16열 x 9행 (인덱스 = 행*16+열), 배경 완전 투명(알파 0 또는 255만, 반투명 금지).
- 행(위→아래)과 프레임 수: 0 idle 8 / 1 walk 8 / 2 run 8 / 3 slash01 9 / 4 slash02 9 / 5 stab 9 / 6 hit 6 / 7 death 8 / 8 spawn 16. 남는 칸은 완전 투명.
- 셀 안 배치: 발바닥 기준선은 셀 위에서 y=91(셀 높이의 71%), 몸 가로 중심은 x=54(셀 왼쪽에서 42%, 정중앙 아님). 발~캡 꼭대기 높이 56px(idle 프레임 0 기준). 셀 가장자리와 최소 2px 간격.
- 전체 시트에 팔레트 1개, 최대 48색(외곽선 #0A0D14 포함), 디더링 없음.

[품질 규칙 — 반드시 지킬 것]
A. 프레임 수 정확히: 행마다 위 프레임 수와 정확히 같아야 한다(idle/walk/run 은 각 8장, 7장이면 실패). 빠진 프레임은 다시 생성한다. 완성 후 행별 프레임 수를 세어 report.json 에 적는다.
B. 눈 보호: 눈은 어두운 눈구멍 3x3px 안에 초록 2x2px 코어가 또렷해야 한다(최종 크기 기준). 눈이 보이는 모든 프레임에서 유지하고, 뭉개져 코어가 사라지거나 번지면 그 프레임을 다시 생성/보정한다. 눈 초록(#4ADE80)과 눈구멍 어두운 색은 팔레트 보호색으로 지정해 양자화에서 합쳐지지 않게 한다. 눈 감은 피격 프레임은 1px 두께의 또렷한 선으로 그린다.
C. 무기 잘림 금지: 검 끝·검날·팔 어디도 셀 경계와 2px 이상 떨어져야 한다(검 끝 x ≤ 125, y ≥ 2). 포즈가 셀을 넘으면 잘라내지 말고 몸을 더 웅크리거나 검을 짧게 뻗도록 포즈를 다시 그린다. 검 길이와 굵기는 승인본 비율 그대로 모든 프레임에서 같게 유지한다(원근 축약만 허용). 특히 slash01 F5~F6, stab F4~F6(최대로 뻗는 프레임)과 slash02 F3~F4(검을 높이 든 프레임)를 검사한다.
D. 흐릿함 금지: 생성 시 최종 1픽셀 = 정확히 4x4 블록이 되게 그린다(셀 512px, 몸 높이 224px). 최근접 이웃으로 정확히 1/4 축소한다. 비정수 배율 축소·부드러운 리샘플링 금지.

[행별 동작]
0 idle: 숨쉬기. 몸이 위아래로 최종 크기 기준 2px 움직이고 검 끝이 살짝 흔들린다. 프레임 7→0 이 끊김 없이 이어진다.
1 walk: 제자리 걷기 사이클. 두 다리 교차, 팔·검이 반대로 흔들림, 몸이 사이클 중 2번 1px 위아래.
2 run: 상체가 앞(오른쪽)으로 기울고 보폭이 크다. 검은 뒤로 젖혀진다.
3 slash01: F0 준비, F1~F3 검을 오른쪽 위로 들어 와인드업, F4 타격 순간(검이 앞쪽 아래로 휘둘러져 가장 멀리 뻗은 포즈 — 가장 중요한 프레임), F5~F7 여운, F8 idle F0 과 같은 대기 자세.
4 slash02: slash01 과 반대 궤적(아래에서 위로 올려 베기). F4 타격, F8 대기 자세 복귀.
5 stab: F0~F3 검을 뒤로 당김, F4 찌르기 최대 뻗음(검이 수평으로 앞), F5~F7 유지 후 복귀, F8 대기 자세.
6 hit: F0 충격, F1~F2 뒤로 젖혀지며 눈이 깜빡임, F3~F5 복귀.
7 death: 비틀거리다 뼈가 분해되어 쓰러지고, F7 은 바닥에 뼈 더미(마지막 프레임 유지).
8 spawn: 바닥의 뼈 조각이 모여 조립되며 일어서고, F15 는 idle F0 과 같은 자세.
프레임은 서로 눈에 띄게 달라야 한다(복사 금지). 같은 행 안에서 캐릭터 디자인은 변하면 안 된다.

[작업 방법]
1) 행마다 따로 생성한다(행당 1회). 매번 승인 키포즈와 이미 만든 행을 참조로 쓴다. 생성은 품질 규칙 D 대로 셀당 512px(최종의 4배)로 그리고 배경은 마젠타 #FF00FF 단색.
2) 코드 후처리(모든 프레임에 같은 규칙, 프레임별 따로 맞추지 말 것):
   - 마젠타 키잉 후 가장자리 마젠타 잔여(번짐) 제거. 남은 마젠타 계열 픽셀 0개.
   - 시트 전체에 **스케일 계수 1개만** 사용: idle F0 의 발~캡 꼭대기가 56px 가 되는 비율을 모든 프레임에 똑같이 적용(프레임마다 키를 다시 맞추면 안 됨 — 숨쉬기·점프 움직임이 사라진다). 축소는 최근접 이웃.
   - 정렬은 행마다 1개의 이동량만 사용: 그 행 F0 의 발바닥 기준선→y=91, 몸 중심→x=54. 나머지 프레임은 생성된 상대 위치를 그대로 유지(위아래 움직임 보존).
   - 팔레트 48색 이하로 양자화(전체 공유), 알파는 0/255.
3) 결과 파일:
   - Knight_Sheet.png (위 규격)
   - rows/ 폴더: 행별 가로 스트립(row0_idle.png … row8_spawn.png, 투명, 128px 셀)
   - preview/ 폴더: 행별 반복 재생 GIF(셀 4배 확대, fps: idle 8, walk 10, run 14, slash/stab 15, hit 12, death 10, spawn 12, 어두운 남색 배경)
   - report.json: 행별 프레임 수, 프레임별 bbox(x,y,w,h), 발바닥 y, 사용 색 수, 셀 가장자리 간격이 2px 미만인 프레임 목록(0개여야 함), 눈 검사 결과(프레임별 초록 코어 픽셀 수), 행별 실제 프레임 수
   - raw/ 폴더: 후처리 전 원본 생성 이미지
```

## 제가 확인할 것
- 격자·프레임 수·투명 배경·48색·마젠타 잔여 0
- 프레임별 bbox 변화(움직임 보존: idle 의 상하 변위가 0 이 아니어야 함)
- slash01/02/stab 의 F4 가 타격 포즈인지, F8 이 idle F0 과 같은지, death 마지막 프레임, spawn F15
- 캐릭터 디자인이 행마다 변하지 않는지
