## 1. 레퍼런스 메커니즘 분석

### 1.1 동작

Legend of Keepers 에서 플레이어(던전 마스터)는 여러 방(Room)으로 이루어진 던전을 운영하며 2~4명의 영웅 파티를 막아야 한다. 영웅 파티는 단순히 고정 수치가 아니라 **전투 경험에 따라 라운드마다 상태가 변화**한다.

**상태 레이어 1 — 심리 상태 (Scared / Normal / Enraged)**:
- 영웅이 큰 피해를 입고 살아남으면 `Scared` → 다음 방 진입 시 공격력·이동속도 감소
- 영웅이 다수의 몬스터를 빠르게 처치하면 `Enraged` → 다음 방 진입 시 공격력·치명타 확률 증가
- 상태는 방과 방 사이 전환 시 업데이트되며, 영웅 초상화에 아이콘으로 즉시 표시됨

**상태 레이어 2 — 체력 관리**:
- 영웅은 방 사이 이동 시 최대 HP 의 일부(보통 10~30%)를 자연 회복
- "Healing Station" 룸을 적에게 내주면 영웅 완전 회복 가능 (플레이어의 희생)
- 전투에서 입힌 피해가 다음 방 진입 HP 에 직접 이어지므로, "이 방에서 충분히 깎았는가?"가 핵심 판단

**상태 레이어 3 — 협상·적응**:
- 던전 입구에서 영웅에게 "위협(Intimidate)", "뇌물(Bribe)", "설득(Negotiate)" 선택지 제공
- 위협 성공 → 영웅 그룹 내 특정 멤버 `Scared` 선입력 (전투 전 약화)
- 협상 성공 → 영웅이 일정 골드 지불 후 돌아감 (전투 회피, 자원 획득)
- 실패 시 → 영웅이 `Enraged` 상태로 돌입 (역효과)

**킬-페이싱 추적**:
- 게임 내부에서 라운드당 영웅이 처치한 몬스터 수를 추적
- 이 수치가 임계를 넘으면 `Enraged` 조건 충족
- 플레이어는 "몬스터를 빨리 죽이게 두는 것"이 다음 방에서 더 강한 영웅을 만들 수 있음을 인지

### 1.2 왜 잘 될까

첫째, **영웅 상태가 가시화되어 있어 다음 방 전략을 준비할 수 있다**. `Scared` 아이콘이 뜨면 "이번 방은 압박보다 피해 누적 위주로"처럼 플레이어가 목표를 바꾼다. 시스템이 투명하기 때문에 죽어도 납득이 가능하다.

둘째, **심리 상태 토글이 짧은 피드백 루프를 만든다**. 한 방에서 성공적으로 Scared 상태를 만들면 다음 방 진입 시 바로 보상(약해진 영웅)을 받는다. 행동→결과→보상의 루프가 밀리지 않는다.

셋째, **협상 시스템이 자원 트레이드오프를 만든다**. "위협해서 Scared 만들기" vs. "뇌물줘서 골드 손실 but 피해 없음" vs. "그냥 싸우기" 중 선택해야 하므로, 전투 외에도 의사결정 밀도가 올라간다.

넷째, **킬-페이싱이 영웅 강화의 트리거**가 되기 때문에, 플레이어가 몬스터 배치를 너무 약하게 하면 영웅이 더 빠르게 Enraged 되어 역풍을 맞는다. "적당히 강한 몬스터로 영웅을 지치게 하되, 빠르게 쓸어버리게 두지 않는다"는 밀도 있는 전략적 판단을 유도한다.

### 1.3 제약·한계

- **방과 방 사이 간격**이 있어야 상태 전환이 의미 있다. 단일 연속 전투(Project Lair 의 5분 런)에서는 "방 사이 전환" 자체가 없으므로 직역 불가능.
- 협상 시스템은 파티(2~4인) 구성이 있어야 대화 상대가 다양해진다. Project Lair 는 영웅 1명이므로 협상 분기가 단순해짐.
- Scared/Enraged 이분 구조는 단순하지만, 세 가지 이상의 상태 추가 시 UI 인지 부담이 커진다.

## 2. Project Lair 적용 후보 (패턴 3개)

### 2.1 패턴 1: 영웅 격분 상태 — 연속 처치 격발 (Kill-Streak Rage)

- **적용 대상**: `HeroController` / `IBattleContext` / `HeroAuraRunner` (or 신규 `HeroStateTracker`)
- **구현 스케치**: 영웅이 20초 이내에 5마리 이상 처치하면 `HeroRage` 상태 진입 (12초 지속). 이 구간 동안 영웅 공격속도 ×1.4, 이동속도 ×1.3. `HeroStateTracker` 가 kill event 타임스탬프 큐를 유지하고 20초 슬라이딩 윈도우로 체크. 격분 돌입 시 `IBattleContext.OnHeroStateChanged` 이벤트 → `BattleViewModel` 이 HUD 에 격분 타이머 표시. 플레이어는 격분을 보고 TimeStop / Fear 액티브 카드를 선제 사용 가능 — "격발 예보 → 대응 카드 선택" 루프가 생긴다. 격분이 끝나면 영웅은 `Normal` 상태로 복귀 (일시적 쿨다운 없음 — 격분 종료 후 다시 5마리 처치하면 재발동 가능).
- **구현 비용**: 2
- **MVP §11 호환**: O (신규 카드 없음, 기존 액티브 카드와 자연스럽게 연동)
- **적재 타이밍**: Alpha
- **의존 패턴**: 기존 `HeroController.OnMonsterKilled` 이벤트, 기존 `EHeroState` enum 확장 (Rage 값 추가)

### 2.2 패턴 2: 영웅 적응 저항 — 2분 30초 피해 분석 (Adaptive Mid-Run Resistance)

- **적용 대상**: `IBattleContext` (피해 추적) / `HeroStatSystem` / `BattleViewModel` (HUD 공지)
- **구현 스케치**: `IBattleContext` 에 `Dictionary<DamageSource, float> CumulativeDamageBySource` 유지. `DamageSource` 는 `MonsterAttack(speciesId)`, `PoisonAura`, `Bleed`, `WeakenEffect` 등 카드 효과 분류. 2분 30초(t=150s) 시점에 `HeroAdaptationSystem` 이 가장 큰 피해 출처를 읽고 해당 타입 저항 +30% 영구 부여. 예: Plague 피해가 최다 → 중독 저항 +30% (독 DPS 효과 감소). 영웅 HP 바 좌측에 작은 "방어막" 아이콘 + 저항 타입 아이콘 표시. 이 시스템은 단일 축 과도 집중(All-in Debuff 빌드 등)을 자연스럽게 압박하여 빌드 다양성을 유도한다. LoK 의 "영웅이 던전의 위협에 적응한다"는 서사와 정합.
- **구현 비용**: 3
- **MVP §11 호환**: O (카드 효과 값 조정이 아닌 영웅 수신 측 수정이므로 기존 카드 SO 변경 불필요)
- **적재 타이밍**: Alpha
- **의존 패턴**: `IBattleContext` 의 피해 로그 인프라, `HeroStatSystem` 의 stat multiplier 체계 (이미 `WispHpBoost` 등에서 사용)

### 2.3 패턴 3: 협박·지연 보상 — 스코어 기반 사전 약화 (Pre-Fight Debuff for Leaderboard Bonus)

- **적용 대상**: `MetaProfile` (리더보드 / 스코어) / 런 시작 화면 / `IBattleContext` (초기 설정)
- **구현 스케치**: 런 시작 전 마을 허브에서 "핸디캡 챌린지" 선택지 제공 (LoK 협박 시스템의 변형). 플레이어가 자발적으로 "영웅 초기 저항 +20%" 또는 "영웅 HP ×1.2" 같은 핸디캡을 골라 런을 시작하면, 클리어 시 리더보드 제출 점수에 핸디캡 배율(×1.3~×2.0) 을 곱해 상위 스코어 가능. v0.3 리더보드(최단 클리어 + 점수) 와 자연스럽게 결합. 핸디캡 미선택은 기본 배율 ×1.0. 구현: `RunConfig.HandicapFlags` 를 런 시작 시 설정 → `HeroInitSystem` 에서 초기 stat 에 반영 → `LeaderboardScoreCalculator.ComputeFinal(runTime, handicapMultiplier)`. 협박이 "실패하면 Enraged"인 LoK 와 달리, Project Lair 에서는 핸디캡 선택이 항상 플레이어 의지이므로 역효과 없음 — 대신 "어려운 조건에서 클리어한 자랑"의 사회적 인센티브로 작동.
- **구현 비용**: 3
- **MVP §11 호환**: O (v0.3 리더보드 연동 범위 내)
- **적재 타이밍**: v0.3 (리더보드 구현과 동시에 설계 가능)
- **의존 패턴**: `2026-06-15-unity-server-integration-design.md` 의 리더보드 제출 API, `MetaProfile` 세이브 구조

## 3. 우선순위 제안

**1순위: 패턴 2 (영웅 적응 저항)** — 가장 높은 게임플레이 영향력. 현재 Project Lair 에서 단일 축 올인 빌드(All-Debuff, All-Swarm)가 매우 강력할 것으로 예상되는데, 2분 30초 분기점에서 영웅의 자연 저항이 생기면 빌드 다양성을 시스템적으로 유도할 수 있다. qa-simulator 로 검증 가능한 정량 지표(단일 축 승률 vs. 혼합 빌드 승률)도 명확하다. Alpha 이전 구현 권장.

**2순위: 패턴 1 (격분 상태)** — 구현 비용이 가장 낮으면서 5분 런에 "반응 타이밍"을 추가한다. 현재 액티브 카드(Fear, TimeStop, Weaken)가 존재하지만 이를 "언제 써야 하는가"에 대한 명확한 신호가 부족하다. 격분 상태 UI 는 그 신호를 시각화하여 액티브 카드 사용의 의미를 높인다.

**3순위: 패턴 3 (핸디캡 리더보드)** — v0.3 서버 연동과 연계하면 개발 비용을 낮출 수 있지만, 리더보드 자체가 아직 설계 초안 수준이므로 리더보드 구조 확정 후 결정.

## 5. 쉬운 설명 (비개발자 요약)

Legend of Keepers 는 Project Lair 와 아주 비슷한 게임이에요. 플레이어가 던전 주인이 되어 쳐들어오는 용사 파티를 막아야 하죠. 이 게임의 핵심 아이디어는 용사들이 "기억"을 가진다는 점이에요. 방금 전 방에서 몬스터를 많이 쓸어버린 용사는 다음 방에서 자신감이 넘쳐 더 강해지고, 반대로 크게 다쳐서 살아남은 용사는 겁을 먹어 약해집니다. 용사의 심리 상태가 바뀌고, 던전 주인은 그걸 보며 전략을 짜는 거죠. Project Lair 에 적용하면 이렇게 됩니다: 영웅이 몬스터를 빠르게 잡을수록 일시적으로 격분해 더 강해지고, 2분 30초가 지나면 영웅이 지금까지 자기를 가장 많이 아프게 한 공격 방법에 면역이 생겨 플레이어가 전략을 바꿔야 해요. 마치 "아, 이 방법은 이제 안 통하겠구나"라는 긴장감을 주는 거예요. 그래서 이번에 참고하려는 것은: 영웅을 단순히 "공격 받으면 HP 줄어드는 고정 타깃"이 아니라, 전투 상황에 반응해 상태가 바뀌는 능동적 존재로 만드는 설계 패턴입니다.
