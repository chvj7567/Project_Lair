# 시너지 진행도 표시 — 기획서 (범위 축소판)

> 작성일 2026-10-03 · 사용자 피드백으로 범위 축소(같은 날 개정) · 단계 v0.3 · game-designer
> 입력: 사용자 요청 "시너지를 쌓아가고 있는지 확인이 어렵다 — 카드에 시너지 아이콘, 진행도 표시"
> 연관 단일 진실: 컨셉 §5.2(시너지 가시성) · `docs/design/card-renewal.md` §4.1(임계 3/5/7·누적 정책) · `docs/design/ui-dot-dungeon-redesign.md`(도트 UI 톤)
> 주의: 시너지 Tier 효과 수치의 단일 진실은 코드 Tier 상수와 `Strings_Ko.json` 200~211 이다. 본 기획서는 수치를 새로 정하지 않는다.

## § 헤더

- **목표**: 플레이어가 "내가 어느 시너지를 몇 장 쌓았고 다음 Tier 까지 몇 장 남았는지"를 **카드 선택창과 전투 HUD 양쪽에서** 한눈에 보게 하고, 카드가 어느 시너지 축인지 아이콘으로 알아보게 한다.
- **검증 가설**: 진행도가 항상 보이면 플레이어가 Tier 임계를 의식해 카드를 고르고(빌드 의도성 ↑), 한 축에 집중해 Tier 2·3 에 도달하는 런이 늘어난다.
- **현재 단계 범위 적합성**: **범위 내**. 읽기 전용 표시 UI. 임계(3/5/7)·Tier 효과·카드 풀·드로우 규칙 무변경(밸런스 불변), 신규 아트 0(기존 `SynergyIcons` 4장 재사용).
- **핵심 메커니즘**: 축별 누적 장수 `c`(`BattleViewModel.GetBuildCount`)를 **7칸 진행 트랙 + `장수/다음 임계` 숫자**로 보여주는 시너지 행 위젯 1종을 (1) 카드 선택창 하단 "내 시너지" 4칩, (2) 배틀 HUD 우상단 시너지 패널에 같이 쓴다. 카드 선택창의 각 카드에는 자기 축 아이콘 1개만 모서리에 붙인다.

### 범위 (사용자 확정)

| 포함 | 제외 (이번 범위 아님) |
|---|---|
| ① 카드 선택창 하단 "내 시너지" 4칩 | 카드 안 시너지 띠(선택 후 미리보기·발동/진행 중/신규/MAX 라벨·설명·카드 글로우) |
| ② 배틀 HUD 우상단 시너지 패널 개편 | 빌드 바 카드 칸 축 아이콘 배지, 빌드 상세 모달 카드 셀 배지 |
| ③ 카드 선택창 카드 모서리 축 아이콘 1개(텍스트·진행도 없음) | 카드 폭·일러스트 높이 변경, 시너지 모달 확장, 발동 토스트, 정렬·추천 |

## 1. 설계 결정 (대안 비교)

### 1.1 진행도 표현 (핵심 결정 ①)

| 대안 | trade-off | 판정 |
|---|---|---|
| A. 숫자만 `2/3` | 쌈. Tier 3단계(3/5/7) 위치가 안 보이고 도트 UI 톤과 이질적 | 기각 |
| **B. 7칸 트랙 + 숫자 (권장)** | 현재 위치·다음 Tier 까지 거리·Tier 3개 구조가 한 위젯에 보임. HP 10칸·레벨 5칸 눈금과 같은 도트 UI 문법 | **채택** |
| C. Tier 별 3분할 게이지 | Tier 간격이 3/2/2 로 달라 구간 폭이 불균등하고 폭 낭비 | 기각 |

### 1.2 카드 축 표시 (핵심 결정 ②)

| 대안 | trade-off | 판정 |
|---|---|---|
| **A. 모서리 축 아이콘 1개 (권장)** | HUD 패널·칩의 아이콘과 같은 그림이라 "이 카드 = 저 줄" 이 연결됨. 신규 아트 0, 레이아웃 무변경 | **채택** |
| B. 프레임 색을 축 색으로 | 프레임 색은 패시브 소울/액티브 금(종류 구분)에 이미 사용 — 의미 겹침 | 기각 |

### 1.3 아이콘 공급 (핵심 결정 ③)

| 대안 | trade-off | 판정 |
|---|---|---|
| A. 소비처마다 인스펙터 Sprite 4개 | 이번 신규 소비처는 카드 선택창(`CardView` 아이콘 + 하단 4칩) 2곳이라 프리팹 슬롯이 8개로 늘고, 누락 시 아이콘이 조용히 사라짐 | 기각 |
| **B. 공유 SO `SynergyVisualConfig` (권장)** | 4축 Sprite 를 SO 1곳에 모아 `EData` 키로 로드. Sprite 참조를 담으므로 SO 가 맞음(Rule 02 §11 예외). 로드 후 뷰에 주입(Rule 02 §5) | **채택** |

기존 `BuildSynergyPanel`·`SynergyModalPopup` 의 Sprite 4필드는 이번에 건드리지 않는다. 단 HUD 패널(§3.2)은 위젯을 개편하므로 기존 `AxisIcon` 매핑이 그 패널에 이미 공급하는 Sprite 를 그대로 쓴다.

## 2. 공통 규칙 — 시너지 진행 산식

- 임계 `{3, 5, 7}` = Tier 1/2/3. 원본은 `BuildSynergyService.Tier1Threshold/Tier2Threshold/Tier3Threshold` 하나이며 신규 코드는 이를 참조한다.
- `c` = `GetBuildCount(axis)`. 파생값:
  - 활성 Tier `t(c)`: `c ≥ 7` → 3, `c ≥ 5` → 2, `c ≥ 3` → 1, 그 외 0.
  - 다음 임계 `N(c)`: `c` 보다 큰 첫 임계. `c ≥ 7` 이면 없음.
  - 장수 텍스트: `c < 7` 이면 `{c}/{N}`, `t ≥ 1` 이면 뒤에 ` T{t}` 부착(예 `4/5 T1`). `c ≥ 7` 이면 `{c}+ T3`(예 `9+ T3`).
- 축 이름·색은 기존 `BuildSynergyPanel.AxisLabel` / `AxisColor`(Tank `#5AA9FF` · Dps `#FF6B5A` · Debuff `#C08BFF` · Swarm `#7BE36A`)를 재사용한다.
- 축 나열 순서: `TANK → SWARM → DPS → DEBUFF`(기존 `AllAxes`).

### 2.1 7칸 진행 트랙 (`SynergyTrack`)

- 칸 7개, 높이 7px, 간격 2px, 칸 너비 19px. 검산 `7×19 + 6×2 = 145 ≤ 행 안쪽 폭 151`(`170 − 8×2(패딩) − 3(축 색띠)`).
- 채움 칸 = 축 색, 빈 칸 = `#0B0E14`.
- 3·5·7번째 칸 = Tier 칸: 빈 상태 `#B9B09A` 2px 테두리, 채운 상태 `#E8E1CF` 2px 테두리 + 바깥 `#07090E` 2px.
- **새 칸 점멸**: 장수가 늘어난 직후 방금 채워진 칸이 0.3초간 흰색 → 축 색(3단계 steps). Tier 임계 돌파 시 기존 `JustCrossed` 펄스(축 색띠 알파 50 → 100 → 50, 0.3초)는 그대로 유지.

## 3. 표면별 사양

### 3.1 시너지 행 위젯 (`BuildSynergyCell` 개편 — HUD 패널과 선택창 칩 공용)

| 항목 | 사양 |
|---|---|
| 크기 | 폭 170 × 높이 44. 검산 `5(상 패딩) + 22 + 4(줄 간격) + 7 + 5(하 패딩) = 43 ≤ 44` |
| 1줄(높이 22) | 축 아이콘 22×22(기존 `_axisIcon`) · 축 이름(남는 폭) · 장수 텍스트(§2, 12px, 축 색, 우측 정렬) |
| 2줄(높이 7) | `SynergyTrack` 7칸 |
| `c = 0` | 행 전체 불투명도 0.55(기존 흐림) |
| `c ≥ 1`, `t = 0` | 불투명도 1.0, 색띠 없음(쌓는 중 — 기존에는 0장과 같이 흐렸음) |
| `t ≥ 1` | 불투명도 1.0 + 왼쪽 3px 축 색띠(기존) |
| 기존 점 3칸 마커(`_tierMarkers`) | 트랙 7칸으로 대체 |

### 3.2 배틀 HUD 우상단 시너지 패널 (`BuildSynergyPanel`)

- 위치(우상단)·폭 170·접기/펼치기·루트 클릭(→ `SynergyModalPopup`)·접힌 탭 축 점 4개는 **그대로**.
- 4행을 §3.1 위젯으로 표시. 패널 총 높이 검산 `헤더 14 + 간격 6 + 4행×44 + 3간격×6 = 214 ≤ 현재 _expandedHeight 247` — 247 유지.
- 접힌 동안 장수가 변하면 접힌 탭 점만 갱신하고 펼칠 때 일괄 갱신(기존 경로).

### 3.3 카드 선택창 하단 "내 시너지" 4칩

- 팝업 하단에 §3.1 위젯 4개를 가로 배치. 폭 170, 간격 12 → 합계 `4×170 + 3×12 = 716 ≤ 960`, 가운데 정렬, 하단 여백 14 → 칩 영역 y = 482~526(`540 − 14 − 44 = 482`).
- 칩 위 10px 보조 라벨 `내 시너지`(y = 464). 기존 카드 배치(상단 y=92 + 카드 높이 314 → 하단 406, 검산 `6+6+200−26+22+52+40+8+6 = 314`)와 겹치지 않는다. 카드 하단이 y=460 을 넘지 않는 것이 제약이다.
- 칩은 읽기 전용(클릭 동작 없음). 장수는 팝업이 열린 시점의 `GetBuildCount`(팝업 중 게임 일시정지라 불변).
- 액티브 카드 팝업에도 동일하게 표시(패시브·액티브 구분 없이 카운트되므로).

### 3.4 카드 선택창 카드 모서리 축 아이콘 (`CardView`)

- 카드에 해당 `CardData.Axis` 의 아이콘 1개. **텍스트·진행도·색 변화 없음.**
- **위치**: 카드 좌상단, 종류 라벨(`패시브`/`액티브`, 좌상단 `(10, 10)`) 바로 아래 `(10, 36)`. 우상단 `n/3` 배지와 반대편이라 겹치지 않는다.
- **크기**: 외곽 28×28 = 아이콘 24×24(도안 12×12 의 2배) + 패딩 2. 바탕 `#0C1017`, 안쪽 2px 축 색 테두리, 바깥 `#07090E` 2px.
- **아이콘이 없는 경우**(축에 해당 Sprite 가 없거나 SO 미로드): 위젯 전체를 숨긴다(빈 박스 금지).
- 카드 폭 210·일러스트 높이 200 등 기존 치수·프레임 색·배지는 무변경.

## 5. 페이싱 · 밸런스 영향

- 수치 변경 0(임계·Tier 효과·카드 풀·3픽 캡·드로우·트리거 간격 전부 무변경). 헤드리스 시뮬과 무관하므로 qa-simulator 재실행 불필요.
- 카드 선택창은 일시정지 상태라 정보가 늘어도 전투 압박이 없다. 추가 정보는 칩 4개와 카드당 아이콘 1개뿐이다.
- 의도된 행동 변화(사람 플레이로 확인): 임계 직전 축을 더 의식해 고른다. 쏠림 우려 시 조정은 별도 밸런스 사이클에서 다룬다.

## 7. 구현 요청사항 (gameplay-programmer 용)

### Enum (`Assets/_Lair/Scripts/Data/CommonEnum.cs`)

- `EData` 맨 끝에 `SynergyVisualConfig` 추가(append-only). 값명 = SO 에셋 파일명(Rule 03 §2).
- 그 외 Enum·Interface 신규 없음. 소비처는 기존 `BattleViewModel.GetBuildCount` · `OnBuildChanged` 를 사용한다. 진행 산식(§2)은 View 밖 순수 계산 단위에 두어 EditMode 에서 검증할 수 있어야 한다(Rule 02 §6).

### 에셋 키

| 에셋 | 경로 | 키 |
|---|---|---|
| 공유 SO | `Assets/_Lair/Art/Synergy/SynergyVisualConfig.asset` (신규 폴더 `Art/Synergy/`) | `EData.SynergyVisualConfig` = Addressables 주소 `SynergyVisualConfig`, 라벨 `Resource` |
| 축 아이콘 4장 | `Assets/_Lair/Art/Sprites/SynergyIcons/*.png` | 기존, SO 가 Sprite 로 참조 |

### SO 스키마

`SynergyVisualConfig : ScriptableObject`

| 필드 | 타입 | 설명 |
|---|---|---|
| `Entries` | 배열(길이 4) | 축마다 정확히 1개 |
| `Entries[i].Axis` | `EBuildAxis` | Tank/Dps/Debuff/Swarm, 중복·누락 금지 |
| `Entries[i].Icon` | `Sprite` | 해당 축 `SynergyIcons/*.png` |

`Axis → Sprite` 조회는 누락 시 null 반환. 로드는 `CHMResource.Instance.LoadAsync<SynergyVisualConfig>(EData.SynergyVisualConfig)` 1회 후 `CardSelectionPopup` 에 주입.

### 프리팹 변경 (정적 배치, 코드 동적 생성 금지 — Rule 03 §3)

- `CardView`(카드 선택창 카드): 모서리 아이콘 Image 1개 추가 + `[SerializeField]` 연결. 팝업 안 3개 인스턴스에도 동기화.
- `BuildSynergyCell`: 점 3칸 마커 → 7칸 트랙, 장수 텍스트(`CHText`) 위치 조정, 높이 44. `BuildSynergyPanel` 내 origin 셀 인스턴스에도 동기화(origin 컴포넌트·참조 누락 금지).
- `CardSelectionPopup`: 하단 칩 4개 + 보조 라벨(`CHText`, 문자열 id 300). 칩에는 §3.1 위젯(`BuildSynergyCell` 프리팹)을 재사용.
- 프리팹을 코드로 찍어내는 빌더를 쓰면 생성 후 삭제(Rule 04 §3).

## 9. 수용 기준

### A. 자동 검증 가능

| # | 기준 |
|---|---|
| A-1 | 장수 텍스트: `c=0 → 0/3`, `2 → 2/3`, `3 → 3/5 T1`, `5 → 5/7 T2`, `6 → 6/7 T2`, `7 → 7+ T3`, `9 → 9+ T3` |
| A-2 | 불투명도·색띠: `c=0 → 0.55`, `c=1·2 → 1.0(색띠 없음)`, `c≥3 → 1.0(색띠 있음)` |
| A-3 | 트랙 채움 칸 수 = `min(c, 7)`, 3·5·7번째 칸에 Tier 테두리 |
| A-4 | 풀 재사용 후 이전 트랙·색띠·텍스트 잔상 없음 |
| A-5 | SO 의 4축 전부 Sprite 할당, 누락 시 카드 모서리 아이콘 비활성 |
| A-6 | 카드 모서리 아이콘 표시 크기가 PNG 해상도의 정수배 |
| A-7 | `CardView` 는 `CardData.Axis` 에 해당하는 아이콘을 표시하고 축이 다른 카드끼리 아이콘이 다르다 |

### B. 수동 플레이 확인

| # | 기준 |
|---|---|
| B-1 | 전투 중 HUD 만 보고 "TANK 를 몇 장 쌓았고 다음 Tier 까지 몇 장인지" 말할 수 있다 |
| B-2 | 카드 선택창에서 하단 칩으로 같은 정보를 볼 수 있고, HUD 패널과 같은 장수가 표시된다 |
| B-3 | 카드 모서리 아이콘이 좌상단 종류 라벨·우상단 `n/3` 배지와 겹치지 않는다(960×540) |
| B-4 | 카드 하단과 칩 보조 라벨(y=464)이 겹치지 않는다 |
| B-5 | 카드를 고른 직후 HUD 해당 축 트랙의 새 칸이 점멸하고, 임계 돌파 시 기존 펄스가 함께 동작한다 |

## 12. 열린 질문

1. **카드 모서리 아이콘 위치**: 좌상단 종류 라벨 아래 `(10, 36)` 로 정했다. 일러스트 위에 얹히므로 일러스트 좌상단 일부가 가려진다. 우상단 `n/3` 배지 아래로 옮기는 안도 가능한데, 배지가 없는 카드(첫 픽)에서는 우상단이 비어 보인다. 목업에서 보고 위치 변경을 원하면 알려 달라(기본값은 좌상단).
2. **효과 측정**: Tier 2 이상 도달 런 비율 같은 정량 지표는 `RunSummary` 변경이 필요해 범위 밖이다. 수동 플레이 확인(§9 B)만으로 갈지 확인 필요.
