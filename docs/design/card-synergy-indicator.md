## § 헤더

- **목표**: 플레이어가 (a) 카드가 어느 시너지 축인지, (b) 지금 그 축을 몇 장 쌓았고 다음 Tier 까지 몇 장 남았는지, (c) 지금 고르려는 카드가 내 진행을 올려주는지 / Tier 를 발동시키는지를 **카드 선택 순간과 전투 중 모두** 한눈에 알 수 있게 한다.
- **검증 가설**: 시너지 진행이 눈에 보이면 플레이어가 "Tier 까지 N장 남음"을 근거로 카드를 고르고(빌드 의도성 ↑), 한 축에 집중해 Tier 2·3 에 도달하는 런이 늘어난다.
- **현재 단계 범위 적합성**: **범위 내**. 읽기 전용 표시 UI 이며 시너지 임계(3/5/7)·효과 수치·카드 풀·드로우 규칙은 **무변경**(밸런스 불변). 신규 아트 0(기존 `SynergyIcons` 4장 재사용), 메인 메뉴/세팅 화면·서버 연동 무관. 컨셉 §5.2 시너지 가시성의 직접 연장.
- **핵심 메커니즘**: 모든 표시 면이 하나의 진행 산식(축별 누적 장수 `c` → 활성 Tier · 다음 임계 · 남은 장수)을 공유한다. 카드 선택창은 카드마다 "선택 후 장수 `c+1`" 을 미리 계산해 **발동 / 진행 중 / 신규 / MAX** 4상태 띠로 보여주고, 배틀 HUD 는 빌드 바 카드 칸에 축 아이콘 배지를, 시너지 패널에 7칸 진행 트랙과 `장수/다음 임계` 숫자를 붙인다.

## 1. 설계 원칙과 대안 비교

### 1.1 시너지 식별 방식 (핵심 결정 ①)

| 대안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| **A. 축 아이콘 배지 (권장)** | 카드마다 자기 축의 기존 도트 문장 1개를 18×18 배지로 붙인다 | 신규 아트 0, HUD 시너지 패널 아이콘과 같은 그림이라 "이 카드 = 저 패널 줄" 이 즉시 연결됨. 4종뿐이라 학습 비용 최소 | **채택** |
| B. 카드 프레임 색을 축 색으로 | 프레임 테두리를 축 색(4색)으로 | 이미 프레임 색은 패시브 소울/액티브 금(종류 구분)에 쓰이며 `ui-dot-dungeon-redesign` 에서 확정. 두 의미가 한 채널에 겹쳐 오독 | 기각 |
| C. 카드별 개별 시너지 아이콘 | 카드 28장마다 고유 아이콘 | 시너지는 카드 단위가 아니라 **축 단위**(4개)이므로 의미 없는 신규 아트 28장. YAGNI | 기각 |

### 1.2 진행도 표현 방식 (핵심 결정 ②)

| 대안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| A. 숫자만 `2/3` | 텍스트만 | 가장 쌈. 그러나 Tier 3단계(3/5/7)가 어디인지 안 보임, 도트 UI 톤과 이질적 | 기각 |
| **B. 7칸 트랙 + 숫자 (권장)** | 7칸 중 장수만큼 축 색으로 채움, 3·5·7번째 칸은 흰 테두리(= Tier 칸), 옆에 `장수/다음 임계` | 한 위젯에서 "현재 위치·다음 Tier 까지 거리·Tier 3개 구조"가 다 보임. 도트 UI 의 기존 눈금(HP 10칸·레벨 5칸 눈금) 문법과 동일 | **채택** |
| C. Tier 별 3분할 게이지 | 0-3 / 3-5 / 5-7 구간 게이지 3개 | Tier 간격이 3/2/2 로 달라 구간 폭 불균등, 위젯 폭 낭비 | 기각 |

### 1.3 선택지 카드 강조 방식 (핵심 결정 ③)

| 대안 | 내용 | trade-off | 판정 |
|---|---|---|---|
| A. 단순 "+1" 표기만 | 모든 카드 동일 비중 | 강조가 없어 "내 진행 올려주는 카드"를 찾아 읽어야 함 | 기각 |
| **B. 4상태 + 강조 위계 (권장)** | 발동 > 진행 중 > 신규 > MAX 위계로 띠 스타일·카드 테두리 빛을 차등 | 읽지 않아도 "빛나는 카드 = Tier 터짐" 이 눈에 들어옴. 카드 순서·확률은 건드리지 않음 | **채택** |
| C. 진행 중 축 카드를 앞으로 정렬 | 드로우 결과 재정렬 | 3택 위치 학습(좌/중/우 무작위) 파괴, 사실상 추천 시스템 = 메카닉 변경 | 기각 |

## 2. 공통 규칙 — 시너지 진행 산식 (모든 표면의 단일 진실)

- 임계 배열 `{3, 5, 7}` = Tier 1/2/3 (카운트 대상·누적 정책은 card-renewal §4.1 그대로). **원본은 `BuildSynergyService.Tier1Threshold/Tier2Threshold/Tier3Threshold` 하나**이며 신규 표시 코드는 이를 참조한다(신규 복제 금지).
- `c` = `GetBuildCount(axis)` (현재 장수). 파생값:
  - 활성 Tier `t(c)` = `c ≥ 3` 이면 1, `c ≥ 5` 이면 2, `c ≥ 7` 이면 3 (해당 없으면 0).
  - 다음 임계 `N(c)` = `c` 보다 큰 첫 임계. `c ≥ 7` 이면 없음.
  - 표시 장수 텍스트(HUD 패널): `c < 7` 이면 `{c}/{N}`, Tier 1 이상이면 뒤에 ` T{t}` 부착(예 `4/5 T1`). `c ≥ 7` 이면 `{c}+ T3`.
- 시너지 축 표기: 아이콘 + 대문자 이름(`TANK`/`SWARM`/`DPS`/`DEBUFF`, 기존 `BuildSynergyPanel.AxisLabel`) + 축 색(기존 `BuildSynergyPanel.AxisColor`: Tank `#5AA9FF` · Dps `#FF6B5A` · Debuff `#C08BFF` · Swarm `#7BE36A`). **축 색·이름은 신규 정의하지 않고 기존 static 을 재사용한다.**
- 축 나열 순서(패널·칩): `TANK → SWARM → DPS → DEBUFF` (기존 `BuildSynergyPanel.AllAxes` 와 동일).

### 2.1 7칸 트랙 위젯 (`SynergyTrack`, 공용)

- 칸 7개, 칸 높이 7px, 칸 간격 2px. 채움 = 축 색, 빈 칸 = `#0B0E14`.
- 3·5·7번째 칸 = **Tier 칸**: 빈 상태에서 `#B9B09A`(Bone2) 2px 테두리, 채워진 상태에서 `#E8E1CF`(Bone) 2px 테두리.
- 칸 너비는 배치처가 정한다: HUD 패널 19px(검산 `7×19 + 6×2 = 145`, 행 안쪽 폭 151 이내), 카드 띠 22px(검산 `7×22 + 6×2 = 166`, 띠 안쪽 폭 186 이내 — 카드 폭 230 기준 `230 − 12(카드 패딩) − 16(띠 외곽 여백) − 16(띠 패딩) = 186`).
- **고스트 칸**(카드 선택창 전용): "이 카드를 고르면 채워질 칸" = `c` 번째(0부터) 칸. 축 색 2px 테두리 + 0.8초 주기 2단계(steps) 깜빡임. MAX 상태에서는 고스트 없음.
- **새 칸 점멸**(HUD 전용): 장수가 늘어난 직후 방금 채워진 칸이 0.3초간 흰색→축 색(steps 3). Tier 임계 돌파 시의 기존 `JustCrossed` 펄스(축 색띠 알파 50→100→50, 0.3초)는 그대로 유지.

## 3. 표면별 사양

### 3.1 카드 선택창 — 카드 시너지 띠 (`CardView` 확장)

**배치**: 카드 설명(`ds`)과 선택 버튼 사이에 **시너지 띠(SynergyStrip)** 1개를 둔다. 카드 프레임 색(패시브 소울/액티브 금)·종류 라벨·`n/3` 배지는 **변경하지 않는다**.

**카드 치수 변경** (띠를 담기 위해): 카드 폭 210 → **230px**, 일러스트 높이 200 → **170px**(−30). 카드 총 높이 합계 검산 `6(패딩) + 6(일러스트 마진) + 170 + (−4 이름 오버랩) + 36(설명 최소) + 77(띠) + 54(버튼 마진 포함) + 6 = 351`. 카드 높이 상한 **400px**(카드 상단 y=82 → 하단 ≤ 482, 하단 칩 상단 y=482 와 겹치지 않음. 검산 `540 − 14 − 44 = 482`). 3장 가로 합계 `3×230 + 2×28(간격) = 746 ≤ 960`.

**띠 구성** (`SynergyStrip`, 폭 = 카드 안쪽 186px, 높이 77px, 줄별 높이는 아래 표):

| 줄 | 요소 | 사양 |
|---|---|---|
| 1줄(높이 18) | 축 아이콘 배지 · 축 이름 · 상태 태그 · `c → a` | 배지 18×18(아이콘 12×12 + 패딩 3, 바탕 = 축 색, 외곽선 2px `#07090E`). 축 이름 12px 축 색. 상태 태그 10px. `c → a` 는 우측 정렬 13px, `a` 만 축 색 |
| 2줄(높이 7) | `SynergyTrack` 7칸 | 채움 = `c`칸, 고스트 = `c`번째 칸(MAX 제외) |
| 3줄(높이 28 = 2줄 ×14) | 캡션 11px | 상태별 문구(아래 표). 2줄 초과 시 말줄임 |

높이 합계 검산: `상하 패딩 12 + 18 + 4(줄 간격) + 7 + 4 + 28 + 4(띠 위 마진) = 77`.

**상태 판정** (카드마다 독립 계산. 선택지 3장이 같은 축이어도 각각 `a = c + 1` 로 계산하고 서로 누적하지 않는다):

`c` = 선택 전 장수, `a = c + 1` = 이 카드를 골랐을 때 장수.

| 우선순위 | 상태 | 조건 | 태그 | 캡션 | 띠 스타일 | 카드 전체 |
|---|---|---|---|---|---|---|
| 1 | **발동** | `a ∈ {3, 5, 7}` | `T{t} 발동` (t = 1/2/3) | 그 Tier 효과 문구(런타임 설명, 예 `환령·도깨비불 이동속도 ×1.3`) | 바탕이 축 색 22% 혼합, 외곽 2px 축 색 + 바깥 2px 검정, 태그는 축 색 반전(축 색 바탕·어두운 글자) | 프레임 바깥 글로우가 1초 주기 2단계 점멸(축 색, 번짐 16px, 확산 2px) |
| 2 | **MAX** | `c ≥ 7` | `MAX` | `Tier3 달성 · 추가 효과 없음` | 전체 불투명도 0.5, 고스트 없음 | 변화 없음 |
| 3 | **진행 중** | `c ≥ 1` 이고 위 둘이 아님 | `진행 중` | `Tier{n}까지 {k}장` (n = `N(a)` 의 Tier 번호, k = `N(a) − a`) | 외곽 2px 축 색, 태그 글자·테두리 축 색 | 변화 없음 |
| 4 | **신규** | `c = 0` | `신규` | `Tier1까지 2장` (`a = 1` 이므로 `N = 3`, `k = 2`) | 기본(외곽 2px 검정) | 변화 없음 |

- 우선순위 1·2 는 동시 성립할 수 없다(`c ≥ 7` 이면 `a ≥ 8` 이라 발동 조건 `a ∈ {3,5,7}` 에 해당하지 않음). 판정은 표의 우선순위 번호가 아니라 조건 그대로 평가하면 된다.
- 검산(Tank): `c=0 → 신규(1)` · `c=1 → 진행 중(2)` · `c=2 → 발동 T1(3)` · `c=3 → 진행 중(4), 캡션 Tier2까지 1장` · `c=4 → 발동 T2(5)` · `c=5 → 진행 중(6), 캡션 Tier3까지 1장` · `c=6 → 발동 T3(7)` · `c=7 → MAX`.
- **상태 계산 시점**: 팝업이 열리는 순간 1회. 팝업이 열려 있는 동안 게임은 일시정지(`_pause.Pause()`)이므로 `c` 가 바뀔 일이 없다.
- 액티브 카드 팝업도 동일 띠를 쓴다(`AddPick` 이 패시브·액티브 구분 없이 카운트를 올리므로 의미가 같다). 프레임 색만 금색.

### 3.2 카드 선택창 — "내 시너지" 4칩 (재사용 위젯)

- 팝업 하단(y=482~526, 높이 44)에 **HUD 시너지 패널 행과 같은 위젯**(§3.4 `BuildSynergyCell` 개편본) 4개를 가로로 배치한다. 폭 170, 간격 12 → 합계 `4×170 + 3×12 = 716 ≤ 960`, 가운데 정렬. 상단에 10px 보조 라벨 `내 시너지`.
- **연결 하이라이트**: 이번 선택지 3장에 포함된 축의 칩은 4면 3px `#E8E1CF` 테두리를 둘러 "카드 띠 ↔ 칩" 을 연결한다. 선택지에 없는 축은 기본 테두리.
- 칩은 현재 상태(`c`)만 보여준다. 고스트 +1 은 카드 띠가 담당한다(중복 방지).
- 칩 클릭 동작 없음(팝업 중 모달 중첩 금지).

### 3.3 배틀 HUD 빌드 바 — 카드 칸 축 아이콘 배지 (`BuildIconCell` 확장)

- 채워진 모든 카드 칸(패시브 9칸 최소 · 액티브 5칸 최소 구조는 유지)의 **왼쪽 위 모서리**에 18×18 배지(아이콘 12×12). 위치 오프셋: 칸 좌상단 기준 `(-6, -6)`. `×N` 배지(우하단)·종류 링과 겹치지 않는다.
- **배지 바탕 2상태**(그 카드의 축 시너지 진행 반영):

  | 축 활성 Tier | 배지 | 의미 |
  |---|---|---|
  | `t(c) ≥ 1` | 바탕 = 축 색, 외곽 2px 검정 | 이 카드가 속한 시너지가 켜져 있음 |
  | `t(c) = 0` | 바탕 `#0B0E14`, 안쪽 2px 축 색 테두리 + 아이콘 | 아직 Tier 1 미달 — 쌓는 중 |

- 빈 슬롯(빗금)에는 배지 없음.
- 같은 카드 `×N` 중첩은 배지 1개(축 장수 `N` 반영은 §3.4 트랙이 담당).
- 빌드 상세 모달 `BuildModalPopup` 의 카드 셀(`BuildModalCardCell`)에도 같은 배지를 같은 규칙으로 붙인다(빌드 전체를 보는 화면에서 축 분포를 확인할 수 있게).
- 정렬은 **획득 순서 유지**(대안 "축별 묶음 정렬"은 §11 비범위: 획득 순서 기억을 깨고, 배지만으로 분포 파악이 가능하다).

### 3.4 배틀 HUD 시너지 패널 — 진행 트랙·장수 숫자 (`BuildSynergyPanel` / `BuildSynergyCell` 개편)

- 패널 위치·폭(우상단, 폭 170)·접기/펼치기·루트 클릭(→ `SynergyModalPopup`)은 **그대로**. 접힌 탭의 축 점 4개도 그대로(활성 Tier ≥ 1 이면 축 색).
- **행 구성**(높이 44, 현재 32 에서 확대): 

  | 줄 | 내용 |
  |---|---|
  | 1줄(22) | 축 아이콘 22×22(기존 `_axisIcon`) · 축 이름(`flex`) · 장수 텍스트(§2: `{c}/{N}` / `{c}/{N} T{t}` / `{c}+ T3`, 12px 축 색) |
  | 2줄(7) | `SynergyTrack` 7칸 (칸 너비 19px) |

  행 높이 검산 `5(상 패딩) + 22 + 4 + 7 + 5(하 패딩) = 43 ≤ 44`.
- 패널 총 높이 검산: `헤더 14 + 간격 6 + 4행 × 44 + 3간격 × 6 = 214 ≤ 현재 _expandedHeight 247` — 펼친 높이 247 **유지**.
- **상태 스타일**:

  | 조건 | 스타일 |
  |---|---|
  | `c = 0` | 행 전체 불투명도 0.55 (기존 흐림) |
  | `c ≥ 1` 이고 `t = 0` | **불투명도 1.0, 색띠 없음** (쌓는 중 — 기존에는 0.55 로 0장과 구분 안 됨) |
  | `t ≥ 1` | 불투명도 1.0 + 왼쪽 3px 축 색띠(기존) |
- 점멸: 장수가 늘면 새 칸 점멸(§2.1), Tier 돌파 시 기존 펄스 유지.
- 기존 3칸 점 마커(`_tierMarkers`)는 트랙 7칸으로 대체한다.

### 3.5 시너지 상세 모달 — 쌓는 중인 축 포함 (`SynergyModalPopup` 소폭 변경)

- 행 생성 조건을 "활성 Tier ≥ 1" 에서 **"장수 ≥ 1"** 로 넓힌다. 장수 1~2(Tier 0)인 축은 헤더 행 1개만 생성(효과 행 0개).
- Tier 0 헤더: 라벨 `{AXIS} ({c}장)`, 단계 배지 `0/3`, 현재 설명 `아직 발동 전`, 다음 미리보기는 기존 `다음: {Tier1 설명}` 형식 그대로.
- 빈 상태 문구: `아직 발동한 시너지가 없습니다` → `아직 쌓은 시너지가 없습니다`(모든 축 0장일 때만 표시).
- 정렬·효과 행 포맷·스크롤바·아이콘 정책은 `synergy-modal-popup.md` 그대로.
- 이 항목(§3.5)은 §3.1~3.4 와 독립적으로 구현·테스트할 수 있다(분할 가능 단위, §10 참고).

## 5. 페이싱 · 밸런스 영향

- **수치 변경 0**: 임계 3/5/7, Tier 효과, 카드 풀, 3픽 캡, 드로우 확률, 트리거 간격(패시브 HP 10% 구간 · 액티브 주기) 전부 무변경. 컨셉 §8 밸런싱 기준 영향 없음 → qa-simulator 시뮬 재실행 불필요(헤드리스 자동 픽은 UI 와 무관).
- **결정 시간**: 카드 선택창은 `_pause.Pause()` 로 일시정지 상태이므로 읽을 정보가 늘어도 전투 압박이 없다. 선택창 정보량은 카드당 띠 1개(3줄)이며, 위계 강조(§1.3 B)로 "읽지 않아도 보이는 것"(발동 카드 글로우)을 먼저 둔다.
- **의도된 행동 변화(검증 대상)**: 플레이어가 Tier 임계 직전 축(`k = 1` 인 진행 중 / 발동 상태 카드)을 더 많이 고른다. 이는 컨셉 §5.2 의 의도(시너지가 선택지에 자연스럽게 노출) 그대로이며, 과도한 쏠림(전 런 단일 축 고정)이 우려되면 카드 풀·임계 조정은 별도 밸런스 사이클(`project.md` 밸런스 조정 흐름)로 다룬다. 본 기획서는 그 조정을 하지 않는다.
- **검증 방법**: 사람 플레이 의존 가설이라 qa-simulator 로 측정할 수 없다. 수동 플레이 체크리스트는 §8 수용 기준 B 에 둔다. 정량 지표(Tier 2 이상 도달 런 비율)를 수집하려면 `RunSummary` 에 런 종료 시 축별 최종 장수를 기록해야 하는데, 이는 메타 저장 구조 변경이라 범위 밖으로 두고 §12 질문 3 으로 올린다.

## 10. 구현 분할 제안 (스코프 분해 점검 결과)

단일 기능("시너지 가시성")이나 표면이 5곳이라, 독립 구현·테스트 가능한 단위로 나누면 다음과 같다. 사용자가 원하면 분할 승인한다.

| 단위 | 범위 | 선행 |
|---|---|---|
| 1 | 공용 기반: `SynergyVisualConfig` SO·`EData` 값·진행 산식·`SynergyTrack` 위젯·문자열 300 블록 | 없음 |

| 4 | 빌드 바·빌드 상세 배지 (§3.3) | 1 |
| 5 | 시너지 모달 확장 (§3.5) | 없음 |

권장: 1 → (2+3) → 4 → 5 순. 요청의 두 축(아이콘 / 진행도)을 모두 만족하는 최소 단위는 **1+2+3+4** 이다.

## 11. 비범위 (YAGNI)

- 신규 JSON 데이터 스키마, 서버·저장 구조 변경.

## 12. 사용자 판단이 필요한 열린 질문

1. **카드 폭 210 → 230px, 일러스트 200 → 170px 변경 승인** — 띠를 넣기 위한 치수 변경이다. 일러스트가 잘려 보이는 정도가 허용되는지 목업의 카드 아트로 확인 필요. 대안: 띠를 일러스트 하단 오버레이로 얹어 카드 치수 무변경(일러스트 가려짐, 글자 가독성 하락).
2. **기존 두 곳(`BuildSynergyPanel`, `SynergyModalPopup`)의 Sprite 4필드를 이번에 SO 로 통합할지** — 기획 권장은 "이번엔 유지, 후속 정리"(회귀 위험 0). 통합하면 단일 진실이 되지만 기존 프리팹 2개를 건드린다.
3. **효과 측정 수단** — 정량 지표(Tier 2 이상 도달 런 비율)를 보려면 `RunSummary` 에 축별 최종 장수 기록이 필요하다(메타 저장 구조 변경). 이번에 포함할지, 수동 플레이 확인(§8 B)만으로 갈지.
4. **시너지 발동 토스트 도입 여부** — Tier 발동 순간의 화면 중앙 피드백은 card-renewal §8.4 에 계획만 있고 미구현이다. 본 기획에는 넣지 않았다(카드 띠 글로우 + HUD 펄스가 발동 신호를 맡는다고 판단). 발동 순간의 임팩트를 더 원하면 별도 기획.
5. **분할 승인** — §10 의 5단위 분할 중 이번에 어디까지 진행할지(권장: 1+2+3+4, 모달 확장 5 는 후속 가능).

## 13. 데이터 구조 확인 게이트 (Rule 00)

**신규 JSON 데이터 스키마(row 클래스): 없음.**

- 카드 28장·시너지 Tier·임계는 기존 SO/코드를 읽기만 한다.
- `Strings_Ko.json` 은 기존 `{ id, text }` 스키마에 행 9개(300~308)만 추가하므로 스키마 변경이 아니다.
- 신규 ScriptableObject 1종(Sprite 참조 보유라 SO 유지 — Rule 02 §11 예외)의 구조:

```
SynergyVisualConfig (SO, 에셋 1개 · EData.SynergyVisualConfig)
└─ Entries[4]                  ← 축마다 정확히 1개 (필수 1:1 관계 → 관계 데이터 분리 불필요, §11-1-3)
   ├─ Axis : EBuildAxis        ← 키 (Tank / Dps / Debuff / Swarm)
   └─ Icon : Sprite            ← SynergyIcons/{TANK,DPS,DEBUFF,SWARM}.png
```

- 핵심 엔티티: "축 하나의 표시용 아이콘". 선택적 관계·sentinel 값·복합 키 없음.
