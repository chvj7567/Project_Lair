## 0. 헤더

- **목표**: 마을 도감 팝업의 몬스터 탭을 "기준 몬스터 6칸"에서 **6종족 x 등급 5 x 티어 4 = 120칸**을 모두 보는 구조로 바꾼다. 모든 칸에 실제 이름(등급 접두어 + 기존 이름)을 보여 주되, 미해금 칸은 몬스터 그림만 검은 실루엣, 해금 칸은 컬러 + 등급 이펙트로 보여 주고, 새로 열린 칸은 등급색 해금 연출을 낸다.
- **검증 가설**: (1) 승급·강화 진척이 "열린 칸 수"로 한눈에 보이면 승급·강화를 더 하고 싶어지는가. (2) 실루엣 120칸이 수집 욕구를 만드는가. (3) 칸 20개에 등급 이펙트를 입혀도 가독성·성능(프레임)이 유지되는가(동시 애니 상한 8칸).
- **현재 단계 범위 적합성**: **범위 밖 -> 사용자 승인으로 승격 확정**(2026-11-09). 현행 §8 은 "UI 아이콘(상점·편성·도감 카드)에는 등급 이펙트를 표시하지 않는다"로 금지했으나, 사용자가 도감 몬스터 탭의 **상세 패널 + 매트릭스 칸**에 한해 허용하기로 결정했다. §8 에 추가할 승격 항목 초안은 **§12**. 신규 몬스터·신규 UI 화면·별도 메인 메뉴는 계속 금지(도감은 기존 마을 팝업 안).
- **핵심 메커니즘**: 해금은 저장 데이터 변경 없이 기존 값에서 파생한다(전투에서 만남 AND 종족 보유 최고 등급 >= g AND 강화 티어 >= t). 칸은 등급 5행 x 티어 4열 매트릭스(선택 종족 1개 = 20칸)이고 오른쪽 상세 패널이 큰 미리보기(쇼케이스 프리팹 -> RenderTexture)와 능력치 배율·해금 조건을 보여 준다.

## 3. 해금 규칙·산식

```
race ∈ 6 기준 몬스터(Wisp/Wraith/Reaper/Hex/Plague/Phantom)
seen(race)   = profile.SeenMonsters 에 기준 몬스터 이름 포함
G(race)      = profile.GetRaceGrade(race 의 ERace)            1~5
Lv(race)     = profile.GetShopLevel("Enhance_" + 기준 몬스터)  0~5 (범위 밖은 0~5 로 클램프)
T(race)      = [0,1,1,2,2,3][Lv]
open(race,g,t) = seen(race) AND g <= G(race) AND t <= T(race)
```

- 칸 수: 종족당 5 x 4 = 20, 전체 6 x 20 = 120. "수집 n / 120" = 열린 칸 합. 종족 칩 "n/20".
- 티어 t 의 강화 Lv 조건: T1 = Lv1, T2 = Lv3, T3 = Lv5 (표기는 Lv 범위 Lv1~2 / Lv3~4 / Lv5).
- 이름: 해금 칸 = 해당 등급 몬스터의 `SpeciesVisual.MonsterName`(등급 접두어 + 기존 이름, 접두어 키 `Grade.prefixKey` 1511~1515). 칸의 (종족, 등급)에 대응하는 `EMonster` 는 `FormationDatabase`/`Race_Monster` 에서 조회. **미해금 칸도 같은 실제 이름을 표시한다**(흐린 색 `#7d879f`, "???" 없음). 가리는 것은 몬스터 그림(검은 실루엣)과 능력치뿐이다.
- **스포일러 수용(사용자 결정, 2026-11-09)**: 미해금 칸의 이름 노출로 아직 못 얻은 등급 이름(예: 군주 도깨비불)이 미리 알려지는 것을 수용한다. 모든 등급 이름이 보여 목표 수집 대상이 명확해지는 쪽을 택했다.
- 몸 시트: 티어 0 = 풋내기 시트, 티어 1~3 = `MonsterTierSheetSet`(`EMonsterTierSheet`). 티어는 종족 공통이라 같은 티어의 모든 등급 칸이 같은 시트를 쓴다.
- 단조성: 승급·강화는 되돌림 금지라 한 번 열린 칸은 닫히지 않는다. 클라우드 복원 등으로 값이 낮아지면 칸은 파생 규칙대로 다시 닫히고(저장 데이터에 열림 기록이 없으므로) 별도 처리 없음.

### 3.1 미해금 칸 상호작용

잠금 칸을 눌러도 선택은 된다. 상세는 검은 실루엣(이펙트 없음) + **실제 이름(등급 접두어 + 기존 이름)** + 능력치 비공개 + "해금 조건" 목록을 보여 준다. 조건은 해당하는 것만 표시하고 줄마다 충족/미충족을 색(충족 `#5ef0b4` / 미충족 `#e5484d`)과 말머리로 구분한다.

| 조건 줄 | 표시 대상 | 충족 판정 |
|---|---|---|
| 전투에서 이 종족을 만난다 | 항상 | `seen(race)` |
| {등급명} 승급 (상점 몬스터 강화, 지금 {보유 최고 등급명}) | g > 1 | `G(race) >= g` |
| 강화 Lv{필요 Lv} 도달 -> {티어명} (지금 Lv{현재 Lv}) | t > 0 | `T(race) >= t` |

하단 문구: "능력치는 해금하면 공개됩니다".

## 5. 등급 이펙트 (승격 확정 범위)

### 5.1 등급별 구성 (상세·칸 공통, `monster-grades.md` 연출 규칙 그대로)

| 등급 | 크기 | 몸 외곽 발광 | 바닥 오라 | 불꽃 기둥 | 뒤 후광 | 몸 밝기 맥동 |
|---|---|---|---|---|---|---|
| 1 풋내기 | x1.000 | - | - | - | - | - |
| 2 견습 | x1.075 | O | O | - | - | - |
| 3 숙련 | x1.150 | O | O | - | - | - |
| 4 정예 | x1.225 | O | O | 몸 양옆 2개 | - | - |
| 5 군주 | x1.300 | O | O | 4개 | 햇살 후광 | O |

이펙트 색은 종족색 팔레트(현재 6종 임시안은 같은 이펙트의 색만 바뀜, 종족별 차별화는 후속). 티어(T1~T3) 시트 전환과 함께 동작한다(몸 시트만 교체, 이펙트는 등급 기준).

### 5.2 상세 큰 미리보기

- 전투 쇼케이스와 같은 방식으로 `sizeMul`·이펙트를 그대로 쓴다(상세는 배율 x1.000~1.300 상대 비교 가능).
- 쇼케이스 프리팹을 도감 전용 카메라로 찍어 RenderTexture 에 그린다(§6.3). 신규 에셋 없음.

### 5.3 매트릭스 칸

- 칸은 RenderTexture 를 쓰지 않는다. 몸 = 티어 시트 대기(Idle) 첫 프레임 1장(UI Image) x 크기 배율(§2). 이펙트 = 기존 등급 이펙트 시트(`{Name}_aura`·`_g4`·`_g5`)를 UI Image 프레임 스왑으로 재생.
- 몸 외곽 발광은 몸 Image 뒤에 종족색 가산 틴트 복제 Image(블러 불가 시 1.08 배 확대 복제)로 근사한다. 정확한 UI 구현은 gameplay-programmer 가 정하되 §8 의 "신규 에셋 없음"을 지킨다(기존 가산 머티리얼·이펙트 시트 재사용).
- 잠금 칸은 몸을 검은 실루엣(`brightness 0` + 옅은 테두리)으로만 그린다. 이펙트 없음.
- 1등급 칸은 효과 없음(카운터 소비 없음).

| 우선순위 | 상세 미리보기 1개 -> 매트릭스에서 등급 높은 칸 -> 같은 등급이면 티어 낮은 칸 (2등급 이상 해금 칸만 후보) |
| 슬롯 계산 | 칸 1개 = 슬롯 1(그 칸의 이펙트 세트). 상세는 상한 8 과 별도로 **먼저 확보**하고 칸 상한에는 포함하지 않는다 |
| 초과 칸 | 정지 프레임: 발광·오라·기둥·후광은 첫 프레임으로 고정해 보이되 움직이지 않음, 맥동 없음 |
| 쇼케이스 공유 | 도감 칸의 이펙트 애니는 `GradeFxBudget` 의 기존 슬롯 풀(Aura / Tornado / Sunburst)에서 슬롯을 받는다. 즉 마을 쇼케이스가 쓰는 슬롯과 같은 카운터를 공유하고, 도감 `fxLiveCap` 과 풀 상한을 **둘 다 통과해야** 애니. 하나라도 실패하면 정지 프레임 |
| 반환 | 팝업 닫힘·탭 전환·종족 전환 시 모든 슬롯 반환 |

후보 개수 예: 선택 종족이 군주 G5·T3 전부 열렸다면 2등급 이상 칸 16개 중 상한 8칸만 애니(5등급 4칸 + 4등급 4칸), 나머지 8칸은 정지 프레임.

## 6. 연출·NEW 배지

### 6.1 해금 색 연출 (등급색)

| 등급 | 등급색 | 펄스 횟수 | 퍼짐 px | 링 | 스파클 | 글로우 px |
|---|---|---|---|---|---|---|
| 1 풋내기 | `#9aa5bd` | 1 | 4 | 0 | 0 | 2 |
| 2 견습 | `#5aa9ff` | 1 | 6 | 1 | 4 | 5 |
| 3 숙련 | `#b07cff` | 2 | 8 | 1 | 8 | 8 |
| 4 정예 | `#f7c64a` | 3 | 10 | 2 | 12 | 12 |
| 5 군주 | `#ff7a45` | 4 | 14 | 3 | 18 | 16 |

- 몸: 검은 실루엣 -> 컬러 페이드 1.4초(중간 45% 시점에 글로우 최대). 테두리 펄스 1회 0.7초. 링 0.9초(펄스 사이 간격 0.25초 x 링 번호). 스파클 0.9초(시작 0.5초 지연).
- **칸용 축소**: 펄스 `min(펄스,2)`, 링 `min(링,1)`, 스파클 `min(스파클,8)`(퍼지는 거리 34px). 해금 연출 중인 칸의 등급 이펙트 레이어는 1.4초 뒤 0.6초 동안 서서히 켜진다.
- **상세는 전체 강도**(위 표 그대로)로 재생한다. 재생 시점은 §6.2 의 새 칸 재생이며, 선택된 칸이 신규일 때만 상세 미리보기에도 같이 재생한다.
- 칸 간 스태거 0.15초. 신규 칸 최대 20개 = 최대 3.0초(20x0.15).

### 6.2 NEW 배지와 재생 시점 (세션 한정)

- 세션 스냅샷: 앱 실행 후 **마을이 처음 로드될 때** 종족별 "열린 칸 집합"을 메모리(정적)에 기록한다. 저장하지 않는다(MetaProfile 버전 불변). 앱을 다시 켜면 스냅샷은 새로 잡히므로 이전 세션에 열린 칸은 NEW 가 아니다.
- 신규 칸 = 현재 `open` 집합 - 스냅샷. 도감 오픈 시 초기 선택 종족 = 신규 칸이 있는 첫 종족(종족 순서 Wisp~Phantom), 없으면 Wisp. 초기 선택 칸 = 선택 종족의 최고 해금 칸(등급 높은 것, 같으면 티어 높은 것).
- 종족이 화면에 나타날 때(오픈 시 선택 종족, 이후 종족 칩 전환 시) 그 종족의 신규 칸에 §6.1 연출을 재생하고, **재생한 종족의 스냅샷을 즉시 현재 값으로 갱신**한다. 보지 않은 종족은 스냅샷이 그대로라 다음에 열 때도 신규로 남는다.
- NEW 표시: 신규 칸 우상단 "NEW" 배지(24x14, 금색 배경 `#f7c64a` 글자 `#10141d`, 칸 연출 재생과 함께 표시) - 재생한 팝업이 닫힐 때까지 유지(`_newThisOpen` 팝업 수명 집합). 아직 보지 않은 종족의 종족 칩에는 NEW 점(10px 금색)을 둔다.
- 해금 연출은 도감을 열 때만 재생한다(마을에서 승급·강화 직후 실시간 팝업 알림 없음).

## 11. 구현 요청사항 (gameplay-programmer 용)

- **Enum**: `EData` 에 `CodexConfig`, `Grade_CodexUnlock` 추가(JSON 에셋 키, Rule 03 §2 파일명 = 값명). `EUI` 변경 없음(기존 `CodexPopup` 유지). 신규 몬스터·에셋 Enum 없음.
- **Interface**: 필수 없음. 도감 칸 슬롯 확보용 추상화가 필요하면 `GradeFxBudget` 소비 경계를 테스트 더블이 가능하게 둘 것(Rule 02 §9).
- **에셋 키**: 신규 프리팹 `CodexMonsterCell.prefab`(`Assets/_Lair/Art/UI/`, 매트릭스 칸) 1개. 기존 `CodexPopup.prefab` 수정(목업 승인 후 배선 - UI 목업 게이트 통과). 그 외 신규 에셋 없음(티어 시트·등급 이펙트 시트·가산 머티리얼·쇼케이스 프리팹 재사용).
- **데이터 스키마(구조 확인 게이트 대상, 아래 구조표)**: `CodexConfig`·`Grade_CodexUnlock`(JSON, `Assets/_Lair/Data/Json/`).
- **문자열**: UI 라벨용 신규 문자열(예: "해금 조건", "전투에서 이 종족을 만난다", "{등급명} 승급 (상점 몬스터 강화, 지금 {등급명})", "강화 Lv{n} 도달 -> {티어명} (지금 Lv{n})", "능력치는 해금하면 공개됩니다", "수집 n / 120", "이 종족 n / 20", "NEW", "HP · 공격력 x{n}", "강화 외형 {티어}") 를 기존 `CHText.StringProvider` 문자열 표에 추가. ID 부여는 표의 기존 규칙을 따른다.
- **MetaProfile**: 변경 없음(버전 불변). `CodexLockedSlots` 제거로 `MetaConfig` 필드·값 정리.
- **금지**: 칸/상세 외 위치(상점·편성·카드 탭·결과창)에 등급 이펙트 표시 금지, 몸 시트 신규 제작 금지, 신규 몬스터 금지.

### 11.1 데이터 구조표

```
Grade (기존, Grade.json) ── 핵심 엔티티: 등급 하나. sizeMul·hpMul·atkMul·prefixKey 보유
```

| `pulseCount` | int | 테두리 펄스 횟수 | 1 / 1 / 2 / 3 / 4 |
| `spreadPx` | int | 펄스 퍼짐 | 4 / 6 / 8 / 10 / 14 |
| `ringCount` | int | 링 수 | 0 / 1 / 1 / 2 / 3 |
| `sparkCount` | int | 스파클 수 | 0 / 4 / 8 / 12 / 18 |
| `glowPx` | int | 글로우 반경 | 2 / 5 / 8 / 12 / 16 |
