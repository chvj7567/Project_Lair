## § 헤더

- **목표**: 상점 몬스터 강화 외형(T1~T3)을 "몸 위에 덧그리는 파츠 시트"에서 **"몸 시트 전체를 통째로 교체하는 전신 강화 시트"**로 바꾼다. 종족마다 몸 시트는 풋내기(기본) + T1 + T2 + T3 네 장이다.
- **검증 가설**: (1) GPT 가 그린 전신 T 시트가 덧그림 파츠보다 화풍이 맞고 강화 단계가 한눈에 구분되는가. (2) 전신 시트에 프레임 흔들림이 거의 없어 실사용 가능한가(확인됨: 흔들림 거의 없음). (3) 얼굴(눈) 기준으로 월드 크기를 맞추면 단계가 바뀌어도 몬스터가 갑자기 커지거나 점프해 보이지 않는가.
- **현재 단계 범위 적합성**: **범위 안**(§8 "아트/에셋 작업 허용"). 신규 몬스터·카드·수치 변경 0. 강화 레벨 → 티어 매핑·바닥 링·발광 곡선은 불변이다.
- **핵심 메커니즘**: 강화 레벨 → 티어 [0,1,1,2,2,3] 매핑은 그대로이고, 티어가 정해지면 몬스터 몸 렌더러의 스프라이트를 **같은 인덱스(행 x 6 + 열)의 해당 티어 시트 스프라이트로 치환**한다(기존 덧그림 렌더러·`Enhance` 자식은 쓰지 않는다). 시트마다 PPU 를 따로 두어 **얼굴(두 눈) 기준의 월드 크기·위치가 풋내기와 같게** 맞춘다. 모자·왕관·망토·날개 같은 장식만 얼굴 밖으로 뻗는다.

## 3. 월드 크기·위치 정합 (T3, T4, T5)

풋내기 시트(이미 192 규격·PPU 확정)를 기준으로, 각 T 시트가 같은 얼굴 크기·위치를 갖도록 시트별 PPU 와 이동을 정한다. 아래 모든 측정은 **대기 F0** 에서 한다.

| 기호 | 정의 |
|---|---|
| `eB`, `eT` | 풋내기·T 시트(192 셀 변환 후)의 두 눈 중심 간격(px) |
| `mB`, `mT` | 두 눈 중심점의 위치(px, 셀 좌하단 원점) |
| `PPU_B` | 풋내기 몸 PPU(`monster-sheet-v4.md` §1 값) |
| `s_fit` | 셀 안 크기 맞춤 균일 축소(기본 1.00, 필요 시 0.85~1.00) |

산식:

1. 풋내기의 눈 간격 월드 길이 `eW = eB ÷ PPU_B`(u), 눈 중심의 발 기준 월드 좌표 `(xW, yW) = ((mB.x − 96) ÷ PPU_B, mB.y ÷ PPU_B)`(u).
2. T 시트 PPU: `PPU_T = (eT x s_fit) ÷ eW`. (이미지를 s_fit 만큼 줄였다면 T 눈 간격도 그만큼 줄어 PPU 도 같은 비율로 낮아진다.)
3. T 시트 이동(정수 px): 눈 중심이 `x = 96 + xW x PPU_T`, `y = yW x PPU_T`(셀 바닥 기준)에 오도록 시트 전체를 같은 이동으로 옮긴다(프레임별 이동 없음).
4. 결과: **풋내기와 T 시트를 교체해도 얼굴 크기·위치가 같다**(단계가 바뀔 때 점프·확대 없음). 몸 둘레 장식만 달라진다.
5. 정합 판정: `eT`와 `eB` 를 같은 월드 단위로 환산한 비의 차이가 12% 이내(= PPU_T 산출 전 단계의 사전 검사: 그림 자체의 얼굴 크기 차). 12% 를 넘으면 장식이 아니라 몸이 커진 것으로 보고 **재생성**.

규칙(전 단계 공통):

| 규칙 | 값 | 위반 시 |
|---|---|---|
| 전체 월드 높이 ≤ 풋내기 월드 높이 x 1.55 (대기 F0, 불투명 bbox) | 구 T3 최대 +53%(환령 19 -> 29 texel)에 맞춤 | 재생성 |
| 전체 월드 폭 ≤ 풋내기 월드 폭 x 1.60 | 날개·망토 확장 허용 | 재생성 |
| 셀 가장자리 여백 | 모든 프레임에서 불투명(알파 ≥ 24) 픽셀이 가장자리 8px 이상 안쪽(밉맵 번짐 방지) | s_fit(T5), 0.85 미만이면 재생성 |
| 몸 바닥 | 대기 F0 최대 성분(몸통) 밑단이 발 기준 월드 높이 0(= 부유 0.042u 이내) | 정합 기준(눈)을 우선, 바닥 편차가 0.08u 를 넘으면 사용자 보고 |

**HP바 높이**: 티어별 `heightWorld[t] = 대기 F0 최상단의 발 기준 월드 높이(= (192 − 최상단 y 에서의 높이 px) ÷ PPU_T) + 0.08`. 기존 `_hpBarHeightByTier` 표(`monster-2d-conversion.md` §6.3.7)는 덧그림 기준이었으므로 **값이 바뀐다**. 값은 추출 도구가 `Monster_SheetSpec.json` 의 `hpBarHeights[4]` 에 기록한다. 등급 크기 배율이 곱해지는 규칙은 `monster-grades.md` §4.

## 5. 발광 마스크 생성

풋내기 규칙(`monster-sheet-v4.md` §5.2)을 T 시트에 그대로 돌리고, 티어에서 새로 생긴 빛나는 부위를 더한다. 마스크는 연속값(0~255), 대기 F0 면적비 5~20%(X7).

| 종족 | 티어 추가 발광 부위 (v5 육안 관찰 기준, 최종은 육안 검수) | 발광 아닌 것 | 수동 보정 지점 |
|---|---|---|---|
| Wisp | T2~T3: 왕관 중앙 보석(녹색), T3: 몸 곁 떠다니는 작은 불방울(몸에서 떨어진 소성분) | 금 왕관 본체 | 불방울 위치가 프레임마다 흔들리므로 소성분 자동 검출 실패 시 ROI |
| Wraith | T1~T3: 가슴 마름모 룬(기존), T2~T3: 이마 왕관 보석 | 금 갑주·뿔 | 사망 연기 프레임 룬 |
| Reaper | T1~T3: 붉은 눈, 낫 날 안쪽 | 금 어깨 갑주 | 낫 회전 프레임마다 날 검출 |
| Hex | T1~T3: 구슬·반짝이 다이아몬드, T2~T3: 배의 별 문장 | 금 별 테두리 | 반짝이와 로브 하이라이트 구분(ROI) |
| Plague | T1~T3: 기포, T2~T3: 왕관 보석 | 금 왕관 본체 | 기포/하이라이트 구분(ROI) |
| Phantom | T1~T3: 청백색 눈, T2~T3: 왕관 보석 | 금 왕관·발톱 | 없음 |

- 금색 장식(왕관·갑주·뿔 도금)은 발광하지 않는다(빛은 보석·눈·불방울에만 -> 강화 발광 곡선이 장식 전체를 뭉개지 않게).
- 마스크 보정 지시(`maskOverrides`)는 추출 도구 입력이며 커밋하지 않는다.

## 6. 프리팹·코드 영향 범위 (읽기 전용 점검 결과)

기존 덧그림 구조: 몬스터 프리팹 `Visual2D` -> `Enhance` 자식(SpriteRenderer + `MonsterTierOverlay`) -> `MonsterEnhancementVisual` 이 레벨 -> 티어 선택(`SetTier`)과 `_renderers`(몸 + Enhance)·HP바 높이를 관리.

| 대상 | 변경 | 비고 |
|---|---|---|
| `MonsterTierOverlay` | **영웅이 공유**(`_tier4Frames` = 영웅 스테이지 5, `hero-2d-conversion.md` §6.4). 몬스터용은 "덧그림 렌더러 켜기" 대신 "몸 렌더러 스프라이트 치환"이 필요 -> **몬스터용 별도 동작이 필요**. 영웅 경로는 건드리지 않는다 | 구현 방식(기존 클래스 확장 vs 몬스터 전용 신규)은 gameplay-programmer 판단. 영웅 오버레이 동작 회귀 테스트 필수 |
| `MonsterEnhancementVisual` | 티어 적용이 "오버레이 SetTier" -> "몸 스프라이트 치환 티어 설정"으로. `_renderers` 에서 Enhance 제거. `_hpBarHeightByTier` 값 갱신(§3) | `ApplyLevel(int, EMonster)` 시그니처·호출 시점 불변 |
| `HitFlash` | 렌더러 캐시(`Awake`)가 Enhance 자식을 더 이상 포함하지 않는 것만 확인. 로직 변경 없음 | 몸 렌더러 하나만 플래시 |
| 프리팹 6종 | `Visual2D/Enhance` 자식 삭제, 티어 배열(`_tier1Frames` 등)을 T 시트 스프라이트(36개)로 재배선 | G2~G5 Variant 는 기준 프리팹을 따름(`monster-grades.md` §8) |
| 클립·컨트롤러 | 변경 없음(풋내기 시트 스프라이트 참조 유지). Spawn 클립 없음 | 티어별 클립 세트 만들지 않음(T2) |
| 임포트 | T 시트·마스크 36장 재슬라이스 192(6x6), PPU 시트별(SheetSpec), 밉맵·Bilinear·ASTC(`monster-sheet-v4.md` §4.5) | 풋내기와 같은 설정 |
| 기존 테스트 | `MonsterTierOverlaySyncTests`(합성 스프라이트, 영웅 공유 코드 검증)는 영웅 경로 유지 시 통과. 몬스터 치환 동작 테스트 신규 필요 | test-engineer |

## 7. 용량·메모리 (추정, 실측으로 덮어씀)

몬스터당 몸 시트 4 + 마스크 4 = 8장, 장당 1.327M px.

| 구분 | 6종 픽셀 | ASTC 6x6(시트 0.444B/px) · 마스크 ASTC 8x8(0.25B/px) | 밉맵 x1.33 |
|---|---|---|---|
| 몸 시트 4장 x 6종 | 31.85M | 14.1MB | 18.8MB |
| 몸 마스크 4장 x 6종 | 31.85M | 8.0MB | 10.6MB |
| 소계 | 63.7M | 22.1MB | **29.4MB** |

- 덧그림 방식(`monster-sheet-v4.md` §10.3 합계 25.7MB: 시트·마스크에 6x5 덧그림 포함)과 비교해 T 시트가 6x6 전신이라 합계가 25.7MB -> 29.4MB 로 늘어난다(+3.7MB). 등급 이펙트(`monster-grades.md` §9.4)를 더한 총합 상한 50MB 는 그 문서에서 정한다.
- 한 몬스터는 풋내기 + T1~T3 시트 4장을 **모두 로드**(티어가 판마다 바뀌므로). 판 시작 시 확정 티어만 로드하는 최적화는 Addressables 변종이 필요해 이번 범위 밖(Q4).

## 8. 데이터 구조표 (Rule 00 데이터 구조 확인 게이트)

- **게임 JSON 스키마 변경: 없음.**
- 아트 매니페스트 `Monster_SheetSpec.json`(`monster-sheet-v4.md` §8)에 T 시트 필드를 추가한다:

```
Monster_SheetSpec.monsters[].tiers[3]   "강화 티어 하나" (T1~T3, 필수 1:1: 모든 종족이 3티어를 가짐)
  |-- tier(1~3), sheet "<Name>_Sheet_T<n>"
  |-- ppuTier, sFit, offset[dx,dy], eyeDistHD, eyeMidHD[x,y]
  |-- hpBarHeight (월드 u, +0.08 포함)
  +-- measured { worldHeightRatio, worldWidthRatio, silhouetteGain, protrusion, minEdgeMargin, removedSpecks, neonPixels }
```

- 삭제: `monsters[].topY`(덧그림 기준 4값), `monsters[].ppuOverlay`·`floatPxOverlay`(덧그림 PPU), `overrides.anchorOverrides`(파츠 앵커).
