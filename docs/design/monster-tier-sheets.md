## § 헤더

- **목표**: 상점 몬스터 강화 외형(T1~T3)을 "몸 위에 덧그리는 파츠 시트"에서 **"몸 시트 전체를 통째로 교체하는 전신 강화 시트"**로 바꾸고, 모든 몸 시트에서 **Spawn(등장) 행을 삭제**(5행)하며, 강화 T 시트는 **전투 시작 때 필요한 (종족, 티어)만 불러와** 메모리를 줄인다.
- **검증 가설**: (1) GPT 가 그린 전신 T 시트가 덧그림 파츠보다 화풍이 맞고 단계가 한눈에 구분되는가(프레임 흔들림 거의 없음 확인). (2) 얼굴(눈) 기준 월드 정합으로 단계가 바뀌어도 점프가 없는가. (3) 필요한 티어만 로드해도 로딩 구간·풀 워밍·실패 처리가 안정적인가.
- **현재 단계 범위 적합성**: **범위 안**(§8 "아트/에셋 작업 허용"). 신규 몬스터·카드·수치 변경 0. 강화 레벨 → 티어 매핑·바닥 링·발광 곡선 불변.
- **핵심 메커니즘**: 강화 레벨 → 티어 [0,1,1,2,2,3] 은 그대로. 티어가 정해지면 몬스터 몸 렌더러의 스프라이트를 **같은 인덱스(행 x 6 + 열)의 해당 티어 시트 스프라이트로 치환**한다. 시트마다 PPU 를 따로 두어 **얼굴(눈) 기준 월드 크기·위치가 풋내기와 같게** 맞춘다. 풋내기 시트는 프리팹이 직접 참조해 항상 로드, T 시트는 프리팹이 참조하지 않고 **전투 시작 로딩 구간에서 필요한 것만 Addressables 로 로드**, 전투 종료 시 해제한다.

## 3. 월드 크기·위치 정합 (T3, T4, T5)

풋내기 시트(이미 192 규격·PPU 확정)를 기준으로, 각 T 시트가 같은 얼굴 크기·위치를 갖도록 시트별 PPU 와 이동을 정한다. 측정은 **대기 F0**.

| 기호 | 정의 |
|---|---|
| `eB`, `eT` | 풋내기·T 시트(192 셀 변환 후) 두 눈 중심 간격(px) |
| `mB`, `mT` | 두 눈 중심점의 위치(px, 셀 좌하단 원점) |
| `PPU_B` | 풋내기 몸 PPU(`monster-sheet-v4.md` §1) |
| `s_fit` | 셀 안 크기 맞춤 균일 축소(기본 1.00, 필요 시 0.85~1.00) |

1. 풋내기의 눈 간격 월드 길이 `eW = eB ÷ PPU_B`(u), 눈 중심의 발 기준 월드 좌표 `(xW, yW) = ((mB.x − 96) ÷ PPU_B, mB.y ÷ PPU_B)`(u). (셀 높이가 960/5 = 192 이므로 바닥 기준 y 계산은 6행 때와 같다.)
2. `PPU_T = (eT x s_fit) ÷ eW`.
3. T 시트 이동(정수 px): 눈 중심이 `x = 96 + xW x PPU_T`, `y = yW x PPU_T`(셀 바닥 기준)에 오도록 시트 전체를 같은 이동으로 옮긴다.
4. 결과: 풋내기 ↔ T 교체 시 얼굴 크기·위치 동일(점프·확대 없음), 장식만 달라진다.
5. 정합 판정: 그림 자체의 얼굴 크기 차(`eT`를 같은 월드 단위로 환산한 비)가 12% 이내. 초과 시 **재생성**.

| 규칙 | 값 | 위반 시 |
|---|---|---|
| 전체 월드 높이(대기 F0 불투명 bbox) | ≤ 풋내기 x 1.55 | 재생성 |
| 전체 월드 폭 | ≤ 풋내기 x 1.60 | 재생성 |
| 셀 가장자리 여백 | 모든 프레임에서 불투명(알파 ≥ 24) 픽셀이 가장자리 8px 이상 안쪽 | s_fit(T5), 0.85 미만 재생성 |
| 몸 바닥 | 최대 성분 밑단이 발 기준 월드 높이 0(부유 0.042u 이내) | 눈 정합 우선, 편차 0.08u 초과 시 사용자 보고 |

**HP바 높이**: `heightWorld[t] = 대기 F0 최상단의 발 기준 월드 높이 + 0.08`(티어 3개 값). 기존 `_hpBarHeightByTier` 표(덧그림 기준)는 값이 바뀌며, 추출 도구가 `Monster_SheetSpec.json` 의 `tiers[].hpBarHeight` 에 기록하고 `MonsterTierSheetSet.hpBarHeightWorld` 에 복사된다. 풋내기(티어 0) 값은 기존 표(0.747 / 1.434 / 1.038 / 0.934 / 0.643 / 0.538) 불변. 등급 크기 배율 곱은 `monster-grades.md` §4.

## 7. 티어 시트 로드 정책 (D7)

### 7.1 무엇을 언제 로드하나

- **풋내기 시트**: 몬스터 프리팹이 직접 참조 → 프리팹과 함께 항상 로드(현행 풀 워밍 그대로).
- **T 시트**: 전투 시작 직전 **로딩 구간**(영웅·몬스터 프리팹 로드와 풀 워밍을 `await` 하는 기존 구간, 첫 스폰·타이머 시작 이전)에서 로드한다.
- 필요 목록 산출(순서):
  1. 출격 편성에서 6 종족 둥지의 몬스터를 읽고 각각 **기준 몬스터**(= 종족 1등급, `monster-grades.md` §6)로 환산(등급 몬스터는 기준 몬스터의 강화 Lv 를 이어받으므로 종족당 하나).
  2. 상점 강화 상태에서 기준 몬스터별 강화 Lv(`Enhance_<EMonster>`, 전투 시작 스냅샷)를 읽어 티어 `[0,1,1,2,2,3][Lv]` 계산.
  3. 티어 > 0 인 종족만 `EMonsterTierSheet` 키(§7.2)를 만든다. **종족당 최대 1개 → 한 판 최대 6개**(종족당 base 1 + T 1).
  4. 키들을 병렬(`Task.WhenAll`)로 `CHMResource.LoadAsync<MonsterTierSheetSet>(key)`.
  5. 결과를 전투 범위 레지스트리(`(기준 몬스터, 티어) → 세트`)에 등록한 뒤 **몬스터 풀 워밍**과 첫 스폰을 진행한다. (워밍은 프리팹만 필요하므로 3~4와 병렬 가능, 단 첫 `Pop` 전에 레지스트리가 준비돼야 한다.)
- 모든 전투 모드(챕터·무한의 탑·데일리)가 같은 시작 루틴을 쓴다. 판 도중 강화 Lv 는 바뀌지 않는다(스냅샷 규칙 유지)라 도중 추가 로드는 없다.

### 7.3 실패 처리

| 상황 | 처리 |
|---|---|
| 로드 결과 null(키 없음·번들 실패) | **1회 재시도**. 다시 실패하면 그 종족은 **티어 0(풋내기)로 폴백**하고 레지스트리에 등록하지 않음. 경고 로그 1줄(종족·티어). 전투는 계속 진행(차단 없음, 사용자 알림 없음) |
| 폴백 종족의 연출 | 외형만 풋내기. 발광 곡선·바닥 링·강화 효과 수치는 강화 Lv 그대로(수치 불변). HP바 높이도 티어 0 값 |
| 로딩 시간 초과 | 5초(로컬 번들 기대 시간은 수백 ms 이하, 측정 후 조정) 초과 시 아직 미완료인 종족을 위 폴백으로 처리하고 이후 늦게 도착한 결과는 해제 |

| 헤드리스 시뮬(qa-simulator) | 로드 실패 시 폴백으로 동작해 외형 무관하게 통과(전투 수치 불변) |

### 7.4 풀 워밍·State Reset 연동

- 몬스터 프리팹 풀은 현행과 같이 `CHMPool.CreatePool`(종족별 워밍 수량 불변). 프리팹이 T 시트를 참조하지 않으므로 워밍·Pop 비용이 티어에 무관하다.
- 한 판에서 종족의 티어는 고정이므로 풀 인스턴스는 모두 같은 티어를 쓴다. Pop(`OnEnable`) 리셋: 티어 0(풋내기 스프라이트) → `ApplyLevel(level, species)` 가 레지스트리에서 세트를 조회해 티어 적용(없으면 0 유지).
- 풀 인스턴스는 전투 종료 시 정리되고, 스프라이트 참조가 남지 않게 렌더러 스프라이트를 풋내기로 되돌린 뒤 해제한다.

### 7.5 해제

- **전투 종료 → 몬스터 풀 정리(Push/Destroy 완료) → `CHMResource.Unload(key)`** 순서로, 이번 판에 로드한 키 목록을 전부 해제한다. 결과창이 떠 있는 동안 몬스터가 화면에 남아 있으면 그 시점에는 해제하지 않고 **씬 전환(마을 복귀·재도전) 직전**에 한다.
- 재도전은 필요 집합을 다시 계산해 다시 로드한다(캐시 핸들이 이미 해제됐으므로 재로드).
- 마을(상점·편성)에서는 T 시트를 로드하지 않는다(UI 는 기존 아이콘 6장).

- 등급 이펙트(`monster-grades.md` §9.4 최악 16.9MB)를 더한 **전체 최악 약 29.1MB**. 총량 상한은 **35MB(밉맵 포함, 몬스터 시트 + 이펙트)**로 정한다(`monster-grades.md` §9.4·U8 갱신).
- 해제 시 번들 단위로 반환되므로 전투 사이에 누적되지 않는다.

## 8. 데이터 구조표 (Rule 00 데이터 구조 확인 게이트)

- **게임 JSON 스키마 변경: 없음.** 신규 데이터는 아트 매니페스트(편집기 전용)와 ScriptableObject(스프라이트 참조가 필요해 JSON 불가, Rule 02 §11 SO 예외).

```
Monster_SheetSpec (아트 매니페스트, 루트 1개 - 변경점만)
 |-- rows 5            (신규: rowsBody·rowsOverlay 대체), cell 192, 시트 1152x960
 |-- outRowOrder ["idle","move","attack","hit","death"]   (spawn 삭제)
 |-- source { fileSuffix, cols 6, rows 6, cell 229, srcRowOrder 원본 6행 유지, discardRows ["spawn"] }
 +-- monsters[6]
       +-- tiers[3]  "강화 티어 하나" (필수 1:1)
             |-- tier(1~3), sheet "<Name>_Sheet_T<n>", ppuTier, sFit, offset[dx,dy], eyeDistHD, eyeMidHD[x,y]
             |-- hpBarHeight
             +-- measured { worldHeightRatio, worldWidthRatio, silhouetteGain, protrusion, minEdgeMargin, removedSpecks, neonPixels, manualEdits }

MonsterTierSheetSet (ScriptableObject, 종족·티어당 1, 18개 - Addressable, 키 = EMonsterTierSheet)
 |-- frames        Sprite[30]  (인덱스 = 행*6+열, 이름 끝 숫자 = 인덱스)
 +-- hpBarHeightWorld float    (이 티어 대기 F0 최상단 + 0.08, SheetSpec.hpBarHeight 와 같음)
```

| 필드 | 타입 | 값 |
|---|---|---|
| `Monster_SheetSpec.rows` | int | 5 |
| `Monster_SheetSpec.source.discardRows` | string[] | `["spawn"]` |
| `MonsterTierSheetSet.frames` | Sprite[] | 길이 30, 인덱스 0~29 |
| `MonsterTierSheetSet.hpBarHeightWorld` | float | §3 식 |

- 삭제된 매니페스트 필드: `rowsBody`·`rowsOverlay`, `topY`, `ppuOverlay`, `floatPxOverlay`, `overrides.anchorOverrides`, `outRowOrder` 의 `spawn`.
- 같은 `EMonster` 순회 지점 점검: 종족 단위 목록은 `Race`/기준 몬스터 기준(등급 몬스터가 끼어들지 않게).

## 11. 구현 요청사항 (gameplay-programmer 용)

### Enum / Interface / 에셋 키 / SO
- **Enum**: `EMonsterTierSheet`(18값, §7.2)을 `CommonEnum.cs` 에 추가.
- **Interface**: 신규 1개 권장 - 전투 범위의 티어 세트 조회(`(기준 몬스터, 티어) → MonsterTierSheetSet`, 없으면 null). 이름·위치는 gameplay-programmer 판단(Rule 02 §9 `CommonInterface.cs`).
- **에셋 키**: Addressable 신규 18(SO, §7.2), 시트 이미지는 Addressable 등록 안 함(SO 의존으로 번들에 포함).
- **SO 스키마**: `MonsterTierSheetSet`(§8).

### 할 일
1. **추출 도구 확장**(JS, `.mockups/`, 커밋 대상 아님): Spawn 행 제외 5행 출력, 풋내기 12장 재출력(X-T9 해시 회귀), T 36장 처리(§2~5), `Monster_SheetSpec.json` 갱신, 게이트 X-T1~T9 출력.

3. **일회용 에디터 툴**(Rule 04 §3, 실행 후 삭제): 풋내기 12장 + T 36장 5행 재슬라이스(rect y = (5 − r − 1) x 192)·PPU(풋내기는 몸 PPU, T 는 ppuTier)·밉맵·Bilinear·압축·보조 텍스처 재연결 → `MonsterTierSheetSet` SO 18개 생성(frames·hpBarHeightWorld) → Addressables 그룹 `MonsterTierSheets`(Pack Separately)·라벨 `Resource`·주소 등록 → 프리팹 6종의 `Enhance` 자식 삭제·티어 배열 참조 제거 → 종속성 검사(U-T2).
