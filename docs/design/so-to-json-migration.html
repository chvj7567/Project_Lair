수치·문구 데이터 이사 안내

에셋 파일 안에 들어 있던 밸런스 수치와 화면 문구를 JSON 표로 옮깁니다. 게임은 그대로이고, 수치를 보관하는 서랍만 바뀝니다. (상세 수치·규칙은 같은 이름의 구현용 문서가 기준입니다.)

플레이어에게는 아무것도 달라지지 않습니다.
몬스터·영웅 능력치, 상점 가격, 카드 효과, 스킬 수치, 모든 이름과 설명 문구, 세이브 파일이 전부 지금과 똑같습니다. 세이브 버전도 올리지 않습니다.

1. 왜 옮기나요

지금 - 에셋 파일(ScriptableObject) 안

유니티 인스펙터에서만 고칠 수 있음
  • 몬스터 6종 기본 능력치, 영웅 기준 능력치
  • 상점 31항목, 영주 보상, 도전과제 13개
  • 영웅 스킬 15개 수치
  • 카드 28장의 이름·설명·효과 수치

옮긴 뒤 - JSON 표 16개

텍스트로 열어 고치고, 바뀐 줄이 그대로 기록에 남음
  • 다른 데이터(챕터·유물·육성 등 57개 표)와 같은 방식
  • 이름·설명은 문구 표(Strings_Ko)에 모임
  • 에셋 파일에는 그림만 남음

프로젝트 규칙

이번 작업의 근거
  • 자주 고치는 수치·문구는 JSON
  • 에셋 파일은 그림·프리팹처럼 유니티 에셋을 가리켜야 할 때만

"해당하는 것만 딸린 표에 적는다"가 이번 구조의 핵심입니다. 지금은 쓰지 않는 칸을 0 이나 빈 글자로 채워 두고 있는데, 옮긴 뒤에는 그런 가짜 값이 없어집니다. 예: 상점의 둥지·특성 항목은 설명 칸이 비어 있었습니다 → 설명 표에 줄 자체가 없습니다.

옮긴 뒤 수치를 고치는 흐름

몬스터가 너무 약해요MonsterStat 표에서 그 몬스터 줄의 HP 숫자를 고칩니다.
상점 가격을 올리고 싶어요ShopItem 표에서 그 항목의 시작 가격을 고칩니다.
카드 설명 문구를 다듬고 싶어요문구 표에서 그 카드 설명 번호의 글자를 고칩니다.
오타를 냈어요게임을 켜기 전에 자동 점검이 "어느 표 어느 줄이 틀렸는지" 알려 줍니다.

각 단계는 따로 끝낼 수 있고, 단계 사이에도 게임은 항상 실행됩니다. 단계마다 이렇게 확인합니다.

  1. 똑같은지 대조 - 에셋을 지우기 전에, 에셋의 값과 새 표의 값을 전부 하나씩 비교합니다. 하나라도 다르면 넘어가지 않습니다.
  2. 바꿔 끼우기 - 게임이 새 표를 읽게 바꾸고 에셋과 낡은 도구를 지웁니다.
  3. 전체 점검 - 기존 자동 테스트를 전부 다시 돌리고, 표에 빠진 줄·중복·잘못 가리키는 값이 없는지 검사합니다.

6. 조사하면서 바로잡은 것

도전과제는 13개

처음 조사에는 9개로 적혀 있었지만 실제 에셋에는 13개가 있습니다.

스킬 에셋에는 그림이 없음

숫자와 이름뿐이라 에셋으로 남길 이유가 없습니다 → 20개 전부 표로 옮깁니다.

종족 이름은 겹치지 않음

종족 표에는 "이그니스", 코드에는 "도깨비불"이 적혀 있습니다. 서로 다른 이름이라 중복이 아닙니다.

안 쓰이는 값 2종

영웅 외형의 발광 색·세기(25칸 전부 꺼짐), 카드 "던전의 점성"의 몬스터 배율 칸. 뒤쪽은 그대로 옮기고, 앞쪽은 아래에서 여쭙니다.

1. 영웅 스킬 에셋 20개를 완전히 없앨까요?
추천: 없앱니다.
그림이 하나도 없는 에셋이라, 숫자를 빼면 빈 껍데기만 남습니다.
2. 카드는 "어떤 효과인지"까지 표로 옮기고, 에셋에는 그림 2장만 남길까요?
추천: 그렇게 합니다.
카드 한 장의 설계(축·이름·효과·수치)를 한 곳에서 볼 수 있습니다.
3. 패시브/액티브 카드 묶음은 지금처럼 에셋에 둘까요?
추천: 그대로 둡니다.
카드 에셋을 모아 둔 목록이라 규칙에 맞고, 데일리 카드가 이 순서에 기대고 있어 건드리지 않는 편이 안전합니다.
4. 스테이지별 영웅 크기·외형 단계 숫자도 이번에 옮길까요? 옮긴다면 한 번도 켜진 적 없는 발광 색·세기 값은 지울까요?
추천: 옮깁니다(마지막 5단계). 발광 값은 지웁니다.
표에 칸 2개만 더하면 되는 작은 일입니다. 발광 값은 25칸 모두 꺼져 있어 게임에 나온 적이 없습니다(변경 기록에는 남습니다).
5. 코드에 적혀 있는 몬스터 이름·종족 색·빌드 축도 이번에 표로 옮길까요?
추천: 이번에는 하지 않습니다.
쓰는 곳이 26군데라 손댈 범위가 크고, 거의 바뀌지 않는 값입니다. 필요해지면 따로 기획합니다.
6. 유니티 안의 편집 창(JSON 동기 창, 마을 수치 편집 창)을 없애도 될까요?
추천: 없앱니다.
다른 표 57개처럼 텍스트로 고치면 됩니다. 카드 편집 창은 그림 배정·카드 만들기 용도로 남깁니다.
7. 새 표를 못 읽었을 때 전투에 못 들어가게 막을까요?
추천: 막고 마을로 돌려보냅니다.
틀린 능력치나 보상 없는 판이 랭킹에 올라가는 것을 막습니다. 배포 실수일 때만 생기고, 출시 전 자동 점검이 먼저 잡습니다.
8. 새 문구 147줄의 번호를 지금 마지막 번호 바로 뒤(1541~1687)에 이어 붙일까요?
추천: 이어 붙입니다.
지금까지 해 온 방식입니다. 그 사이 다른 기능이 번호를 먼저 쓰면 통째로 뒤로 밉니다.
9. 에셋이 아니라 코드 안에 직접 적힌 수치(예: 광폭화의 공격속도 증가폭)도 이번에 다룰까요?
