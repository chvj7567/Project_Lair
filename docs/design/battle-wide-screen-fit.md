### 1.2 마을 (`Village.unity`) — 참고만, 불변

캔버스는 ScreenSpaceOverlay + 1280x720 Match 0.5, 배경 카메라에 `DotStageCoverFit`(배경 640도트 폭 안에서 `min(세로기준, 가로기준)` 으로 직교 크기를 줄여 **덮기**). 마을은 "배경만" 화면을 덮고 HUD 는 캔버스 전체에 붙는다. 덮기(cover) 방식은 위·아래를 잘라내므로 배틀의 핵심 영역(②)에는 쓸 수 없다 → 재사용하지 않는다.

### 1.3 왜 지금 좌우에 띠가 보이나 (원인 추정)

코드 정독 기준이며 실기기 캡처는 없다. 구현 첫 단계 게이트 W0 에서 20:9 Game 뷰 캡처로 확인한다.

1. 게임 카메라와 **캔버스가 16:9 박스에 갇힌다** (`Apply()` 의 rect + ScreenSpaceCamera). 띠에는 UI·Dim 이 없다.
2. 띠에서 월드는 배경 카메라 미러로 그려지지만 **불티(1228 박스)는 박스 밖에 없고**, 이 박스 밖 영역은 배경 이미지 + 전역 조명만 보여 "비어 보인다".
3. 미러는 16:9 박스 내부를 **두 번 그린다**(배경 카메라 풀스크린 + 게임 카메라) — 모바일 오버드로우 비용.
4. 챕터별 배경 변형 중 1600 폭이 아닌 것이 있으면 그 챕터에서만 진짜 빈 띠가 생긴다(W1).

## 2. 결정 1 — 카메라/월드

### 2.1 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 풀 rect + 종횡비 클램프 (권장)** | 게임 카메라 rect 를 종횡비 `a` 가 `16:9 ≤ a ≤ 7:3` 이면 (0,0,1,1), 좁으면 위아래 띠(현행), 더 넓으면 좌우 띠. 직교 size **7 고정** | 핵심 영역(세로 14u) 항상 동일, 오버드로우 제거, 변경 최소(`ComputeViewportRect` 확장) | 21:9 초과·16:9 미만에서는 띠 유지 |
| B. 덮기(cover) 줌 | `DotStageCoverFit` 과 같은 `min` 로직 | 띠 0 | 와이드에서 위아래 크롭 → 핵심 영역 변동, ② 위반 |
| C. 좁은 화면 size 확대 | `size = 7·(16/9)/a` 로 세로를 더 보여 줌 | 좁은 화면도 풀스크린 | 16:10 필요 높이 15.56u = 747도트, 4:3 은 18.67u = 896도트 → 배경 높이 704도트 초과 → **빈 공간**. 세로 배경 신규 제작 필요(범위 확대) |

**권장 A.** 좁은 화면(태블릿)의 위아래 띠는 현행 그대로(결정 요청 2).

### 2.2 수치

- 기준 세로 14u = 14x48 = **672도트**. 가로 도트 = 672·a.
- 16:9 핵심 영역 폭 = 672x16/9 = 1194.67도트(24.89u).
- 상한 `maxAspect = 7/3 = 2.3333` → 672x7/3 = **1568도트**. 흔들림 여백 0.3u = 14.4도트/측 → 1568 + 2x14.4 = **1596.8 ≤ 1600** (여유 3.2도트).
- 7/3 초과(22:9 = 2.444, 폴더블 외부 25:9 등)는 rect 를 7/3 박스로 줄여 **좌우 띠** + 띠 색 `#1F2938`(현행 `_letterboxColor` 0.12,0.16,0.22).

### 2.5 `LetterboxFramer` 변경 요지 (기획 수준)

- 새 직렬화 필드 `_maxAspect`(float). **0 이면 현행 동작 그대로**(로딩 씬이 같은 스크립트를 쓰므로 opt-in). 배틀 씬만 `7/3`(2.3333333) 으로 설정.
- `_maxAspect > 0` 이고 화면 종횡비가 `[_targetAspect, _maxAspect]` 안이면 rect = (0,0,1,1). 그 밖이면 가까운 경계 종횡비로 박스 계산(`ComputeViewportRect` 의 목표를 클램프한 값으로 호출하는 오버로드).
- 배경 카메라 미러(`_renderWorldInBars`)는 **rect 가 풀스크린이면 끈다**(두 번 그리기 제거). 띠가 있을 때만 켠다. 씬 필드 값(1)은 그대로 둔다.
- 캔버스는 계속 게임 카메라에 붙인다(`ScreenSpaceCamera`) → 캔버스 크기 = 카메라 rect.

## 3. 결정 2 — 캔버스·CHMUI 루트

### 3.1 배율 방식

`CanvasScaler` 를 **Expand**(Scale With Screen Size, 1280x720, `m_ScreenMatchMode` = Expand)로 바꾼다. Match 0.5 는 풀스크린에서 논리 높이가 720 미만이 된다.

| 화면 | 현행 Match 0.5 논리 크기 | Expand 논리 크기 |
|---|---|---|
| 1920x1080 | 1280x720 | 1280x720 |
| 2400x1080 | √(1.875x1.5)=1.677 → 1431x644 (높이 720 미만 → ResultPopup 652 높이가 눌림) | scale = min(1.875, 1.5) = 1.5 → **1600x720** |
| 2520x1080 | √(1.969x1.5)=1.719 → 1466x628 (높이 720 미만) | scale = min(1.969, 1.5) = 1.5 → 1680x720 |
| 16:10 (rect 1920x1080) | 1280x720 | 1280x720 |

→ 논리 높이는 항상 720, 폭은 1280 이상(최대 1680). Expand 는 `CanvasScaler` 의 렌더링 크기 해석(카메라 rect 기준/화면 기준)에 관계없이 풀스크린일 때 동일하므로 구현자가 W3 에서 실측만 확인한다.

### 3.2 대안 (CHMUI 단일 루트 문제)

`CHMUI` 는 모든 UI 를 한 루트에 붙이고 강제 스트레치한다. HUD 는 Safe Area 프레임, 팝업은 1280x720 중앙 프레임이 필요하다.

| 안 | 내용 | 팝업 프리팹 작업 | HUD 작업 | 판정 |
|---|---|---|---|---|
| **(i) 루트 분리 (권장)** | 캔버스 아래 `HudRoot`(스트레치 + Safe Area), `PopupRoot`(중앙 1280x720). 부팅 시 `CHMUI.SetRoot(HudRoot)` → BattleHud 표시 → `SetRoot(PopupRoot)`. | **없음**(자동으로 1280x720 에 스트레치). Dim 이 있는 팝업만 가로 오버행 1칸 수정(3.3) | BattleHud 앵커 감사 | 기존 팝업 레이아웃 재작업 최소(④ 충족) |
| (ii) Expand 만, 루트 불변 | 팝업이 1600+ 폭으로 스트레치 | 스트레치 앵커 패널마다 중앙 래퍼 필요(수 미상) | Safe Area 래퍼 필요 | ④ 불충족 위험, 프리팹 수정량 불확실 |
| (iii) 팝업 프리팹마다 자체 Safe/Frame 컨테이너 | 프리팹 내부 재구성 | 프리팹 전수 수정 | 동일 | 작업량 최대 |

**권장 (i).** `OnSceneLoaded` 가 루트를 리셋하므로 `SetRoot` 는 배틀 부팅(BattleHud 표시 직전)마다 호출한다.

### 3.3 팝업 Dim 오버행

`ResultPopup` 의 `Dim` 은 `anchor 0~1, offset 0`, 색 (0.0157,0.0235,0.0392) α0.8, RaycastTarget on. PopupRoot 가 1280 폭이므로 좌우 추가 영역이 무조명·터치 통과가 된다. → Dim 이 있는 배틀 팝업 프리팹의 `Dim.offsetMin.x = -400, offsetMax.x = +400` (세로 0).

- 필요 오버행 = (1680 − 1280) ÷ 2 = **200/측** (최대 종횡비 7:3 일 때 논리 폭 1680). 여유 포함 **400**.
- 대상 후보: ResultPopup, CardSelectionPopup, BuildModalPopup, SynergyModalPopup, ConfirmPopup (Dim 보유 여부는 W5 감사로 확정. SkillUnlockBanner·ToastView 는 Dim 없음, 입력 통과 유지).
- ConfirmPopup 은 마을과 공용이지만 오버행은 마을 캔버스 밖으로 나갈 뿐 무해(마을 동작 불변).

## 4. 결정 3 — HUD 앵커 + Safe Area

### 4.1 Safe Area 프레임 동작 (`HudRoot`)

- 안전 영역 `Screen.safeArea` 와 게임 카메라 `pixelRect` 의 **교집합**을 캔버스 rect 기준 정규화해 `HudRoot` 의 anchorMin/Max 로 설정, offset 0.
- 화면 크기·방향·safeArea 가 바뀔 때만 재계산(매 프레임 비교는 값 비교 3개).
- 에디터(Game 뷰)에서도 갱신(ExecuteAlways 또는 시뮬레이터 safeArea 반영).

### 4.2 산출 예 (2400x1080, 가로 노치)

| 항목 | 값 |
|---|---|
| 캔버스 scale / 논리 크기 | 1.5 / 1600x720 |
| 16:9 핵심 영역 | 논리 x 160..1440 (좌우 160 논리 = 240px 씩 바깥 영역) |
| 예시 인셋 | 왼쪽 노치 132px, 오른쪽 0, 아래 홈바 63px (실기 값은 기기마다 다름) |
| `HudRoot` anchorMin | (132/2400, 63/1080) = (0.055, 0.0583) |
| `HudRoot` anchorMax | (1, 1) |
| 결과 | HUD 좌측이 논리 88 만큼 안쪽(132÷1.5)으로 밀림 — 핵심 영역(160)보다 바깥이라 영역 침범 없음 |

### 4.3 HUD 배치 규칙

- BattleHud 의 루트는 `HudRoot` 스트레치(CHMUI 가 처리). 화면 모서리에 붙어야 하는 요소(상단 바·우측 시너지·빌드 열·종료/배속 버튼)는 **모서리 앵커**를 쓰고, 중앙 정렬 요소(타이머·카운트다운 글로우)는 **상·하 중앙 앵커**를 쓴다.
- 요소가 핵심 16:9 영역 안쪽에 있어야 한다는 제약은 두지 않는다(풀스크린 모바일 게임 관례: 가장자리 앵커). 대신 와이드에서 HUD 가 투기장을 덜 가리게 되는 이득.
- 스트레치 앵커(가로 전폭 바)는 와이드에서 그대로 늘어남. 늘어남이 어색한 요소(고정 비율 아이콘열 등)는 감사 표에서 모서리/중앙 앵커 + 고정 크기로 수정.
- 감사 대상은 `BattleHud.prefab` **최상위 자식**(편성은 W4 에서 표로 확정). 현재 확인된 데코 요소(DecoCornerTL/TR/BL/BR, DecoPanelFrame, DecoCountdownGlow)는 모서리/프레임 앵커 여부를 감사 표에서 확인.

## 5. 팝업 규칙

- PopupRoot = 중앙 1280x720 (anchorMin=anchorMax=(0.5,0.5), pivot (0.5,0.5), sizeDelta (1280,720), 위치 0).
- 팝업은 CHMUI 가 PopupRoot 에 스트레치 → 현행 1280x720 레이아웃 그대로(ResultPanel 600x652, offset(0,−24) 등 불변).
- 토스트(하단 중앙)·스킬 해금 배너는 PopupRoot 기준(중앙 1280 안). 입력 통과 유지.
- 팝업은 Safe Area 를 따르지 않는다: 1280 폭은 논리 160 이상 안쪽이라 일반 노치(논리 88~100)보다 안쪽이다. 폴더블 등 이보다 큰 인셋은 범위 밖.
