## § 헤더

- **목표**: 풋내기(1등급) 몬스터 6종의 본체 그림을 AI 생성 HD 시트(v4)로 바꾼다. HD 시트를 **현행 월드 크기에 맞춰 축소**해 같은 파일명·같은 칸 규격으로 덮어쓰고, 발광 마스크와 강화 T1~T3 덧그림은 새 몸 기준으로 **스크립트가 다시 굽는다**. 피격은 새 Hit 행(6프레임)으로 바꾸고, 등장 행은 시트에만 남긴다.
- **검증 가설**: (1) 더 표정 있는 새 그림이 같은 월드 크기·같은 전투 수치에서 "누가 누구를 때렸나" 가독성을 해치지 않고 몬스터 애착을 높이는가. (2) 6.5:1 안팎으로 줄여도 작은 종(환령 19px·역병귀 24px)의 식별이 유지되는가. (3) 공격 준비 동작이 긴 새 그림을 현행 "데미지 즉시 적용"에 얹어도 타격감이 어긋나지 않는가.
- **현재 단계 범위 적합성**: **범위 안**. CLAUDE.md §8 "아트/에셋 작업 허용". 기존 6종의 외형·클립 교체이며 신규 몬스터·신규 종족·카드·규칙·수치 변경 0. 2~5등급(24종) 아트·6등급 이상은 범위 밖(§9에서 호환성만 점검).
- **핵심 메커니즘**: 몬스터 프리팹·컨트롤러·클립·파일명·GUID 는 그대로 두고, ① 몸 시트 6장·몸 발광 마스크 6장은 v4 를 축소해 6x6 으로 덮어쓰고 ② 강화 T1~T3 덧그림 18장·발광 마스크 18장은 새 몸의 앵커에 파츠를 다시 얹어 6x5 로 덮어쓰며 ③ 클립 30개는 프레임 수·시간표만 갈아 끼운다. 전투 판정·수치는 불변이다.

## 3. 현행 -> 신규 매핑

### 3.1 행·인덱스 매핑 (출력 인덱스 = 행 x 6 + 열)

|---|---|---|---|---|---|---|
| 0 | Idle | 0~5 | 0 Idle | 0~5 | 연결(6프레임) | |
| 1 | Move | 6~11 | 4 Move | 24~29 | 연결(6프레임) | |
| 2 | Attack | 12~17 | 1 Attack | 6~11 | 연결(6프레임, 비균등) | 현행 4~5프레임 → 6 |
| 3 | Hit | 18~23 | 5 Hit | 30~35 | 연결(6프레임) | 현행 18~20(3프레임) 대체. 이전에 비어 있던 21~23 사용 |
| 4 | Death | 24~29 | 2 Death | 12~17 | 연결(6프레임) | |

- 현행에서 바뀌는 인덱스 의미: Attack 은 종족별 4~5프레임이던 것이 6프레임(12~17 전부 사용), Hit 는 18~20 → 18~23, Phantom 의 대기·이동은 0~3 / 6~9 → 0~5 / 6~11.
- 덧그림(T1~T3)은 인덱스 **0~29 만** 존재한다. 인덱스 30~35(Spawn) 에서는 `MonsterTierOverlay` 가 오버레이를 끄지만 Spawn 클립을 재생하지 않으므로 무해하다. 등장은 현행대로 `Visual2D` 트윈(알파 0 → 1, 스케일 0.6 → 1.0, 0.3s)이다.

| Death 6종 공통 | 12 | 6 | 0 1 2 3 4 5 / 끝 6 | 0.500s | off | 0.500s |
| Spawn | - | - | **클립 없음** | - | - | 트윈 0.3s |

- 프레임 수 합계 = 6 종 x 6 프레임 x 5 상태 = 180(현행 150).
- **공격 비균등 근거**: 전 종 타격 포즈가 F3 이다(Wisp 돌진 정점 · Reaper 낫이 앞으로 내려옴 · Wraith 사슬 팔 뻗음 · Hex 구슬 발사 · Plague 독 방울 발사 · Phantom 급강하 물기). 데미지는 클립 시작과 같은 프레임에 적용되므로(`OnHit → OnAttack`) 준비 동작 F0~F2 를 각 1/30s 로 압축해 F3 가 3 ÷ 30 = **100ms** 에 보이게 한다. 현행 히트 포즈 지연은 83ms(Wraith 100ms)이므로 최대 지연이 같다. 이후 F3 = 1/10s 유지, F4 = 3/30 = 1/10s 유지, F5 = 3/30 = 1/10s 유지 → 총 12/30 = 0.400s.
- **재트리거 검산**: 최단 실효 쿨다운은 Reaper 0.5 x 0.7 x 0.8 ÷ 1.5 = 0.187s(`monster-2d-conversion.md` §5.3). 0.187 > 0.100 이라 타격 포즈 F3 는 재시작 전에 항상 한 번 보인다. 공격 클립 0.400s ≤ `_attackSuppressWindow` 0.5s 라 공격 모션을 피격이 끊지 않는다.
- **피격 길이 검산**: 0.250s < `_hitReactionCooldown` 0.4s 라 피격 클립끼리 겹치지 않는다(Any State -> Hit 은 자기 전이 off 이므로 겹치면 트리거가 남아 어긋난다 - 0.4s 미만 유지 필수).
- 등급 빌더(`MonsterGradeAssetBuilder`)는 `MonsterGrade_SheetSpec.json` 의 균등 fps 로 G2~G5 클립을 따로 굽는다. 본 시간표와 무관하다(§9).

## 8. 데이터 구조표 (Rule 00 데이터 구조 확인 게이트 · Rule 02 §11-1)

- **게임 JSON 데이터 스키마 변경: 없음.** `Grade`·`Race_Monster`·`MetaProfile`·`BalanceConfig` 등 런타임 row 클래스·세이브·클라우드 동기 변경 0.

```
Monster_SheetSpec (아트 매니페스트, 루트 1개)
 |-- doc, pixelsPerUnit(48), cols(6), rowsBody(6), rowsOverlay(5), indexRule("row*6+col"), pivot{x,y}
 |-- outRowOrder: ["idle","move","attack","hit","death","spawn"]
 |-- source { fileSuffix "_ver4", cols 6, rows 6, cell 229, srcRowOrder: ["idle","attack","death","spawn","move","hit"] }
 |-- process { filter "box", alphaThreshold 0.5, haloAlphaCut 40, paletteColors 48, floatPx 2 }
 +-- monsters[6]  "몬스터 하나"
       |-- base            Wisp|Wraith|Reaper|Hex|Plague|Phantom  (= EMonster 값명)
       |-- cell, bodyPx, srcBodyHeight, scale, offset[dx,dy]
       |-- anchorMode      "all" | "largestComponent"
       |-- anim { idle|move|attack|hit|death : { frames, sampleRate, loop, keyTimes[] } }
       |-- topY[4]         Lv0·T1·T2·T3 대기 F0 최상단 y (HP바 표 입력)
       |-- measured { edgeCrossFrames, removedSpecks, rowJitter{}, rise{}, maskRatioIdle, paletteColorsUsed }
       +-- overrides { maskOverrides[], anchorOverrides[] }   (선택 - 있는 종족만 항목 존재)
```

| 필드 | 타입 | 키/관계 | 값 |
|---|---|---|---|
