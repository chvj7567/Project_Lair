## 0. 헤더

- **목표**: 전투(챕터 5종)·마을·로딩 세 씬의 배경 그림 7장(Battle 5 + Village 1 + Loading 1)을 **월드 지오메트리를 한 칸도 바꾸지 않고** 더 풍부한 화질·재질감으로 다시 그린다. 같은 파일명·같은 크기·같은 PPU 로 제자리 교체하므로 씬·코드·JSON 변경은 0 이다.
- **검증 가설**: (1) UI 아트 리프레시(고해상도 GPT 세트)와 몬스터 리디자인 이후, 배경만 옛 도트 질감으로 남아 "화면 안에서 어긋난다"는 인상을 배경 재작도로 해소할 수 있는가. (2) 그 재작도가 HUD 가림 영역·쇼케이스 보행 구역·발광 장식 좌표·유닛 가독성을 깨지 않는가.
- **현재 단계 범위 적합성**: **범위 안(경계 확인 필요)**. §8 "아트/에셋 작업 허용"(프리미티브 제약 해제, 실제 에셋 교체 가능)과 챕터 4·5 의 "맵 배경" 항목이 이미 배경 그림 작업을 허용한다. U7 이 제외한 것은 월드맵 일러스트성 스프라이트(메달·달·실루엣·안개·비네트)이며 씬 배경은 제외 대상이 아니다. 다만 "제자리 교체인지 구조 변경인지"의 경계가 §8 에 명문화돼 있지 않으므로 §10 에 한정형 승격 문구를 둔다(사용자 승인 후 CLAUDE.md 반영).
- **핵심 메커니즘**: 현행 배경을 지오메트리 가이드(선화 오버레이)로 삼아 GPT 로 재작도 -> 현행 도트 격자(Point 필터·PPU 48)로 다운샘플·팔레트 스냅 -> 같은 파일명으로 덮어쓰기 -> 겹침 검사(오버레이 차이)로 기하 일치 확인. 조명은 기존 `Mat_Dot2DLit` + 2D Light 가 계속 담당한다(그림에 조명을 굽지 않음).

### 1.2 현재 룩 진단

- **UI풍 도트 패스는 이미 적용돼 있다.** `.mockups/scene-bg-ui-style.html`·`scene-bg-loading-village.html` 의 "후" 안(금 코니스·금 리벳·금 웨인스코트·금 테 옥좌·소울그린 광원)이 현재 PNG 와 일치한다. 따라서 현재 상태 = "UI풍 도트 배경", 구 도트 아님.
- **화질 격차**: 몬스터 시트는 192 셀 HD(Bilinear), UI 는 화면 x3 고해상도 GPT 세트인데 배경만 PPU 48 도트(Village·Loading 은 1도트 = 1/48u, Battle 은 시안 캔버스 800x352 를 2배 확대한 2x2 블록으로 추정 — 실측 게이트 G0). 같은 화면에서 질감 수준이 갈린다.
- **조명 체계는 유지 가치가 있다.** `Dot2DLit`·`Monster2DSprite` 가 같은 `DotLightQuantize`(1/48u 격자, 6단계 + Bayer 4x4)를 공유해 배경·몬스터가 하나의 조명으로 묶여 있다.

### 2.1 대안

### 2.2 권장: **C (하이브리드)**, 실패 구간은 A 로 폴백

이유:
1. 조명 체계(Bayer 양자화 조명)는 몬스터와 배경을 묶는 현 룩의 핵심이고, 이를 건드리는 B 는 §8 의 머티리얼/셰이더 교체 금지 정신과 충돌한다(몬스터 등급 항목의 "머티리얼/셰이더 교체는 후속 별도 승격" 선례).
2. 제자리 교체라 7장 교체가 실패해도 롤백이 파일 복원 하나다.
3. 몬스터가 이미 HD 이므로 B 가 더 닮아 보이는 것은 사실이지만, 그 차이는 "조명 계단 + 도트 배경 위의 HD 몬스터"라는 현 룩이 이미 허용·검증된 상태(몬스터 v4 승인)여서 긴급하지 않다. B 는 후속 별도 승격 안건으로 남긴다.
4. 키잉: 배경 PNG 는 전부 불투명이라 마젠타 크로마키는 쓰지 않는다. 키잉은 전경 투명 레이어를 분리할 때만 필요하며 이번 범위는 분리 레이어를 만들지 않는다(레이어 추가 금지 §10).

## 5. 교체 방식
