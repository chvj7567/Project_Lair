# 마을 HUD 재배치 — 하단 도크형 3분할 (1280x720)

> 작성: game-designer · 입력: 사용자 요청 "마을 허브 HUD 가 너무 비어 있다, 1280x720 에서 꽉 차 보이게 재배치" · 선행 기획: `scene-2d-conversion.md` §5(마을 배경, Q4 "VillageHud 재배치는 별도 후속 기획"·F8 가림), `village-meta-hub.md` §8.4
> 현행 구현: `Assets/_Lair/Art/UI/VillageHud.prefab`, `Assets/_Lair/Scripts/UI/Village/VillageHud.cs`
> **UI 목업**: `.mockups/village-hud-layout.html` (현재/제안 토글, 가림 검사 포함)

## § 헤더

- **목표**: 마을 HUD 의 기존 위젯(메뉴 6 · 영웅 · 출격 · 스테이지 캐러셀 · 전적 · 상단 바)을 위치·크기만 바꿔 화면 하단을 채우는 도크로 재배치하고, 배경 소품(상점·도감·왕좌·게시판·묘비·왕관)과 홀로그램 영웅을 가리지 않게 한다.
- **검증 가설**: HUD 를 벽면 소품 아래 바닥 영역으로 내리면, (a) 시작 화면이 "비어 보인다"는 인상이 사라지고 (b) 메뉴 6개가 배경 소품과 같은 좌→우 순서로 읽혀 어느 소품이 어느 메뉴인지 즉시 연결되는가.
- **현재 단계 범위 적합성**: **범위 내**. v0.2 승격분인 마을 허브(메뉴 6 · 영웅 · 출격)와 v0.3 계정/랭킹 진입 위젯의 배치만 바꾼다. 신규 기능 · 신규 화면 · 메인 메뉴/세팅 화면 0건(CLAUDE.md §8 준수), 서버 연동 변경 0건, 신규 JSON 스키마 0건.
- **핵심 메커니즘**: 화면을 세 띠로 나눈다. 상단 바(y 0~88, 현행 유지) · 중단 소품 벽면+홀로그램(y 88~464, HUD 금지 구역) · 하단 도크(y 464~704, 좌 메뉴 패널 / 중앙 영웅+출격 / 우 스테이지+전적 패널). 위젯 종류·개수·바인딩은 불변.

## 2. 대안 비교

| 안 | 구조 | 소품 가림 | 점유율 | 판정 |
|---|---|---|---|---|
| **A. 하단 도크 3분할 (권장)** | 상단 바 유지 + 하단 y 464~704 에 좌 메뉴 / 중앙 영웅·출격 / 우 스테이지·전적 | 0건 (벽면 y 88~464 와 홀로그램 비침범) | 112,640 + 456x240x2 + (96+216)x72 = 353,984 ÷ 921,600 = 38.4% | 권장 |
| B. 측면 컬럼 확대 | 좌우 컬럼 240x600 두 개(x 16~256, x 1024~1264, y 104~704) + 중앙 하단 버튼 | 상점·묘비·왕관 받침대 3종 가림 (F8 재발) | 112,640 + 144,000x2 + 22,464 = 423,104 ÷ 921,600 = 45.9% | 점유는 높으나 배경 소품(마을 정체성)을 다시 덮음 |
| (구 C, rev 2 에서 폐기 — 새 C안은 §3C) 현행 위치 유지 + 크기 확대 | 타일·카드·패널을 키우고 출격만 아래로 | 카드가 왕좌를 계속 덮음 | 수치 산출 대상 아님(좌표 전면 재계산 필요, A 와 작업량 동일) | 이점 없음 |

**권장 이유**: 점유 면적은 A(38.4%)가 현행(40.9%)보다 오히려 낮다. 그러나 현행의 문제는 면적이 아니라 **분포**(하단 170px 공백 + 소품 가림)이고, A 는 하단을 화면 가장자리 16px 여백까지 채워 공백을 0 으로 만들면서 소품 가림도 0 으로 만든다. "화면 면적을 위젯으로 더 채우는" 것이 목적이면 B 를 택해야 하지만 소품 3종이 다시 가려진다. (rev 1 시점 서술. rev 2 에서 사용자가 A·B 모두 반려, §2.1 의 C안으로 확정 진행.)

## 3D. D안 — 사용자 에디터 배치 정합판 (현재 채택 대상, rev 4)
