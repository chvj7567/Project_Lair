## 1. 의도

현재 게임은 「Battle 5분 런 → 결과 팝업 → 재시작」의 단일 루프다. 런 결과가 다음 런에 아무것도 남기지 않아 반복 동기가 없다. v0.2 에서 **마을(허브)** 을 런 사이에 끼워 넣고, 소울(영혼석) 경제 위에 영구 성장·기록·도전과제를 올려 "한 판 더"의 이유를 만든다.

컨셉서 §7 (메타 진행) 의 승격이다. 서버 연동(§9)은 여전히 범위 밖 — 세이브는 로컬.

## 2. 메타 루프 / 씬 흐름 (확정)

```
앱 시작 → Loading → Village (신설 씬) → 출격 → Battle (5분 런)
              ↑                                      │
              └── 결과 팝업 (보상 요약: 소울 +N, XP +N) ──┘
```

- **Village.unity 별도 씬 신설.** Battle 씬에 마을 모드를 얹는 대안은 전투 상태와의 결합 리스크로 기각.
- 앱 시작 시 메인 메뉴 없이 **바로 마을 진입** — 마을이 사실상 시작 화면을 겸한다 (기존 "메인 메뉴 금지" 제약은 마을이 흡수).
- 기존 ResultPopup 에 보상 요약(획득 소울·XP) 표시를 추가하고, 확인 시 마을로 복귀한다.

## 3. 마을 씬 구성 (시안 v2 확정)

- **3D 레이어**: 중앙에 해골 영웅 — 기존 에셋 `Skeleton_Model_110.fbx` + `Skeleton_idle` 루프 재생. 고정 카메라. 배경(마을 전경)은 **더미 리소스** — 추후 교체 전제.
- **UI 레이어** (CHMUI / UIBase, 기존 패턴):
  - 상단 바: 소울 보유량(좌) · 마을 이름(중) · 영주 Lv + XP 게이지(우)
  - 좌측 세로 메뉴: 상점 · 도감 · 기록
  - 우측 세로 메뉴: 영웅 · 퀘스트(도전과제) · 영주성
  - 하단 중앙: 출격 대형 버튼
- 중앙 3D 모델 = **현재 선택된 상대 영웅**. 영웅 메뉴에서 선택을 바꾸면 교체 표시 (v0.2 는 Knight 1종이라 사실상 고정).

## 5. 시스템별 윤곽

> 구체 수치(가격·보상량·XP 곡선·도전과제 목록)는 game-designer 기획서가 단일 진실. 본 절은 메커니즘 골격만 락.

### 5.1 소울(영혼석) 경제
- **승리**: 기본 보상 + 남은 시간 비례 보너스 (빨리 처치할수록 ↑)
- **패배**: 영웅 HP 를 깎은 비율 비례 부분 지급 — 빈손 방지, 메타 성장은 항상 전진
- **도전과제**: 달성 시 1회 추가 지급

### 5.2 상점 — 레벨제 영구 업그레이드 (확정 구조)
- 항목 6~8개 목록형. 각 항목 레벨 0→5, 레벨당 가격 점증.
- 효과 예 (기획서에서 확정): 몬스터 전종 HP +α%/Lv · 몬스터 공격력 +α%/Lv · 스포너 주기 -α%/Lv 등.
- 전투 시작 시 BattleContext 가 메타 보너스를 일괄 적용 — 기존 StatMultiplier 체계 재활용. 스킬 트리/하이브리드 구조는 기각.

### 5.3 던전 영주 레벨 (영주성 팝업)
- 런마다 XP 획득 (승패·성과 반영) → 레벨 트랙 UI 에서 레벨별 보상 확인.
- v0.2 보상: 일부 레벨 = 소울 지급, 나머지 = **잠금 슬롯 + 더미 아이콘** ("??? — 추후 해금") 으로 자리만 표시.

### 5.4 영웅 메뉴
- 선택 가능 영웅: Knight(해골) 1종. + 잠금 슬롯 N개 (더미 실루엣).
- 선택된 영웅이 마을 중앙 3D 모델 및 다음 런의 상대로 반영.

### 5.5 도감 / 기록
- 도감: 몬스터 6종 + 카드 28장 — 조우/픽 이력 기반 해금 표시 + 미래 콘텐츠용 잠금 더미 슬롯.
- 기록(통계): 총 런 수 · 승률 · 최단 클리어 · 최다 픽 카드 등 — 기존 RunRecord 데이터 누적 활용.

### 5.6 도전과제 (퀘스트 메뉴)
- 고정 목록 10~15개. 예: "3분 안에 처치", "Tank 축 Tier3 달성".
- RunRecord 데이터만으로 판정 가능한 조건으로 한정 (시간/날짜 기반 로직 없음). 보상은 소울 1회 지급.

### 5.7 세이브 (로컬)
- **MetaProfile** 단일 모델: 소울 잔액 · 상점 항목 레벨 · 영주 Lv/XP · 도전과제 달성 플래그 · 도감/통계 누적.
- 로컬 JSON, `Application.persistentDataPath` (Android 에서 dataPath 는 읽기 전용 — 기존 사고 사례 반영).
- 저장 시점: 보상 정산 직후 + 상점 구매 등 메타 변경 직후 즉시 저장.

- 서버 연동 · 리더보드 · 클라우드 세이브
- 던전 테마 시스템

- 신규 영웅·몬스터·카드의 실제 리소스/밸런스 제작 (잠금 더미 슬롯만)

- 마을 BGM/사운드는 hook 만 준비, 에셋 선정은 별도 작업 가능

## 8. 리스크 / 주의

- **밸런스 인플레이션**: 상점 영구 버프가 누적되면 기존 카드 밸런스(평균 2~4분 처치 기준, 컨셉서 §8)가 무너질 수 있다 → 기획서에서 상한(전 항목 만렙 시 총 보정률)을 명시하고, 구현 후 qa-simulator 재검증 권장.
- **세이브 호환**: MetaProfile 스키마에 버전 필드를 두어 향후 필드 추가에 대비.
- **씬 전환과 풀/리소스 수명**: Village ↔ Battle 전환 시 CHMPool·CHMResource 의 씬 종속 리소스 해제 정책 확인 필요 (plan 단계에서 구체화).
